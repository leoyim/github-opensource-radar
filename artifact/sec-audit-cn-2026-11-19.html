低酌情处理 · 5 项

L-1 内容治理 /removed/ 排序非严格「期次倒序」

src/lib/load.ts:123 采用「retracted 优先 + removedAt 倒序」，导致 11-18 的 blocked 条目（如 FarhanNaem/startall-back）排在 11-16 的 retracted 批次之后。属有意设计且两页共用同一规则，但与补充要求的字面口径有偏差，建议确认取舍。

L-2 内容治理 个别公示条目结论措辞偏观察态

如 manjushree-iyer/soundpad-audio-suite 的 verdict 为「建议在核实前不要直接引入」（verdictOf 兜底句），与「已移除」的公示语境不完全相称；证据链本身充分（5 项、含 correlation）。另：台账证据族均为 metadata / content / correlation，尚无 public-opinion / expert-critique / issue-reports 实例（要求中为举例，非强制）。

L-3 A08 完整性 ingest --push 用 git add -A 全量暂存并自动推送

tools/ingest.mjs:199：可能把 Temp/、artifact/ 等非数据文件带入公开仓库。

修复：仅暂存 _data/ 与 overrides/。
L-4 A03 加固 full_name 仅校验 string 类型，未断言 owner/repo 格式

src/lib/schema.ts:177；且 replace('/', '__') 只替换首个斜杠，构造性恶意 full_name 理论上可路径穿越读/写文件。上游为 GitHub API 数据，现实不可利用，属纵深防御项。

L-5 A05 配置 GitHub Pages 无法自定义安全响应头；CI actions 未钉 SHA

CSP / HSTS 缺失属平台限制，静态站风险有限，可加 <meta> CSP 缓解；actions 钉 major 标签（v4）而非 commit SHA，建议钉版。
