- **AI 与移动端吃掉 93% 的日增，中间四类合计不到 8%**：30 个项目今日合计 6,334 星增（22 个有基线）。AI 类五项 3,240（51.2%），移动类五项 2,637（41.6%），两者相加 5,877，占 92.8%。剩下的前端 146、后端 261、数据 5、工具 45，四类合计 457 星，约 7.2%。这不是「某个方向更热」，而是榜单结构被压成了两极：一端是 agent 与手机，另一端几乎空着。值得注意的是两极的构成完全不同——AI 端的增量集中在单个项目（agent-desktop 一项就占 AI 类的 70%），移动端则是 NOIR +1,135、nectarlink +1,063、AnyPS5 +337 三点开花，说明后者是真实的品类热度，前者更像单点爆发。
- **数据类连续第四期塌陷：五项合计 5 星，最高日增 +4**：数据类五个项目今日日增合计 5 星，最高是 debezium 的 +4，另有一个 +1、一个 0、两个缺基线。更严重的是构成：第五名是一个 100 星、单日 +1、没有 README（真实内容仅两百余字符法语版本备注）、没有许可证的 Dataiku 教学项目；第四名是一个 135 星、零增量的 Jellyfin 看板。整类里唯一具备生产分量的是 debezium。根因在采集侧而非市场——该类四条查询有两条锁定 topic、一条锁定语言，覆盖不到新的存储引擎、OLAP 与 ETL 工具，候选池被小体量仓库填满。这个缺陷已连续四期复现，从「注水」变成了「失真」，应当优先修查询而不是继续观察。
- **工具类第 2、3、4 名曾被三个同模板空壳占位，这已经是安全问题**：三个仓库是同一批投放：创建时间集中在五分钟内，各自只有一次推送（创建后数秒即 push），README 是逐字相同的 311 字符——内容只有「按 Win + X 打开 PowerShell、粘贴下面这段命令、回车」，无源码、无 release、无许可证，topics 用同一套通用标签，星数凑整为 400 / 400 / 502。真正危险的是话术：一个自称 Roblox 游戏复制器、一个自称系统工具、一个自称广告拦截器，三者都用「预激活」「全功能」「开箱即用」降低戒心，而唯一交付物就是那段需要用户亲手执行的脚本。上一期是三个「恰好 400 星、零增量」的占位仓库，这一期升级为定向投毒。复查后三条已全部撤下，判定依据与时间线见移除台账；回填后的第 2–4 名是 openrig、linearmouse、OpenTodo。tools 查询必须加入仓库年龄、提交次数与 README 模板相似度过滤，并对「PowerShell 粘贴执行」这类指令直接判负。
- **手机与桌面的边界仍是今天最快起量的赛道**：移动类前五里，NOIR（2 天 +1,135）用电脑审计手机、nectarlink（29 天 +1,063）把手机通知与文件搬进 Windows、MenuBarMijia（19 天）把米家设备搬上 Mac 菜单栏、AnyPS5（+337）把主机游戏搬到 PC，连 3,268 天的 scrcpy（+102）走的也是同一条路。再加上 AI 类第一的 agent-desktop（+2,275，操作桌面应用），日增前六里大半都是在拆某个平台边界。共同点很清楚：它们解决的不是「某个 App 更好用」，而是「数据与操作被困在某个设备里」。NOIR 和 nectarlink 同时破千且都是冷启动，说明这类需求此前缺少合格的开源方案，而不是需求刚刚出现。
- **八个项目没有日增基线，占 27%**：30 个项目里有 8 个 starGain 为 null 或 0，占 27%。拆开看是两类：一类是刚建仓 1 天的 steam-stash-value-report-card（611 星），还没有历史快照可比，属正常；另一类是 onnxruntime（2,915 天）、agent-safe-pipeline（81 天）、defyxVPN（503 天）、workhorse（103 天）、dqex（74 天）、JellyGlance Server（108 天）、MenuBarMijia（19 天）这些在 Trending 页被捕获但快照未覆盖的仓库。问题在于排序影响——缺基线时热度只能退回按绝对星数或 Trending 位次估算，这让「5 万星但今天没人讨论」的老项目与「2 天涨千星」的新项目在同一把尺子上难以区分。建议对 Trending 来源的条目补一条「首次出现」标记，而不是让它以 null 混在增量序列里。
- **TypeScript 重新回到五席，但这个数字不说明任何趋势**：30 个项目里 TypeScript 出现 5 次（OmniRoute、handwired、agent-safe-pipeline、openrig、OpenTodo），超过 Rust 的 4 次和 JavaScript 的 4 次。Rust 的四席（agent-desktop、OpenLogi、Veronica、nectarlink）唯一的共性是「需要跟系统层打交道」——辅助功能 API、HID++ 报文、GNOME 服务、跨端加密通道；TypeScript 的五席则全是应用层胶水：聚合端点、项目管理、任务队列、agent 团队编排。语言分布在这里是任务性质的映射，不是趋势指标，别拿它当选型依据。
- **十一个一年以上的老项目同台，注意力在往基础设施回流**：入选项目中 11 个年龄超过 365 天：webpack（5,351 天）、rclone（4,614）、debezium（3,937）、scrcpy（3,268）、onnxruntime（2,915）、mealie（2,157）、linearmouse（1,972）、UE4SS（1,460）、ollama（1,225）、defyxVPN（503）、heretic（408）。它们的日增普遍不高（webpack +3、rclone +29、debezium +4），但覆盖了打包、云存储同步、CDC、设备镜像、推理运行时、自建应用、本地模型、鼠标驱动这些互不重叠的基础层。把这条和老项目在 AI 类里的位置放在一起看：AI 前两名都是应用层的新玩法，而唯一的基础设施项 onnxruntime 连基线都没有。这更像一次周期性曝光，但方向值得记——当应用层卷到「让 agent 替你点按钮」时，真正决定成本与可靠性的仍然是下面那几层。
