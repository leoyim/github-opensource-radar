## 1. 它解决什么问题

用 Rust 写高性能桌面应用，最缺的往往不是渲染内核，而是成套的组件、状态管理、布局与编辑能力，团队得从按钮和列表开始自建，选型成本因此被低估。

## 2. 为什么是现在

项目 876 天、19,425 星、1,208 fork，本期 +285，是有当日基线的项目里增量第三高。本期同时出现基于 GPUI 的 navop 数据库工作台与它，说明 GPUI 生态已从「能不能用」进入「有没有现成组件层」的阶段。

## 3. 关键能力

- 提供 75 个以上有文档记录的组件与基础原语
- 覆盖应用级的数据、布局与编辑能力，不只做控件渲染
- 支持 WebAssembly、AccessKit 无障碍与 UI 集成测试
- 提供可选的 JavaScript 扩展运行时
- 拆为 gpui-base（无样式的行为、状态与基础设施）与 gpui-component（完整样式 UI 系统）两层

## 4. 架构与实现

Rust 实现，两个 crate 的分层是主要设计：把无样式的行为与状态层同完整样式组件层解耦，应用侧只需依赖统一入口，定制主题时又可下沉到 base。取舍是绑定 GPUI 生态，换原生渲染性能与一致的 Rust 技术栈。许可证标注为 NOASSERTION，商业使用前需要单独核对条款。

## 5. 上手路径

1. 用官方示例跑一个最小窗口，确认工具链与目标平台可用
2. 按实际需要逐个引入组件，观察编译时间与依赖变化
3. 试一次 UI 集成测试与无障碍检查
4. 再评估是否启用可选的 JavaScript 扩展运行时

## 6. 风险与边界

- 许可证为 NOASSERTION，商业使用前必须确认授权范围
- 绑定 GPUI 意味着上游框架的演进会直接影响应用
- Rust 桌面生态在移动端与 Web 端的成熟度仍有限
- 75+ 组件的质量与文档覆盖需按实际用到的那几个验证
