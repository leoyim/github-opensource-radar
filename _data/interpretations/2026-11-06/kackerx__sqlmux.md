## 1. 它解决什么问题

习惯 tmux 与 vim 的人，在图形数据库客户端里要反复离开键盘；而现有终端客户端的分屏、会话保持与命令面板往往不成体系，远程 SSH 环境下更是如此。

## 2. 为什么是现在

项目 38 天、251 星、14 fork，热度为速度估算（约 34）。它与 navop 同属「数据库交互界面重做」这条线，方向却相反：一个用 GPU 原生渲染做功能一体化，一个把全部能力压回纯终端。

## 3. 关键能力

- tmux 风格的分屏与会话管理
- Vim 键位操作，命令面板与快速 SQL
- 支持 PostgreSQL、MySQL、SQL Server、Redis 等
- 提供 Redis key 浏览与 console 视图
- 在 Windows Terminal 的 PowerShell 或 cmd 下原生运行
- 支持 npm 全局安装、go install 与 Release 压缩包多种分发方式

## 4. 架构与实现

Go 实现、MIT 许可，单二进制 TUI，通过终端多路复用抽象管理分屏与会话，连接层按数据库类型适配。取舍是不依赖图形环境、可直接走 SSH 使用，代价是 ER 图、执行计划图形化等可视化能力弱于桌面客户端。README 摘录偏安装与演示，连接与凭据细节需查文档。

## 5. 上手路径

1. 用 npm 或 go install 装好后连一个本地 SQLite / PostgreSQL
2. 熟悉面板调出、分屏切换与会话保存的键位
3. 保存一份常用连接配置，检查配置文件的明文风险
4. 再在远程 SSH 会话里验证渲染与输入延迟

## 6. 风险与边界

- 项目仅 38 天、评分 2.5，稳定性与连接兼容性仍待验证
- 终端环境差异（尤其 Windows 与远程会话）可能影响渲染
- 多数据库驱动的覆盖深度不一致，需按自己用到的类型实测
- 连接凭据的存储方式需自行核对

## 7. 谁该用 / 谁别碰

长期在终端与 SSH 环境工作、偏好 Vim 键位的开发与运维人员。
