## 1. 它解决什么问题

网页里嵌地图的常见困境是：直接用地图服务 SDK 会被供应商与配额绑住，自己从瓦片、投影、事件一路写又重复造轮子。中间需要一层足够薄、足够稳定的抽象，既能对接不同瓦片源，又能让标记、矢量覆盖与交互控件按统一方式组合。

## 2. 为什么是现在

项目创建于 2010 年、已 5,888 天，是本期榜单里历史最长的项目，本期 45,860 星、6,210 fork、331 个开放议题、+24。在一个以新仓与 agent 工具为主角的榜单里，这种「几乎不增长但不消失」的基础设施恰好构成另一种样本：它的价值来自被依赖，而不是当期热度。

## 3. 关键能力

- 提供瓦片图层、矢量覆盖物、标记、控件与事件等地图基础抽象
- 以轻量与移动端友好著称，适合嵌入各类 Web 页面
- 具备可插拔的扩展生态，具体能力可由插件补充
- BSD-2-Clause 许可，便于集成进不同类型项目
- 长期维护的稳定 API，被大量上层库与业务系统作为地图底座使用

## 4. 架构与实现

纯 JavaScript、BSD-2-Clause 许可，定位是浏览器端地图库而非地图服务：它不提供数据，只提供组织图层与交互的抽象，因此可以自由对接不同瓦片来源。架构上的关键是核心保持薄、把专门能力留给插件，这既控制了体积与移动端开销，也让上层系统不必随某个供应商的 SDK 一起升级。README 摘录主要为项目背景说明，具体实现细节需以官方文档与源码为准。

## 5. 上手路径

1. 用官方教程跑通一个最简单的瓦片地图，确认容器尺寸与坐标系设置
2. 按需要逐个引入标记、图层控制与弹窗，观察核心体积变化
3. 对接自己的瓦片源前先核对使用条款与配额
4. 大量标记场景评估聚合插件，避免逐点 DOM 渲染

## 6. 风险与边界

- 核心刻意保持精简，GIS 分析、路径规划等高级能力依赖插件，需自行评估插件维护状态
- 地图数据与瓦片服务的可用性、条款由第三方决定，与库本身无关
- 项目历史很长，升级时应核对既有插件与新版本的兼容性
- README 摘录以背景说明为主，API 细节应查阅官方文档

## 7. 谁该用 / 谁别碰

需要在 Web 页面嵌入交互地图、又希望避免绑定单一地图服务 SDK 的前端与 GIS 应用开发者。
