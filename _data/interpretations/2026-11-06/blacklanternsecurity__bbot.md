## 1. 它解决什么问题

资产梳理往往从一份不完整的清单开始，子域、证书、DNS 记录与开放服务之间的关联靠人手工串联，漏掉一环就看不到完整攻击面，重复劳动还很难固化成流程。

## 2. 为什么是现在

项目 1,700 天、10,986 星、976 fork，本期 +26，是本期六个满千天老项目之一。在工具方向普遍是小工具的一期里，它是唯一具备长期生产使用痕迹的安全基础设施，也代表自动化资产发现这条线已进入稳定维护期。

## 3. 关键能力

- 递归式资产发现与攻击面管理（ASM / EASM）
- 多模块联动，从 DNS、证书、端口等线索持续展开新的目标
- 面向漏洞赏金与自动化扫描场景
- 支持 CLI 与 Docker 等多种安装方式
- 扫描结果可导出，README 演示中配合 VivaGraphJS 做关系可视化

## 4. 架构与实现

Python 实现、AGPL-3.0 许可，核心是模块化的事件驱动扫描引擎：每个模块产出事件，事件再触发下一轮模块，形成递归展开而非一次性清单扫描。取舍是覆盖广、自动化程度高，但一次扫描会产生大量对外请求，范围与速率必须由使用方显式控制。README 摘录以安装链接与演示为主，完整模块清单需查项目文档。

## 5. 上手路径

1. 在自有或已获书面授权的目标上跑一次范围最小的扫描
2. 限制启用模块与并发，记录实际产生的请求量
3. 导出结果并人工核对误报与范围外资产
4. 确认边界与审批流程后，再考虑接入常态化资产盘点

## 6. 风险与边界

- 属于双用途工具，务必在明确授权范围内使用，未经授权扫描可能违反法律或服务条款
- 递归展开容易造成计划外的请求与目标范围蔓延
- AGPL-3.0 对二次分发与托管服务化有约束，商用前需核对
- 模块由社区贡献，质量与信誉需逐个审阅后再启用
