## 1. 它解决什么问题

AI 编码代理要产出可用于生产的图像、视频、音频与 3D 资产时，卡点往往不是会不会调 API，而是三件杂事：面对一堆模型该选哪个、调用之前不知道要花多少、跨多次生成时角色和品牌元素容易漂移。另一半需求则完全不在云上——ZBrush、Blender、Maya、Unreal 这类 DCC 软件装在本机，代理没有可复用的操作知识，官方文档与专家教程又散落各处。把这两类能力混在一个包里，会让依赖与验证边界都变得含糊。

## 2. 为什么是现在

项目 86 天、3,095 星，本期 +667 居全榜日增第一。它把「技能」当成可分发、可版本化的单元，而不是提示词片段：技能里写明选模型与估价的规则、以及如何保持一致性，正好对应 agent 从演示走向生产时的成本与可控性问题。expert tools 单独放在列表底部并明确不需要 Scenario MCP，也说明作者在有意识地切分能力边界。

## 3. 关键能力

- 通过 Scenario MCP 生成生产级图像、视频、音频、纹理、天空盒、3D 资产与自定义训练模型，面向游戏与娱乐等创意场景
- 调用前完成模型选择与花费预估，避免代理在未估价的情况下直接消耗额度
- 在连续生成中保持角色与品牌元素的一致性
- 兼容 Claude Code、Cursor、Codex、Copilot 等 70 余种编码代理
- expert tools 以技能族形式驱动本机 ZBrush、Blender、Maya、Unreal Engine、Unity、Godot、Roblox Studio，每个族目录的 README 记录构建方式与验证到什么程度

## 4. 架构与实现

Python 实现、MIT 许可，本质是一组结构化的技能包而非运行时服务。主干走 Scenario MCP server 完成生成；expert tools 是并列的另一族，依赖本机已安装的 DCC 应用而非 MCP。关键取舍是「能力按依赖切分」：云端生成与本机软件操作各自独立，前者依赖 MCP，后者只需要应用本身，族级 README 把知识来源（专家教程、会议演讲、官方文档）和验证边界一并留档，便于审阅哪些结论真被验证过。

## 5. 上手路径

1. 先只用默认技能集接上 Scenario MCP，跑通一张图或一段短视频，确认额度与估价逻辑符合预期
2. 按 README 挑一个与本机已装软件对应的 expert tools 族，先读该族 README 的验证范围再启用
3. 验证一致性能力时用同一角色连续生成多次，检查是否漂移
4. 把技能包纳入自己的版本管理，避免代理侧能力随上游更新而无声变化

## 6. 风险与边界

- 生成成本由外部模型与 MCP 服务决定，估价规则能否覆盖所有调用路径需要自行核对
- expert tools 依赖本机 DCC 软件的安装与版本，不同版本的操作路径可能失效
- README 明确各家族「验证到什么程度」各不相同，未验证部分不宜直接用于生产
- 技能是代理可执行的能力描述，接入前应审阅其实际调用范围，尤其是涉及本机应用操作的部分

## 7. 谁该用 / 谁别碰

需要让编码代理产出游戏与创意资产、或希望把本机 DCC 软件纳入代理工作流的开发者与技术美术团队。
