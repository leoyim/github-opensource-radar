## 1. 它解决什么问题

模拟器要在运行时翻译指令与图形调用，开销与兼容性都受制于宿主环境。静态重编译试图把这一步翻译提前到构建期完成，让程序直接在 PC 上以原生指令运行。

## 2. 为什么是现在

项目仅 8 天、5,169 星、430 fork、318 个开放议题，热度为速度估算（约 1,698），是本期估算热度最高的一项。它与同榜的 GeoLibre、gpui-kit 一起构成本期桌面与跨端方向的三条不同技术路径——静态重编译、WebAssembly 与原生 UI 框架。

## 3. 关键能力

- 将指定游戏静态重编译为 Windows 与 Linux 的 x86-64 原生应用
- 提供 Vulkan 渲染后端
- 当前已可在两个平台游玩，仓库明确标注处于早期开发
- 提供 docs/architecture.md 说明实现结构与 CONTRIBUTING.md 说明问题反馈方式
- 不附带游戏文件，需使用方自行准备

## 4. 架构与实现

C 实现、MIT 许可，核心思路是把原平台机器码与图形调用在构建期翻译为目标平台可执行代码，而不是运行时模拟，因此理论运行开销更低，但对原程序版本与资源布局的依赖也更硬。README 明确写明「早期开发，视觉错误与崩溃仍属预期」，318 个开放议题也印证问题面较大；架构细节应以仓库文档为准。

## 5. 上手路径

1. 先读 docs/architecture.md，弄清翻译边界与已知限制
2. 按文档准备合法取得的游戏文件，确认版本匹配
3. 在 Windows 或 Linux 跑通一次，并对照已知问题列表核对现象
4. 提交 issue 时按 CONTRIBUTING.md 提供完整复现步骤

## 6. 风险与边界

- 需要自备游戏文件，涉及原作版权与使用场景，务必遵守适用法律与授权
- 项目仅 8 天且明确处于早期开发，崩溃与视觉错误属于预期
- 静态重编译对原程序版本敏感，上游更新可能导致整体失效
