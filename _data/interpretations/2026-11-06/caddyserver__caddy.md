## 1. 它解决什么问题

给一个服务配 HTTPS 通常要单独准备证书签发客户端、配定时续期、处理签发者故障，内部服务与 IP 还得自建 CA；这套流程和 Web 服务器本身的配置混在一起，容易在小项目里被直接跳过，在大集群里变成一堆脆弱脚本。

## 2. 为什么是现在

项目 4,314 天、78,815 星，本期 +54，是本期评分最高的项目之一（综合 87.6）。它在一个几乎全是新仓与 agent 工具的榜单里出现，说明自动 HTTPS 这类「把运维步骤产品化」的能力仍在持续获得真实使用与关注，而非一次性尝鲜。

## 3. 关键能力

- 默认自动 HTTPS，支持 HTTP/1.1、HTTP/2 与 HTTP/3
- 三种配置入口：简洁的 Caddyfile、原生 JSON 配置、可动态改配置的 JSON API，另有 config adapters
- 公共名称使用 Let's Encrypt 与 ZeroSSL；内部名称与 IP 由全托管本地 CA 签发
- 集群内多实例协调、多签发者回退、Encrypted ClientHello（ECH）支持
- 在 TLS/OCSP 等证书相关问题导致其他服务器中断时仍能保持服务

## 4. 架构与实现

Go 实现、Apache-2.0 许可，模块化架构且无外部依赖（连 libc 都不需要），单二进制即可分发。配置层把人类可读的 Caddyfile 与机器友好的 JSON API 分开，config adapters 允许其他写法接入同一内核。证书管理不是外挂组件而是默认行为：多签发者回退与本地 CA 覆盖了从公网域名到内部 IP 的不同场景，集群协调则让多个实例能共享证书状态。README 摘录以特性列表为主，接口细节需查文档。

## 5. 上手路径

1. 用一个 Caddyfile 起一个静态站点，观察证书自动签发是否完成
2. 切换到 JSON API 试一次运行时改配置，理解动态配置边界
3. 为内部服务或 IP 启用本地 CA，验证客户端信任链
4. 多实例场景再评估集群协调与多签发者回退配置

## 6. 风险与边界

- 自动证书依赖公网可达性与签发者配额，隔离网络需提前规划本地 CA 路径
- 动态 JSON API 若暴露到不受控网络，等同于开放服务器配置修改能力，需严格限制访问
- 功能面很广，从 Caddyfile 迁移到 JSON 配置时概念映射需要重新学习
- README 摘录为特性清单，部署与安全细节应查阅官方文档

## 7. 谁该用 / 谁别碰

需要快速、可靠地为公网与内部服务启用 HTTPS，且不愿单独维护证书续期脚本的开发者与运维团队。
