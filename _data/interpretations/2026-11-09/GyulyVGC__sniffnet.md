## 1. 它解决什么问题

抓包工具要么命令行参数复杂、结果需要另写脚本才能看懂，要么界面停留在原始报文列表。日常排查里更常需要的是先看清「现在流量有多大、连了谁、对方在哪里」，再决定要不要深挖报文。缺的是把这几层信息直接呈现在一个直观界面里。

## 2. 为什么是现在

项目 1,561 天、42,103 星，本期 +80，1,975 fork、56 个 open issue，是本期星标总量最高的项目之一，也是长期维护的 Rust 桌面应用代表。README 把多语言翻译（含简体中文）与 Troubleshooting 中缺失依赖、渲染问题的排查并列写出，说明重心已转向让非专业用户也能顺利跑起来，而非继续叠加抓包能力。

## 3. 关键能力

- 选择要检查的网络适配器，对观察到的流量应用过滤条件
- 以 PCAP 文件导入与导出完整的抓包报告
- 查看整体网络统计与实时流量强度图表
- 识别本地网络中的连接
- 查询远端主机的地理位置
- 查看正在通信主机的域名与 ASN；界面提供包括简体中文在内的二十余种语言

## 4. 架构与实现

Rust 实现、Apache-2.0 许可，形态为跨平台桌面应用（README 提及 iced 相关标签）。章节为 Download、Features、User manual、Troubleshooting（含 Missing dependencies、Rendering problems）、Acknowledgements、Stay in the loop，说明项目把「装得上、跑得动」作为文档重点。关键取舍是把抓包结果在应用层直接汇总为统计、图表与归属信息，并保留 PCAP 导入导出以便与专业工具衔接；README 也明确说明项目免费开源且维护投入较大。

## 5. 上手路径

1. 从 Download 获取对应平台安装包，先确认抓包所需的系统依赖已就绪
2. 选择一个网卡，用默认过滤跑几分钟，观察实时流量图表是否稳定
3. 查看远端主机的地理位置、域名与 ASN，核对归属信息是否符合预期
4. 需要深入分析时导出 PCAP，交给专业报文工具继续排查；遇渲染问题先查 Troubleshooting

## 6. 风险与边界

- 抓包通常需要较高系统权限，部署时需明确授权范围与数据留存策略
- 不同平台的底层依赖不同，Missing dependencies 章节列出的问题需按系统逐项处理
- 地理位置与 ASN 信息来自外部映射数据，结果可能与实际情况有偏差
- README 提示渲染问题在某些环境下会出现，显卡或图形栈兼容性需自行验证

## 7. 谁该用 / 谁别碰
