## 1. 它解决什么问题

传统数据平台通常要十几台机器与上百 G 内存，集成、调度、建模、问数各由一套系统承担，部署与运维门槛把小团队挡在门外。要做的是把这些能力重新设计进一套轻量运行时，而不是把几个开源工具简单拼起来。

## 2. 为什么是现在

项目仅 43 天、38 星，本期 +2，16 fork，是本期最年轻的中文项目之一。README 直接以「DataY = DataX + Nifi + DolphinScheduler」作类比却强调不是拼盘，并把 AI Data Agent 与 MCP Harness 列入五大能力；在本期多个项目把代理接进工程链路的背景下，它是把 MCP 落到数据平台对象上的一例。

## 3. 关键能力

- 支持二十余种数据源：MySQL、PostgreSQL、Oracle、SAP HANA、Doris、ClickHouse、DuckDB 等
- 可视化拖拽画布编排 ETL 数据流，也可用 JSON 配置文件一键跑任务
- 全量同步、增量同步，以及 MySQL、PostgreSQL、Oracle 的 CDC 实时同步
- 自动建表与 DDL 转换，源表字段变更自动同步到目标端
- 跨库数据比对：按主键关联两侧表，用 DuckDB SQL 计算差异，结果写入本地或 MinIO
- 智能问数 AI Data Agent 与 MCP Harness，让代理直接操作平台对象；另含维度建模、任务调度与高性能数仓

## 4. 架构与实现

Java 实现、Apache-2.0 许可，自述为一个 JAR 加自研流批一体数据集成框架与自研分布式调度框架，在单机模式下调度与执行合一；AI 能力需提供模型 API Key，README 注明默认为 Deepseek 原厂 Key。章节依次为 DataY · 轻量数据平台、为什么是 DataY、项目结构、五大能力（集成／建模／调度／数仓／智能问数／MCP Harness）、环境要求、一键部署、下载与启动。关键取舍是把资源门槛压到 2 核 4G，并以单一运行时替代多系统拼接。

## 5. 上手路径

1. 按环境要求准备 JDK 与单机资源，从下载入口取得 JAR
2. 用一键部署或单机模式启动，先接一个 MySQL 数据源做全量同步
3. 试一次可视化画布与 JSON 配置两条入口，核对任务结果是否一致
4. 需要 AI 能力时再配置模型 API Key，并单独评估 MCP Harness 的权限范围

## 6. 风险与边界

- 项目仅 43 天、38 星，自研引擎与调度框架的稳定性、边界情况覆盖仍待验证
- 2 核 4G 是 README 给出的轻量场景，生产数据量与并发下需重新压测
- CDC、DDL 自动转换与跨库比对依赖各数据源版本，接入前应逐项验证兼容性
- AI 能力与 MCP 入口涉及外部模型调用与平台对象操作权限，需设定明确边界

## 7. 谁该用 / 谁别碰
