## 1. 它解决什么问题

让不写代码的创作者做出可发布到多平台的游戏，通常要在「易上手的积木式工具」和「可扩展的真实引擎」之间取舍：前者一旦要加自定义逻辑就到顶，后者又要求先学编程。GDevelop 的做法是把逻辑表达收敛成事件表与可复用行为，同时保留引擎与扩展的代码入口。

## 2. 为什么是现在

项目 4,515 天、28,620 星，本期 +53，是本期年龄最长的项目（2014 年创建），650 个 open issue、1,651 fork。它仍能进入日增榜，说明无代码创作工具在生成式能力普及后并未被替代，反而在 README 里加入了 AI 辅助创作的表述。本期榜单里同时出现大量新仓与多个十年以上老项目，GDevelop 是前端方向最典型的长周期样本。

## 4. 架构与实现

主语言标注 JavaScript，许可证为 NOASSERTION（使用前需核实授权）。Technical architecture 章节把仓库拆成 Core（描述游戏结构与 IDE 所需工具类）、GDJS（用 TypeScript 编写的游戏引擎，借 PixiJS 与 Three.js 完成 2D/3D WebGL 渲染）等目录，另有编辑器与扩展目录。关键设计是「无代码层与引擎层分离」：创作者面对事件表，引擎与扩展仍是可读代码，因此能力上限不会被编辑器锁死。

## 5. 上手路径

1. 从官网下载编辑器，先照入门表选一条路径（做游戏／写扩展／贡献引擎）
2. 用事件系统做一个最小可玩场景，理解事件与行为的组织方式
3. 查看 gd.games 上的示例游戏，确认目标平台的发布流程
4. 需要自定义能力时再读 Technical architecture 与扩展创建文档，进入代码层

## 6. 风险与边界
