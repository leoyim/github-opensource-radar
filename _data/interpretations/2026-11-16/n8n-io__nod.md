## 1. 它解决什么问题

多数「个人助理」只能读写 API 或给建议，真正费时间的活——追发票、退订阅、把客户消息转成任务、按时盯价格——散落在需要登录的真实网页与表单里，云端 agent 既拿不到本地会话，也不便替用户对外发言。

## 2. 为什么是现在

本期日增 +438 居全榜第一，51 天新仓已到 1,739 星。README 把「本机运行、模型自选、代你发言前先征求同意」放在最显眼位置，并给出 macOS / Windows / Linux 桌面包与 research preview 标识，体现 n8n 把工作流自动化的经验搬到桌面 agent 这一新形态。

## 3. 关键能力

- 在真实网站上执行跨标签页、登录与表单填写的任务，仓库自带独立的 computer 与 browser
- 每天汇总邮件线程、日历与客户动态，为每个会议生成一页会前简报
- 从自己的报价单起草 Slack 回复，经用户批准后发送；按计划检查页面只在价格变化时通知
- 记忆只从用户自己的消息中学习，逐条可见、可编辑、可遗忘，并保留来源消息
- 支持 ChatGPT Plus/Pro 或自带 AI key，模型与运行规则由用户决定

## 4. 架构与实现

以本地桌面应用承载 agent 运行时，配合自带的浏览器与计算机环境操作真实网站；记忆层与审批层在本地，外部只接模型 API。README 用 use/workspace、trust/approvals、use/schedules、how-it-works/memory 分节描述工作区、审批、计划与记忆的实现边界。

## 5. 上手路径

1. 按平台下载桌面包，先确认 macOS 14+ 或 Windows 11 preview 的兼容范围与所需模型凭据
2. 从只读取向的任务开始，比如生成一次会前简报，核对它引用的消息与日历是否准确
3. 开启审批流程，试一条需要代发消息的任务，确认它确实停下来等你同意
4. 再补一条「告诉它一次」的偏好，观察后续任务是否按新事实执行

## 6. 风险与边界

- research preview 状态明确，Windows 与 Linux 仍是预览，功能与稳定性可能变化
- 让 agent 带浏览器操作已登录站点，等同于把该会话的权限交给自动化流程，账户隔离要先行
- 会前简报与草稿依赖邮件/日历内容质量，误读客户动态可能带来对外表述风险
- 记忆会学习写作风格，虽 README 承诺不含姓名数字，仍应定期检查与清理记忆条目

## 7. 谁该用 / 谁别碰

适合已被重复网页事务占用大量时间、且愿意在本机保留会话状态的知识工作者；不适合需要集中审计或禁止本地浏览器自动化的受控环境。
