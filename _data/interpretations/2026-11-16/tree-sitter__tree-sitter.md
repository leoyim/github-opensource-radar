## 1. 它解决什么问题

语法高亮、折叠、跳转、重构等编辑器功能若各自写正则或完整重解析，性能与容错都难保证；尤其源码处于编辑中、语法并不完整时，解析器需要给出仍然可用的结果。

## 2. 为什么是现在

本期 27,477 星、日增 +10，4,758 天的项目仍在上榜。README 四个目标——通用、快到每次按键、语法错误下仍健壮、运行时纯 C 无依赖——几乎定义了现代编辑器语法层的标准；本期多项 agent 与代码工具都以它为隐含底座。

## 3. 关键能力

- 为源文件构建具体语法树，并在编辑时增量更新，不必整体重解析
- 解析任意编程语言，速度足以支撑编辑器逐键解析
- 存在语法错误时仍返回有用的树结构，适合编辑中的不完整代码
- 运行时库以纯 C 编写且无依赖，可嵌入任意应用
- 提供 Rust 绑定、Wasm 绑定与命令行 CLI 三类接入方式

## 4. 架构与实现

由 parser generator 与增量解析库两部分组成，语法定义生成解析器，运行时维护可增量更新的语法树；对外以 C 运行时为核心，另提供 Rust / Wasm 绑定与 crates/cli 命令行入口，文档站与 API 说明独立于仓库 README。

## 5. 上手路径

1. 先看官方文档理解语法树与 query 的概念，再从 CLI 解析一份现有源码观察节点结构
2. 为目标语言找到或编写 grammar，用示例文件验证增量更新行为
3. 在编辑器插件或代码工具里通过 Rust/Wasm 绑定接入，测一次大文件编辑的延迟
4. 需要高亮或跳转时再补 query 文件，而不是自己遍历整棵树
