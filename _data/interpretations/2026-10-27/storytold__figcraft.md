## 1. 它解决什么问题

设计文件长期是黑盒：格式私有、协作依赖云端、Agent 无法可靠读写。FigCraft 用纯 Rust 实现界面设计与原型，覆盖 Frame、自动布局、组件与变体、矢量网络、样式与变量、原型联动，并额外提供无头渲染导出与 MCP 接口，让 Agent 能直接驱动。

## 2. 为什么是现在

3,570 星、今日 +49。AI 参与设计的主流做法仍是「生成图片」或「生成代码」，中间的设计文件层缺一个可编程接口。FigCraft 把 MCP 与 headless 导出写进 README，是在抢这个位置。

## 3. 关键能力

- 设计基础：Frame、自动布局、组件与变体、矢量网络、样式与变量
- 原型联动与原生离线使用（打开即用）
- 无头模式：不启窗口执行命令脚本，做渲染与导出
- MCP 接口：Agent 可无头驱动，或附着到已打开的实例
- README 提供完整命令与参数清单
- 示例文件（如 ridgeline-app.figcraft）可直接打开

## 4. 架构与实现

纯 Rust 原生应用（README「Under the hood」章节），核心能力以命令形式暴露，再由两条通道对外：脚本化命令序列与 MCP。这种「一切皆命令」的设计使 GUI 与 Agent 走同一套执行路径，避免了双实现漂移。

## 5. 上手路径

1. 先打开示例文件熟悉自动布局与变量的组织方式
2. 用无头模式跑一次导出，确认 CI 环境可复现
3. 接 Agent 时从只读查询开始，再开放写入类命令，避免误改设计稿

## 6. 风险与边界

- 协作成熟度与生态（插件、社区资源）远不及 Figma，迁移成本高
- 原生应用的多平台一致性与文件兼容需实测
- Agent 拥有写权限时的误操作风险，需要版本控制兜底

## 7. 谁该用 / 谁别碰

关注「设计文件可被 Agent 读写」这一方向的团队与工具开发者；以 Figma 协作生态为核心的设计团队暂不具备迁移条件。
