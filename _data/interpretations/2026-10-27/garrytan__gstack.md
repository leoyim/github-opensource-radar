## 1. 它解决什么问题

直接用编码 Agent 写代码，常见失效模式是缺少角色约束：没人负责质疑产品方向、没人守架构边界、没人做发布检查。gstack 的做法是把这些职责显式化为角色——CEO 重审产品、工程经理锁架构、设计师挡「AI 味」、评审找生产 bug、QA 真开浏览器、安全官跑 OWASP + STRIDE、发布工程师推 PR。

## 2. 为什么是现在

今日 +167 星。它反映了一个明确趋势：Agent 的瓶颈从模型能力转向流程约束，而最轻的约束载体就是提示词与命令。作者是 YC 总裁 Garry Tan，README 直白说明「这是我每天用的开源软件工厂」，这类带强个人信用的项目扩散速度很快。

## 3. 关键能力

- 23 个角色化工具，覆盖产品、设计、工程管理、评审、QA、安全、发布、文档
- 全部以斜杠命令 + Markdown 实现，无二进制、无服务端
- MIT 许可，README 称安装约 30 秒
- 支持团队模式（Team mode）为共享仓库做自动更新
- 声明可配合其他编码 Agent 使用，不限 Claude Code

## 4. 架构与实现

结构极简：命令定义与角色提示都是 Markdown，安装即把文件放进对应 Agent 的配置目录；Team mode 负责在共享仓库内同步版本。没有运行时、没有状态存储——这也是它跨 Agent 可移植的原因。具体命令编排顺序见 README 的 sprint 章节。

## 5. 上手路径

1. 先只启用评审与 QA 两个角色，用真实 PR 验证是否抓到你自己漏掉的问题
2. 确认这些命令会把仓库内容发给哪家模型，按数据敏感度决定能否用于私有代码
3. 团队模式适合共享仓库，但要注意自动更新会把上游变更带进你们的流程

## 6. 风险与边界
