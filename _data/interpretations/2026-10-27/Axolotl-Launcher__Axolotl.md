## 1. 它解决什么问题

官方启动器对模组与整合包的管理能力有限，玩家常在多个第三方工具间来回搬文件；部分第三方启动器又塞入广告与付费引导。美西螈启动器基于 Modrinth App 构建，移除不适用于本项目的商业化模块，把模组、整合包、资源包与光影的检索、安装、更新收进一个客户端。

## 2. 为什么是现在

725 星、今日 +11，属小众但需求明确的方向。Minecraft 生态的启动器竞争本质是「谁能把依赖解析与版本隔离做对」，而不是功能数量；二次开发路线能让它快速继承上游能力。

## 3. 关键能力

- Modrinth 与 CurseForge 双源检索与安装：模组、整合包、资源包、光影
- 实例管理（多版本、多整合包隔离）
- 多种账户认证方式
- 个性化外观与 Axolotl 实验室工具
- 跨平台，支持源码构建与预编译二进制，另有 Nix flake

## 4. 架构与实现

Rust + Tauri + Vue（topics 标注），上游为 Modrinth App，因此继承了其依赖解析与实例管理骨架，本项目主要做减法（去商业化）与增量（实验室工具）。具体差异 README 未逐条列出。

## 5. 上手路径

1. 优先用预编译包，源码构建需要 Rust 与前端工具链齐备
2. 先建一个独立实例装整合包，验证依赖解析与 Java 版本匹配
3. 从其他启动器迁移时保留原目录，避免存档与配置被覆盖

## 6. 风险与边界

- 个人维护、基于上游二次开发，上游大版本变更会带来同步成本
