## 1. 它解决什么问题

模拟器生态长期碎片化：每个主机一个独立程序，各自实现视频输出、音频、手柄映射与存档管理，跨平台移植要重写一遍。libretro 把这些共性问题抽成 API，模拟器只实现「核心逻辑」变成动态库（core），由统一前端负责 I/O 与生命周期。

## 2. 为什么是现在

14,449 星、今日 +22。它是「抽象层设计」的经典案例：不追求功能最多，而是定义接口让别人来插。对今天做插件化架构、统一多后端的系统设计仍有直接参考价值。

## 3. 关键能力

- 参考实现前端：视频、音频、输入与应用生命周期的统一处理
- core 机制：模拟器与游戏引擎以动态库形式接入
- 跨平台覆盖：桌面、主机移植、移动端（README 分列 PC 与主机/移动依赖）
- 同一 core 换平台几乎无需移植（README 明确此点）
- GPLv3 许可

## 4. 架构与实现

libretro 定义通用音视频输入回调，core 只关心自己的模拟逻辑，前端负责呈现与调度；这种「窄接口 + 丰富实现」的结构让生态得以横向扩张，README 提到多个其他前端也复用了 libretro 接口。

## 5. 上手路径

1. 先用发行版包安装，按平台补齐 README 列出的依赖再谈编译
2. 先跑一个熟悉的 core 验证手柄与音频通路，再扩展到多主机
3. 配置文件与存档目录要单独备份，前端升级时最容易丢的是这两处

## 6. 风险与边界

- 配置项极多，初始体验陡峭，非玩家容易在设置里迷路
- core 质量由各上游决定，前端无法替你保证模拟精度
- GPLv3 对二次分发有传染性要求，商业集成需评估

## 7. 谁该用 / 谁别碰

复古游戏玩家、想把多台模拟器收敛到统一界面的用户，以及研究插件化架构的工程师；只用一两个模拟器不必引入这层。
