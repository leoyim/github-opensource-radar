## 1. 它解决什么问题

跨生态传文件的日常摩擦：Windows 与安卓之间没有隔空投送，微信文件助手要压缩画质，网盘要上传下载；局域网直传方案又常绑定单一生态。

## 2. 为什么是现在

100,670 星、上线 1,440 天、Dart（Flutter）、Apache-2.0，fork 5,799、日增 205。作为跨平台直传的事实标准之一仍在显著增长；协议开放意味着第三方实现可以互通，这是与厂商私有方案的边界差异。

## 3. 关键能力

- 局域网内安全传输文件与消息，无需互联网连接
- 覆盖 Android、iOS、macOS、Windows、Linux 全平台
- 协议开放，第三方实现可互通
- CLI 支持脚本化调用
- 传输加密，对等发现

## 4. 架构与实现

Flutter 单代码库多端打包；发现与传输走局域网协议（组播发现 + HTTP 传输），端到端在本地网络内完成，不经任何云端。

## 5. 上手路径

1. 两台异构设备（如 Windows + Android）装上互传一个大文件，测发现与速度
2. 在企业网络或带 AP 隔离的 Wi-Fi 里测一次，确认发现失败时的手动 IP 直连路径
3. 用 CLI 写一个自动化传输脚本，验证无人值守场景
4. 核对各平台的后台权限设置（局域网发现常被系统默认禁用）

## 6. 风险与边界

- 局域网发现依赖组播与防火墙放行，企业网络与 AP 隔离环境常需手动配置
- 无中继意味着两台设备必须在同一网络段，跨网段不可用
- iOS 侧的系统限制使后台接收体验弱于 Android
- 大文件分块与编码的稳定性随版本演进，升级后先复测

## 7. 谁该用 / 谁别碰

跨生态设备间高频传文件的个人用户；需要在局域网内做自动化传输的开发者。
