## 1. 它解决什么问题

着色器重编译的失败模式分散且隐蔽：视图类型错误、描述符生命周期、mip 级别偏移……每个 bug 都要单独定位；公开的逐条修复记录几乎没有。

## 2. 为什么是现在

2,038 星、上线仅 1 天、Rust、GPL-3.0，fork 493、issue 497。它跟随上游 VIctory（另一款 Xbox Series 兼容层）并把「某台 PC 上正确渲染并可玩」作为唯一目标，每条修复对应一种典型的重编译错误模式，且声明由 Claude Code 协作完成——AI 深度参与的复杂系统调试案例。

## 3. 关键能力

- meshlet 裁剪场景缓冲视图类型修复（世界终于画出来了）
- 每绘制描述符表耗尽导致挂卡的修复
- 雾重建、阴影掩码、毛发、混合蒙皮、火焰等多个材质程序的转译修复
- 命名 mip 级 gather（含偏移）读错层的修复
- 上游历史完整保留，与 XCL（GPL-2.0）的参考关系明确声明

## 4. 架构与实现

基于上游 VIctory 的 loader、运行时服务、Direct3D 12 后端与着色器重编译器，fork 层只叠加修复提交；许可证同为 GPL-3.0-or-later，不含任何游戏文件。

## 5. 上手路径

1. 按 README 逐条读修复说明，把每条映射到「重编译错误的典型模式」
2. 有对应硬件与自有游戏文件时复现验证，无则只读代码
3. 对照上游 VIctory 与 XCL 三方的差异，理解同一问题在不同层的解法
4. 关注 fork 与上游的跟进策略变化

## 6. 风险与边界

- 单机单游戏的工作分叉，不是通用改进，适用面很窄
- 497 个 issue 里大量环境类反馈，信噪比低
- 跟随上游 main，策略变化可能导致 fork 定位调整
- 与上游及 XCL 的代码边界以文档声明为准，许可合规需自行核对

## 7. 谁该用 / 谁别碰

做 GPU 兼容层与着色器翻译的工程师；想研究 AI 协作调试复杂系统案例的开发者。
