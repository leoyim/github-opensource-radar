## 1. 它解决什么问题

每个 SIEM / 日志平台都有自己的查询语法，同一条检测思路要在 Splunk、Elasticsearch、各类 EDR 上各写一遍；规则难以共享、难以评审，换个平台几乎等于重做。

## 2. 为什么是现在

11,510 星、2,943 fork、3,613 天历史，本期 +10，是安全运营领域长期沉淀的规则库而非短期热点。README 明写提供 3000+ 条可免费使用的检测规则，并按通用检测、威胁狩猎等类型划分，规模与组织方式都已成熟。

## 3. 关键能力

- 通用签名格式（Sigma）与主规则库，含 3000+ 条检测规则
- 规则按通用检测、威胁狩猎等类型组织，与具体 SIEM 平台解耦
- 提供规则包、转换工具，把同一规则编译到不同查询语法
- 设有误报反馈、新规则建议与贡献 PR 流程
- README 列出采用 Sigma 的产品与项目、官方资源与延伸阅读

## 4. 架构与实现

规则以与平台无关的 YAML 描述检测逻辑（日志字段、条件、级别与元数据），转换层再把抽象条件编译为目标 SIEM 的查询语句；主仓库负责规则内容与评审流程，工具链与集成由生态项目承接，因此内容与执行解耦。

## 5. 上手路径

1. 先读 What is Sigma 与 Key Features，理解规则中字段与条件如何映射到日志
2. 挑一条与自己环境相关的通用检测规则，用转换工具编译到实际使用的查询语法
3. 在测试数据集上跑一次，统计命中与误报，再按 Reporting False Positives 的流程反馈
4. 需要自定义时按 Rule Creation 与 Contributing 规范提交，避免直接改平台侧查询

## 6. 风险与边界

- 规则质量依赖日志字段是否规范，源数据缺字段或改名会让规则静默失效
- 通用规则在不同环境中的误报率差异很大，上线前必须按自身日志做基线校准
- 转换结果与目标平台版本相关，升级后需重新核对编译产物
- 仓库许可标注为 NOASSERTION，商用集成前应单独确认授权条款

## 7. 谁该用 / 谁别碰

适合检测工程师、威胁狩猎与蓝队/SOC 团队，以及希望复用社区规则的产品；不适合没有稳定日志字段规范、或期待开箱即零误报的环境。
