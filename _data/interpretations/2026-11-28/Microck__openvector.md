## 1. 它解决什么问题

位图转矢量的工具通常分散在三个地方：在线转换站（要上传图片）、桌面软件（贵且平台受限）、脚本库（调参麻烦）。同一个需求，三套行为。

## 2. 为什么是现在

29 天、534 星、19 fork、2 个开放 issue，MIT。本期它进入 tools 方向，靠的是「一份引擎四端一致」这个结构，而不是功能数量。

## 3. 关键能力

- 输入 png/jpeg/bmp/gif/tiff，输出 SVG、PDF、EPS、AI、DXF、EMF
- 也可回栅格为 png/jpeg/bmp/tiff
- 自动描摹、手工调色板、分段编辑、去背景
- 批量转换、保存高级配置、保留最近的基础设置
- 网页编辑器在本地浏览器内运行，不上传图片

## 4. 架构与实现

核心是一个 Rust 描摹引擎，通过不同壳层暴露：GPUI 写的桌面端、编译到 WASM 的网页编辑器、CLI 与 Node 绑定。因为共用同一份实现，四端输出的路径与参数语义一致，脚本批量跑出来的结果能和界面里逐张调的结果对齐。版本号到 v0.1.7，仍在早期。

## 5. 上手路径

1. 先用一张图标或线稿试自动描摹，确认默认参数的量级
2. 手工调色板适合颜色数有限的设计稿，照片类素材预期要放低
3. 批量场景直接用 CLI 或 Node 库，比驱动界面稳定
4. 导出 AI/DXF 前确认下游软件能正确读取对应版本

## 6. 风险与边界

- v0.1.x 阶段，格式覆盖全但边界情况仍需实测
- 照片类位图转矢量的质量受限于算法假设，不适合直接商用出图
- 19 fork 的小社区，问题反馈主要靠作者
- 网页端虽不上传，但大图在浏览器内处理仍受内存限制

## 7. 谁该用 / 谁别碰

需要把图标、线稿、Logo 批量转成矢量的设计师与前端；希望在本机完成转换、不上传素材的团队。
