## 1. 它解决什么问题

Markdown 编辑器的常见形态是「源码 + 预览」两栏，或者干脆套一层 Electron。前者割裂注意力，后者用几十兆运行时换一个文本框；想在写作时同时看到排版与结构，选择其实很少。

## 2. 为什么是现在

19 天、715 星、44 fork、10 个开放 issue，MIT，Go 加自研 MyGo Native UI。本期日增 112。它宣称零 HTML、零 JavaScript、零 WebView、零 Electron、零 cgo，界面与排版全部由 Go 驱动。

## 3. 关键能力

- 编辑区与预览合并为一张富文本画布，文字颜色、背景高亮与手绘标注直接落在正文
- 未改动段落原样保留，不改写缩进、列表符号与链接写法
- 扩展排版（GitHub Alert 高亮块、折叠块、跨格合并与着色表格、自定义比例双栏）走标准 Markdown 加语义化 HTML 无损往返
- 空间与实时配色、资料库总览、页边书签、专注模式
- 旧版 .arcmd 文档与历史快照可直接打开与迁移

## 4. 架构与实现

Go 直接驱动窗口绘制、字形排版与系统输入，不经过 WebView，因此启动与内存接近原生应用；文本模型以「块」为单位，通过 ImportSource 比对原始 Markdown，只重写被编辑的段落，从而实现无损往返。性能口径写得克制：测的是无窗口宿主跑完整帧构建的 CPU 耗时，明确不含事件分发、GPU 光栅化与显示延迟，不等同于端到端延迟。

## 5. 上手路径

1. 先用一份已有 Markdown 打开，确认未编辑段落的缩进与列表符号是否被改动
2. 试一次扩展排版（高亮块、双栏）再存回，检查标准 Markdown 兼容性
3. 输入法场景重点验证：中文、日文候选框与选区行为是原生排版最容易出问题的地方
4. 从源码构建需 Go 1.27 以上与 MyGo v0.10，注意 CGO 关闭

## 6. 风险与边界

- 19 天的新项目，输入法、超长文档与大表格的边界仍在收敛
- 「120Hz 流畅」是自测口径，不含显示链路，端到端体感需自行验证
- 单一平台与单一维护者，跨平台计划未见明确时间表
- 无损往返依赖其自身扩展语法，换编辑器后部分排版会退化

## 7. 谁该用 / 谁别碰

在意写作手感与本地文件掌控、不愿为编辑器装一个浏览器的写作者；关注原生 UI 与 Go 桌面开发的技术读者。
