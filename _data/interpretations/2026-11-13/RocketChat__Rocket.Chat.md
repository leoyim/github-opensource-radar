## 1. 它解决什么问题

对数据驻留、内网隔离或监管有硬要求的组织，用公有云沟通工具往往过不了合规审查；而自建一套带端到端加密、 federation、应用市场和移动端的服务，成本又明显高于部署一个聊天服务。缺的是一个把这些能力放在同一发行版里、且允许完全离网运行的方案。

## 2. 为什么是现在

4,196 天的项目本期仍 +52，46,502 星、14,148 fork、4,404 个 issue 显示它仍处在大规模真实使用中。本期后端与协作方向里，它是少数把「气隙部署」写成一等能力的入选项目。

## 3. 关键能力

- 自托管、云托管与 air-gapped 工作区多种部署形态，支持 Docker、Podman 与 Kubernetes，并带可扩展架构与性能监控
- 身份管理、端到端加密、基于角色与属性的访问控制，以及面向合规的信任与说明文档
- 异步与实时消息、语音通话、跨组织 federation，桌面与移动端客户端齐备
- Marketplace 公共应用与 Apps-Engine 自建应用，可把外部系统接进工作区
- README 单列 Trust and compliance、Apps-Engine 与社区/贡献入口，治理与采用者信息较完整

## 5. 上手路径

1. 先按官方文档用 Docker 起一个最小实例，确认存储与数据库依赖的运维边界
2. 在部署形态里明确选哪一条（自托管 / 云 / 气隙），气隙环境要提前规划升级与证书分发
3. 配置身份源、角色与属性访问控制，端到端加密与联邦按需逐项开启
4. 用 Apps-Engine 接一个内部系统做小范围验证，再评估迁移既有频道与历史数据的成本
