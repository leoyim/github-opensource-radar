## 1. 它解决什么问题

摄像头方案在卧室、卫生间、养老照护场景里有天然抵触，穿戴设备又要人配合。WiFi 的 CSI（信道状态信息）会因人体移动与呼吸产生可测扰动，RuView 把这套物理信号做成可用的感知管线：存在检测、人数、活动识别、生命体征、环境指纹。

## 2. 为什么是现在

今日 +182 星。ESP32 这类低成本网卡能直接导出 CSI，让「无摄像头感知」从论文走到可复现的工程；同时智能家居生态（Home Assistant、Matter、HomeKit）已经把接入层标准化，落地路径比两年前短很多。

## 3. 关键能力

- 存在与占位：穿墙检测、计数、进出追踪
- 生命体征：无接触呼吸率与心率，睡眠或静坐状态下测量
- 活动识别：行走、坐、手势、跌倒（基于 CSI 时序模式）
- 环境建图：RF 指纹识别房间、发现家具移动与新物体
- 睡眠分析：整夜监测、睡眠分期与呼吸暂停筛查
- 无摄像头姿态：从 CSI 估计 17 个身体关键点
- 自带模型工作流：录制 CSI → 训练 → 加载 RVF → 切换 LoRA
- 本地自动化：HOMECORE 提供状态、历史、自动化与 HomeKit 支持

## 4. 架构与实现

Rust 为主，ESP32 节点采集 CSI 并通过 UDP 上报；服务端提供 MCP（stdio 或 HTTP）与 Claude Code 的实时感知面板；Docker 路径可用模拟数据在无硬件情况下跑通。生态对接包括 Home Assistant 的 HA-DISCO MQTT publisher、HAP-1.1 桥、Matter 端点。

## 5. 上手路径

1. 先用 Docker + 模拟数据跑通界面与数据流，确认软件链路
2. 再上 1-2 个 ESP32 节点采真实 CSI，注意 Docker 里需要 UDP source guard
3. 从一个房间、一个人、静止场景开始标定，再逐步加难度（多人、隔墙、活动）

## 6. 风险与边界

- 「穿墙」「心率」「17 关键点」都是宣称能力，精度强依赖房间布局、墙体材质与节点摆放，必须自测
- CSI 采集对固件与网卡型号敏感，换硬件可能整套失效
- 生命体征与跌倒属医疗/安全相关判断，不能直接作为决策依据

## 7. 谁该用 / 谁别碰

适合做隐私敏感场景感知（照护、独居监测、智能家居）的团队与研究项目；需要开箱即用的商业级精度时，现阶段的误差不可接受。
