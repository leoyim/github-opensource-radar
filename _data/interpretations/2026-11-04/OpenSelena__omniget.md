## 1. 它解决什么问题

命令行下载工具（yt-dlp 一类）能力极强，但对非命令行用户几乎是不可用的：参数记不住、站点支持度不知道、批量任务不会管。GUI 封装的价值就在这里——把「站点 + 格式 + 后处理」变成表单，把队列、断点与失败重试变成界面状态。omniget 在此之上又加了一层：既然是媒体工具箱，字幕、转写、压缩、阅读器一并做进去。

## 2. 为什么是现在

119 天、1,477 星，本轮无基线（首次上榜）。它出现的位置很清楚：Tauri 2 让「用 Web 技术写跨平台桌面应用」的成本降到个人可承受，于是过去只能做成 Electron 臃肿应用的工具类软件，开始以几十 MB 的体积重新出现。而下载器这个品类长期只有命令行与广告捆绑的闭源软件两个选项，中间地带是空的。

## 3. 关键能力

- 多站点下载，宣称覆盖 1,800+ 站点，含视频、音乐、社交平台与部分课程平台
- 下载队列与批量任务管理，支持字幕单独下载
- 内置 Whisper 转写与 TTS，可把音视频转成文本或反向生成
- EPUB / PDF 阅读器与 PDF 工具（修复、转 Markdown）
- Anki 卡片与间隔重复，衔接「看完就记」的流程
- 音视频压缩、视频转 GIF、图片压缩
- 本地优先设计，Tauri 2 + Rust + Svelte，Windows / macOS / Linux 三平台

## 4. 架构与实现

Tauri 2 的模型是「Rust 后端 + 系统 WebView 前端」，因此体积远小于 Electron，代价是各平台 WebView 差异需要额外适配。下载能力大概率是封装既有提取器（yt-dlp 一类），这决定了它的站点覆盖度与稳定性上限——上游改了，它才跟着改。功能堆叠是它的策略：把「媒体相关的所有小事」收进一个应用，用广度换留存，代价是每个方向的深度都有限。

## 5. 上手路径

1. 先只下自己有权的素材，课程平台类功能涉及平台条款与版权，风险自担
2. 批量任务前先测单条：格式选择与后处理（合并音轨、转码）是最容易出错的一步
3. 转写与压缩是计算密集操作，笔记本上建议限制并发，否则会明显拖慢系统
4. 关注上游提取器的更新节奏，站点改版后下载失败通常要等它跟进

## 6. 风险与边界

- 面向课程平台的下载功能涉及平台服务条款与版权边界，个人学习之外的用途需自行评估
- 站点支持度依赖上游提取器，平台改版会导致部分站点失效
- 功能面极广但深度有限，转写、阅读、Anki 等模块的成熟度不均
- 下载内容常含版权素材，分发与二次使用可能侵权
- Tauri 应用的自动更新与签名机制需确认，否则手动升级容易落在旧版本

## 7. 谁该用 / 谁别碰

需要批量下载与管理媒体文件的普通用户、做素材整理的创作者，以及想找一个跨平台、体积可控的下载工具的开发者。
