## 1. 它解决什么问题

通用聊天模型的教学方式有个结构性缺陷：它不知道你的实际水平，只能对着「平均读者」输出解释，于是你熟悉的部分被重复、卡住的那一步被跳过。学习者自己也常常判断错误——「看懂了」和「能推出来」是两件事。真正有效的教学需要三样东西：对当前理解的测量、到目标的能力依赖图、以及跨会话的记忆，而这三样都不在一次对话的上下文窗口里。

## 2. 为什么是现在

今日 +512 星、12 天 3,631 星。它出现的位置值得注意：本期 AI 类前五里有三个（EGM、learnharness、dashboard-design-skill）都在做「把某个专业流程拆成 agent 可执行的步骤」，学习恰好是最难拆、也最需要测量的一类。同期社区对「AI 让人变笨」的讨论升温，这个项目的立场相反：用 agent 做诊断和编排，把推理的活留给人。

## 3. 关键能力

- Measure：正式教学前，先找出你在该课依赖的每个子能力上理解终止的位置，采集答案、信心与推理过程
- Plan：从测量结果生成到目标的依赖图，计划对学习者可见，并随理解变化调整
- Teach：按推理步骤逐个推进，而不是整段灌输；每步之后用练习把理解固化成可用技能
- 持久知识图谱跨会话保留你的理解画像，不必每次从头自我介绍
- 提供桌面下载与在线文档，AGPL-3.0

## 4. 架构与实现

核心是一个以知识图谱为状态载体的教学编排器：图谱节点是概念与推理步骤，边是依赖关系；每次交互更新节点上的掌握度估计，规划器据此选择下一个教学动作。README 把它描述为 agent harness，即模型本身可替换，harness 负责流程与状态。具体图谱的构建方式与测量算法未在 README 展开。

## 5. 上手路径

1. 选一个你确实卡住过、且有明确边界的主题（不要选「学完机器学习」这种无边界目标）
2. 第一次会话专心做测量，不要急着要答案——测量质量直接决定后续计划是否有效
3. 拿到依赖图后先人工删掉你确认已掌握的分支，避免它在低价值节点上耗时
4. 连续用两周再评估：跨会话记忆的价值只有在第二次、第三次会话才体现出来

## 6. 风险与边界

- 测量环节需要大量作答，前期投入高，容易在第一天就放弃
- 知识图谱的粒度由系统决定，对高度非标准的知识领域（前沿论文、内部系统）可能建不出有效依赖图
- AGPL-3.0，若要做成对外服务需评估传染性条款
- 教学效果高度依赖模型能力，换小模型可能退化为普通问答

## 7. 谁该用 / 谁别碰

要系统啃硬知识、愿意被反复追问、且能接受前几小时「只被测不学东西」的自学者；追求快速概览的人会强烈不适应。
