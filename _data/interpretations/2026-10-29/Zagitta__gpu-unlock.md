> **一句话**：同一块硅片，消费卡被锁到半速——它在驱动加载前把锁摘掉。

## 1. 它解决什么问题

NVIDIA 在 GeForce 上把 tensor core 的 FP16 / BF16 / TF32 加 FP32 累加路径限制到半速，而这恰好是几乎所有 AI 训练和非量化推理用的精度组合。同样的芯片做成 RTX A 系列就全速。用户买了硬件却只用到一半算力，且这个限制不在任何规格表上明示。现有绕法要么刷 VBIOS（风险高、易变砖），要么装补丁驱动（NVIDIA 每次更新都要重做，且签名麻烦）。

## 2. 为什么是现在

今日 +1,005 星、11 天 12,405 星，本期第二高日增。它踩中的是本地推理成本这条主线：过去一年大家习惯了租卡，现在更多人想在自己机器上跑微调和出图，于是「我这张 4090 到底能跑多快」成了真问题。同期上榜的 net-merge、TwinDesk 都是同一取向——不买新硬件，先把已有硬件的余量榨出来。

## 3. 关键能力

- 开机阶段生效：在官方 NVIDIA 驱动加载之前移除限制，不修改驱动本身
- 不打补丁驱动、不刷 VBIOS，NVIDIA 发布新驱动后无需重做
- README 标注收益：最高 2× FP16/BF16/TF32 tensor 吞吐，LLM prefill +25–55%，微调 +25–50%，出图 +30–55%
- 覆盖 20/30/40 系，README 有 Supported GPUs 与 Benchmarks 分节可自查
- 安装方式按引导器分列：GRUB（Debian/Ubuntu/Mint）、GRUB（Arch/CachyOS）、Fedora/RHEL、systemd-boot

## 4. 架构与实现

实现层次在「内核启动参数 + 早期引导阶段」，而不是驱动层：通过在 bootloader 命令行注入参数，让限制在 stock driver 初始化之前就被解除，因此对上层 CUDA 栈透明，也不需要维护驱动补丁。这种设计的代价是强绑定引导方式与内核版本，容器、Windows、云主机等场景无法套用。README 未声明许可证，这是采用前必须确认的一项。

## 5. 上手路径

1. 先读 Supported GPUs 与 Benchmarks，确认你的卡型与工作负载（prefill / 微调 / 出图）在受益区间内
2. 在非生产机器上先做一次完整备份与引导配置快照——改 bootloader 命令行出错会导致起不来
3. 按你的引导器选择对应小节，只改一项、只加一次，重启后用同一组 benchmark 前后对比
4. 确认收益后再考虑扩散；多机环境建议先在一台上跑满两周稳定性

## 6. 风险与边界

- 改动引导参数属于系统级 hack，失败会进不了系统，恢复依赖你事先的引导备份
- 极可能违反 NVIDIA 的消费级产品许可条款，商用与保修均有风险
- 仅 Linux + 特定引导器可用，Windows 与云 GPU 无效
- 仓库无 LICENSE 文件，法律状态不明；11 天即万星、讨论热度高于工程沉淀，需自行审查脚本
- 散热与功耗预算会随吞吐提升而变化，长时间满载需重新评估

## 7. 谁该用 / 谁别碰

有闲置 20/30/40 系卡、在 Linux 上做本地微调或批量出图、且能承担系统级风险的个人研究者与小团队。生产集群与有合规要求的组织不建议采用。
