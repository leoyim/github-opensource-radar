## 1. 它解决什么问题

「让 AI 刷视频」已经火了，但那只解决了消费侧。要在 B 站做内容运营，需要的是发布侧的一整套动作：投稿、发动态、评论、私信、看通知，而且每个动作都有平台特有的细节——@ 必须是真 at 才会给对方推送、评论可以带图和站内表情、回复要能筛出没回过的。这些细节没有任何官方 API 文档友好地覆盖，agent 自己摸索必然踩坑。

## 2. 为什么是现在

今日 +23 星、9 天 298 星。它的时点很准：本期 AI 类前五里有三个在做「给 agent 的工具层」，而 bili-cli 的特殊之处是把工具层做在了中国互联网平台上——这类工作通常没人做，因为需要大量平台细节知识且容易失效。同期 eidolon-sc 也是国内平台的深度适配。

## 3. 关键能力

- 扫码登录，避免在配置里存密码
- 覆盖看视频、评论、私信、发动态、投稿，全部 JSON 输出，任何能执行命令的 agent 可用
- 统一收件箱：回复、@、赞、系统通知、私信聚合，每条附可直接执行的回复命令
- 真 @ 支持：对方会收到提醒，可填 UID 或昵称
- 带图评论与站内表情，能读取他人评论中的图片并存到本地供多模态模型查看
- 运营向筛选：`--unreplied` 只列未回复评论，自己作品下的评论可置顶
- 提供 bili skills install 一键装技能，适配 Claude Code、Codex、Cursor、Gemini CLI、DeepSeek Harness 等

## 4. 架构与实现

Python CLI（pip 包名 bili-agent）+ 技能清单的分层：底层把 B 站网页端接口封装成有类型的命令，上层用 skills install 把命令的使用说明注入宿主 agent。全部 JSON 输出的设计让 agent 不需要解析自然语言，也便于串成管道。

## 5. 上手路径

1. 先只做只读动作（看通知、列未回复），确认登录态稳定后再开写操作
2. 投稿与发动态前先在测试账号上跑一遍，平台风控对自动化行为的容忍度有限
3. 把 `--unreplied` 接进每日例程，它比让 agent 自己判断「哪条没回过」可靠得多
4. 带图评论的图片本地化路径要固定，否则多模态读取会找不到文件

## 6. 风险与边界

- 依赖网页端接口，平台改版即失效，维护压力大
- 自动化操作可能触发风控甚至限流，账号安全需自行评估
- 9 天 298 星，接口覆盖与稳定性仍在快速变化
- 发内容类动作不可逆，建议始终保留人工确认环节

## 7. 谁该用 / 谁别碰

想让 agent 代运营 B 站账号的 UP 主与小团队、以及做内容工作流自动化的开发者；纯内容消费没必要。
