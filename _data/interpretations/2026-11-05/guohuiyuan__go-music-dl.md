## 1. 它解决什么问题

音乐分散在十余个平台，歌单与下载各用一套客户端；想批量整理本地曲库，或让 agent 按一句话点歌，现有工具都做不到。

## 2. 为什么是现在

仓库 291 天、6,012 星，本期 +87。增长点不在下载本身，而在今年补上的「AI 可调用接口」：agent 可以直接操控正在运行的网页播放器。当 agent 成为交互入口，工具的评价标准从「界面好不好用」变成「能不能被调用」。

## 3. 关键能力

- 覆盖网易云、QQ、酷狗、Bilibili、汽水音乐等十余个源，多源并发搜索与失败换源
- 单曲、歌单、专辑、排行榜与本地音乐管理
- CLI、TUI、Web 与桌面端四种形态，Android 包内置 FFmpeg
- AI/Agent 调用接口：点歌、切歌、暂停、调音量，可直接操控已打开的网页播放器
- 按 client id 定向投递，多设备在线时返回 409 与候选列表，不广播误操作

## 4. 架构与实现

Go 后端 + 多前端（Rust/Go 桌面端、Web、TUI、Android），搜索层做多源并发与换源。取舍是「多源覆盖换稳定性」：任一源的接口或风控变化都会影响结果，需要持续跟进维护。

## 5. 上手路径

1. 先用 Web 模式跑搜索与试听，确认目标音源在你的网络下可用
2. 首次启动从日志取出 setup token 创建管理员，再配置 Cookie
3. 接 agent 前用 curl 验证 /play 与 /command 的定向语义，确认多设备时不误触

## 6. 风险与边界

- 版权与平台条款风险是根本性的，下载与解析行为可能违反服务协议
- 接口依赖各家非公开端点，随时可能失效或触发风控
- AGPL-3.0，二次分发与网络服务需评估许可义务
- Android APK 与桌面安装包来自第三方构建，需核对签名与来源

## 7. 谁该用 / 谁别碰

需要整理本地曲库的个人用户，以及想把音乐控制接进 agent 或自动化流程的开发者。
