## 1. 它解决什么问题

短视频的产能瓶颈不在拍摄，而在重复劳动：写文案、找素材、配音、对齐字幕、配乐、剪辑，每一步都有工具，但把六步串起来、并且让每一步都能换供应商，成本很高。大部分团队最终退化成一套手工模板，产量卡在人身上。

## 2. 为什么是现在

仓库 969 天、13.9 万星，本期 +617。老项目还能维持这个量级，说明需求没有消退，变化的是入口：补上 Agent 调用方式后，它从「人点按钮的工具」变成「agent 流水线里的一段」。同时模型适配清单已经长到二十余家，可替换性才让成本真正可控。

## 3. 关键能力

- 四种使用方式：AI Agent、WebUI、API、CLI，既可直接上手也能接进自动化流程
- 主题或关键词驱动的全链条：脚本 → 配音 → 素材 → 字幕 → 配乐 → 合成，每段都可替换为自定义内容
- 批量生成多条成片、任务历史记录，以及生成设置与 API Key 的导入导出和恢复
- 多语言脚本自动生成或改写，也可直接使用自定义脚本
- 素材来源：本地图片/视频，或 Pexels、Pixabay、Coverr 的库存素材
- 可接秘塔 MiniMax H3 文生视频生成 768P/2K、4–15 秒原始素材，适配 9:16、16:9、1:1（README 自述）

## 4. 架构与实现

Python 实现，合成交给 FFmpeg。结构上是一个编排器：脚本、TTS、素材检索、字幕、BGM 各自抽象成 provider，按顺序落盘再合成。取舍是「可替换性优先于单点最优」——任何一段都能换供应商，代价是成片质量取决于最弱的一段，拼接痕迹仍需人工复核。

## 5. 上手路径

1. 先用 WebUI 跑通一条 30 秒成片，确认 FFmpeg、字体与中文字幕渲染正常，再谈批量
2. 固定一个模型与一个素材源做基线，然后逐段替换对比，避免同时改多个变量导致无法归因
3. 批量前先看任务历史里的失败分布：TTS 超时与字幕对齐是最常见的两类问题

## 6. 风险与边界

- 素材版权与平台合规：库存素材的商用范围、以及各平台对 AI 生成内容的标注要求需逐项确认
- 配音语速与字幕时长不匹配会造成音画不同步，长句场景尤其明显
- 多 provider 适配清单很长，但各家接口稳定性与生成质量差异大，替换不等于等价
- 13.9 万星的仓库 issue 噪音大，排障应优先看近期 issue 而非泛化搜索
- README 内含模型服务的推广返利链接，模型推荐部分需自行判断
