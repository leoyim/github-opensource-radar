## 1. 它解决什么问题

WhatsApp 桌面端基于 Web 技术，常驻内存高、启动慢，在多开与低配机器上尤其明显；而聊天是全天挂着的应用，资源占用会被时间放大。

## 2. 为什么是现在

仓库 68 天、2,854 星，本期 +268。它与同期的 Spotifast 出自同一作者、同一套 fastframe 框架，说明「原生重写高频桌面应用」已经从个案变成一条可复制的路线——协议层复用，界面层重写。

## 3. 关键能力

- 通过 whatsapp-rust 以「关联设备」方式登录，手机扫码即用
- 不内嵌浏览器引擎，纯原生渲染
- Linux 实测启动不到 1 秒、空闲约 200MB（作者自测，对比 WhatsApp Web 1.13GB）
- 十余种界面语言，含简体与繁体中文
- 历史消息按滚动位置从手机按需拉取

## 4. 架构与实现

Rust + egui + fastframe，协议层与界面层分离，消息与同步状态存本地。取舍是「原生渲染换功能覆盖」：Web 端的边角功能（状态、通话、部分媒体处理）通常滞后，功能对齐需要持续追赶。

## 5. 上手路径

1. 先确认平台包可用，并准备手机端扫码关联设备
2. 绑定后只同步最近会话，验证按需加载历史是否正常
3. 观察一周内存与耗电，再决定是否替换官方客户端

## 6. 风险与边界

- 非官方客户端，账号存在被平台风控的可能
- 功能覆盖不完整，通话与部分媒体能力可能缺失
- 依赖 whatsapp-rust 上游，协议变更会直接影响可用性
- 68 天的新项目，长期维护与更新节奏不确定

## 7. 谁该用 / 谁别碰

在 Linux 或低配机器上重度使用 WhatsApp、对内存与启动速度敏感的用户。
