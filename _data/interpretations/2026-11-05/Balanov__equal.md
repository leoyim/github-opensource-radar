## 1. 它解决什么问题

开发与 CI 都依赖第三方 API，而对方可能限流、按次计费、在测试环境不可用，或者在 CI 里触发不安全的副作用。手写 mock 成本高，且很快与真实契约脱节，测试于是变成「测 mock 而不是测集成」。

## 2. 为什么是现在

1 天的新项目、151 星，本期按增速估算约 52/日。它契合的是「agent 与自动化大量调用外部 API」的现实：调用次数上去之后，录制回放从测试技巧变成了基础设施。

## 3. 关键能力

- 本地录制器：把真实流量转成返回录制响应的本地服务
- 可移植的 JSONL 磁带，可审阅、可编辑、可分享、可随 Git 版本化
- 自动生成 OpenAPI 3.1 文档，供 Postman、Prism、文档站与 SDK 生成器使用
- 任意 HTTP SDK 无需改代码，只需指向本地端点
- 单个 7.4MB 静态二进制，无运行时与账号，跨三平台双架构

## 4. 架构与实现

Go 编译的静态二进制，充当 HTTP 代理与磁带存储，再把观察到的请求/响应归纳成 OpenAPI。取舍是「录制保真换场景覆盖」：回放只能覆盖录过的路径，超时、5xx、限流等异常分支需手动补录。

## 5. 上手路径

1. 用测试凭据录一条完整业务流，检查磁带里是否混入认证头与个人信息
2. 把磁带与生成的 OpenAPI 一起入库，作为契约基线
3. CI 里先只替换读接口，写接口保留真实调用或显式桩，避免掩盖副作用

## 6. 风险与边界

- 1 天的新项目，流式响应、WebSocket、分页与签名校验等边界覆盖度未知
- 磁带可能包含 PII 与密钥，未经脱敏不应入库
- 回放无法覆盖未录制的错误分支，容易产生「测试全绿但线上失败」
- 生成 OpenAPI 的质量取决于样本覆盖度，不能当作权威契约

## 7. 谁该用 / 谁别碰

集成多个第三方 API 的团队，以及需要在 CI 里稳定跑集成测试的工程组。
