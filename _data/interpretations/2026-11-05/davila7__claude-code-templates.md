## 1. 它解决什么问题

Claude Code 的扩展生态散落在成百上千个仓库里：skills、agents、hooks、MCP 集成各有各的安装方式，质量参差。找到、判断、安全装上，变成一件纯体力活。

## 2. 为什么是现在

仓库 489 天、33,131 星，本期 +30。agent 扩展在近半年爆发，目录型项目的价值随之上升；同时「安装前能看清会写入什么文件」成为安全刚需——这正是它把预览放在核心位置的原因。

## 3. 关键能力

- 约 1900 个组件的开放目录：skills、agents、slash 命令、MCP 集成、settings、hooks、mods、loops、沙箱与项目模板
- 一条命令安装，安装前可逐文件预览
- 可把多个组件合并成一次安装
- 目录中标注组件来源仓库与许可证

## 4. 架构与实现

Python CLI 加目录服务，组件以文件包形式分发，安装即写入项目配置目录。取舍是「便利换可控性」：一键安装降低了门槛，也意味着必须依赖预览与来源标注来兜底安全。

## 5. 上手路径

1. 先只浏览与预览，不安装，确认组件来源与许可证
2. 在独立测试项目里装一次，用 git diff 看清实际写入了哪些文件
3. 固定版本再进团队仓库，避免目录更新导致环境漂移

## 6. 风险与边界

- 第三方组件未经审计，hooks 与 settings 能执行任意命令，风险等级等同于引入依赖
- README 顶部含代理服务推广内容，属商业信息，需与项目本身区分
- 目录规模大，各组件的质量与维护状态差异明显，星标不等于可用
- 组件更新可能改变已有项目行为，缺少锁文件机制

## 7. 谁该用 / 谁别碰

使用 Claude Code 并希望复用社区组件的开发者与团队。
