## 1. 它解决什么问题

 bundle 型工具在大型项目里，冷启动与热更新会随模块数线性变慢：改一行要等整包重建。开发者要的不是更快的打包器，而是开发期根本不打包，同时生产期仍能输出优化过的静态资源，并且这套能力不能被某一个框架独占。

## 2. 为什么是现在

项目 2,391 天、83,844 星，本期 +160。README 已明确写出构建命令改用 Rolldown 预配置输出高度优化的静态资源，说明它在保持「开发期 dev server + 生产期 build」双层结构的同时，正在把底层打包器换成性能更高的实现。本期前端五席全是十年以上老牌基础设施，Vite 是其中唯一仍在做底层替换的一个。

## 3. 关键能力

- 基于原生 ES 模块的 dev server，提供即时服务启动与极快的 HMR
- 生产构建命令使用 Rolldown，预配置输出高度优化的静态资源
- 通用插件接口与完整类型化 API，便于框架与工具链接入
- 仓库以 monorepo 组织多个 Packages，含贡献指南与赞助信息

## 4. 架构与实现

TypeScript 实现、MIT 许可，核心是两部分：开发期一个对原生 ES 模块做增强的 dev server，生产期一条 bundle 命令。关键取舍是「开发不打包、生产才优化」，并用统一的插件接口把两部分连起来，因此框架无关、生态可插拔。README 列举 Instant Server Start、Lightning Fast HMR、Rich Features、Optimized Build、Universal Plugin Interface、Fully Typed APIs 六项能力，构建侧已迁至 Rolldown，具体配置以官方文档为准。

## 5. 上手路径

1. 用官方脚手架新建一个最小项目，对比冷启动与热更新耗时
2. 阅读插件接口文档，为一个真实需求写一个最小插件，理解 dev 与 build 两阶段的钩子差异
3. 在生产构建里验证 Rolldown 的产物体积与加载表现，再决定是否需要额外配置
4. 升级前查看对应 major 版本的迁移说明，尤其关注打包器替换带来的行为变化

## 6. 风险与边界

- 底层打包器正在向 Rolldown 迁移，依赖特定 Rollup 插件或深度定制配置的项目需回归验证
- 框架无关意味着部分能力要由生态插件补齐，选型时需确认插件维护状态
- 838 个开放议题与高频迭代下，锁版本与升级回归是常态工作
- dev 与 build 行为不完全对称，只在开发期验证过的配置可能在生产构建里暴露问题

## 7. 谁该用 / 谁别碰

需要快速开发反馈与可控生产构建的 Web 团队，以及要基于统一插件接口封装内部工具链的工程团队。
