## 1. 它解决什么问题

传统框架把组件结构与更新逻辑带到浏览器里运行，包体积与运行时开销随功能增长。另一条路是让编译器在构建时把声明式组件翻译成命令式、精确到节点的 DOM 操作，从而减少运行时负担，但代价是编译工具链更复杂、生态需要单独建设。

## 2. 为什么是现在

项目 3,638 天、88,658 星，本期 +152，是本期前端五席里历史最长的一个。它长期坚持「编译器即框架」的路线，在 React 与 Vue 主导的生态里提供了第三种答案；本期与 Vite、Tailwind、Angular、Bun 同框，构成一组「前端基础层」全景，说明榜单当日增量主要回流到被长期依赖的底座，而非新框架。

## 3. 关键能力

- 把声明式组件编译为高效 JavaScript，精确更新 DOM 而不依赖虚拟 DOM 运行时
- 组件、模板与响应式能力由编译期处理，产物更贴近原生 DOM 操作
- 提供官方网站与 Discord 社区作为文档与交流入口
- 由志愿者持续维护，MIT 许可，可通过 Open Collective 支持开发

## 4. 架构与实现

JavaScript 实现、MIT 许可，主体是编译器而非运行时库。README 结构简洁，含 What is Svelte?、Supporting Svelte、Roadmap、Contributing、License 等章节，明确项目「完全由志愿者支持」。核心取舍是把 diff 与更新决策前移到构建期：编译产物直接改 DOM，因此浏览器端不需要携带通用运行时。具体的响应式语法与服务端渲染能力不在 README 摘录范围内，应以官方文档为准。
