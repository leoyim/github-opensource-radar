## 1. 它解决什么问题

一个人做内容要把同一期视频发到六七个平台，各平台文案、封面、发布形式都不同；发完还得分别看播放、涨粉与转化，数据散在各家后台，很难判断哪一期、哪个平台真的带来了收入。

## 2. 为什么是现在

仓库创建仅 6 天已 1,605 星 / 474 fork / 10 个 issue，MIT 许可，是本期最年轻的入选项目。README 用中文把三件事写成一条链路——「发得出去 / 看得清楚 / 算得出钱」，并明确「跑在一台常开的 Mac 上、用你自己登录好的浏览器、不存任何平台密码、国内四家只填写不发布」：把凭据边界和人工最后一步写进第一屏，是这类自动化工具少见的克制。

## 3. 关键能力

- 覆盖 B 站、抖音、小红书、视频号、YouTube、X、Instagram 的分发计划，提前排期、到点发布、自动回填链接
- 每天自动采集各期在各平台的播放、互动与粉丝数据并长期留存，配手机大屏与飞书卡片通知
- 接自有站点后可追踪每期、每平台带来的注册与收入，形成转化漏斗与单期复盘
- 由三部分组成：发布 skill（让 Claude Code / Codex 看片写文案并生成 publish.json）、Chrome 发布助手（各平台适配器）、hub（计划、调度、防重、取链接、采数据）
- 提供 macOS 一行安装与 Windows 社区贡献脚本，含演示模式与安装向导

## 4. 架构与实现

本地工作台三段式：发布 skill 生成结构化的「发布素材.md」与 publish.json，hub 把计划写入分发计划并调度执行，Chrome 插件在专用浏览器里驱动各平台上传页完成填写与定时。关键约束是凭据不入库——复用用户已登录的浏览器会话；国内平台只填不点发布，最后一下留给人。数据采集侧每日抓取各平台指标落本地，再喂给大屏、飞书卡片与转化分析。skill + 插件 + hub 通过 publish.json 解耦，可单独替换任一段。

## 5. 上手路径

1. 先跑 `node src/demo.mjs` 看演示数据的大屏，确认输出形态符合预期
2. 按一行安装装好，用向导接上发布 skill 与专用 Chrome，登录各平台
3. 拿一期内容走完整链路：生成 publish.json → hub plan → hub run → 手动点发布 → 回填链接
4. 接自有站点，核对转化漏斗里的注册与收入归因是否与实际一致

## 6. 风险与边界

- 依赖各平台网页结构，平台改版会导致对应适配器失效，需自行维护
- 要求一台常开的 Mac（Windows 开机自启尚未适配）与专用 Chrome，长期运行有维护成本
- 自动化填写可能触及平台对自动化操作的条款，使用前应核对各平台规定
- 仅 6 天、10 个 issue，多平台覆盖的长期稳定性尚未经过充分验证

## 7. 谁该用 / 谁别碰

一人或小编制、需要同时运营国内外多个内容平台并关心转化归因的创作者；只发单一平台、或不需要数据复盘的人用不上这套调度。
