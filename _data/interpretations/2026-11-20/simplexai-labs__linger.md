## 1. 它解决什么问题

能力接近 Claude 的个人 agent 基本都在云端：按 token 计费、记忆留在服务商、离线不可用。消费级显卡显存装不下百 B 级模型，而把模型整体放内存或 SSD 又会让推理慢到无法交互。本地 agent 因此长期卡在「能跑小模型、跑不动强模型」。

## 2. 为什么是现在

仓库创建仅 10 天、已 1,609 星 / 124 fork / 41 个 issue，属本期最年轻的入选项目之一。README 没有把重点放在模型本身，而是明确写「model–harness co-design」与 PolyStrata MoE 推理引擎：用专家分层放置解决显存瓶颈，再让记忆与主动执行落在同一台机器上。这是把本地 agent 从演示推向可用的一次工程化尝试。

## 3. 关键能力

- 通过 MoE 推理引擎 PolyStrata，把模型最忙的专家留在 GPU、其余放在 RAM 或 SSD，让 125B Qwen3.8-Flash-Next 在 12 GB 显卡 + 64 GB 内存上运行
- 本地推理不调用远端服务，没有云账单与 token 费用，数据留在设备上
- 具备长期记忆、主动发起任务、记住用户关注点等个人 agent 能力
- 面向消费级 Mac 与 PC，定位为可持续运行在本机的「AI 伙伴」而非一次性推理脚本

## 4. 架构与实现

核心是模型与宿主（harness）协同设计：MoE 模型的专家按访问热度分层，热专家常驻显存，冷专家下沉到内存或 SSD，由推理引擎在生成过程中调度换入换出；上层 harness 负责会话、记忆与主动任务，与推理引擎共用同一台机器，避免把上下文送到远端。整体是单进程本地栈，模型权重与用户数据都不离开设备。

## 5. 上手路径

1. 按 README 核对硬件门槛（12 GB 显卡 + 64 GB 内存），确认消费级配置是否满足
2. 先跑一次纯推理基准，观察专家换入换出时的首 token 延迟与持续生成速度
3. 再启用记忆与主动任务，验证长会话下上下文是否被正确保留与检索
4. 对比同一任务在云端 agent 上的质量与本机延迟，判断是否值得用本地算力换隐私与零费用
