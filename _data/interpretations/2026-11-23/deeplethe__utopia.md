## 1. 它解决什么问题

企业做知识工程时通常把知识图谱与向量库当成静态存储：材料进来就切块入库，新事实与旧结论冲突时靠人工发现，决策依据与审计链路分散在多个系统里。知识会随时间变化，但底座本身不带时间语义。

## 2. 为什么是现在

本期 8,693 星，Rust 实现，Apache-2.0，上线约 107 天。它把双时态（bitemporal）、本体与冲突检测放在基础层，而不是当作上层应用的补丁，这与近半年 RAG 从「检索质量」转向「事实治理」的方向一致。

## 3. 关键能力

- 双时态存储：同时记录事实生效时间与入库时间，支持按历史时点回溯查询
- 本体层驱动：冲突检测、推理与决策都在本体约束下运行，而非对文本做相似度匹配
- 被动学习：随材料持续入库自动演进知识结构，不依赖一次性建模
- 离线部署：可装在企业自有硬件上，数据不出内网
- 面向 agent 的决策接口与合规审计链路

## 4. 架构与实现

Rust 单体服务 + PostgreSQL/pgvector 作为存储底座，官方提供 GHCR 镜像。知识以本体为骨架、以双时态记录为叶子，检索走图与向量的混合路径，冲突判定由本体约束而非模型自由判断。

## 5. 上手路径

1. 按仓库 README 的 Quick start 用容器起一套本地实例，确认存储后端与端口
2. 先用少量自有文档灌入，观察本体如何自动扩展以及冲突如何被标记
3. 对照一次历史时点查询，验证双时态是否真的能还原当时的结论
4. 评估阶段不要直接接生产数据源，先用脱敏样本跑一轮完整链路

## 6. 风险与边界

- 「世界模型」是产品叙事，实际能力仍取决于本体设计与灌入材料的质量
- 双时态与本体推理会带来写入与查询成本，数据量大时需实测延迟
- 被动学习的知识演进缺乏人工审核环节时，错误结论可能被固化
- 早期项目，接口与存储 schema 仍可能变动，升级需评估迁移成本

## 7. 谁该用 / 谁别碰

需要把分散材料整理成可审计知识底座、且对数据出网有硬性限制的中大型团队；不适合只想要一个文档问答入口的小项目。
