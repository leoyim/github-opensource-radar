## 1. 它解决什么问题

渗透测试的执行环节高度依赖人：信息收集、漏洞验证、资产关联由不同角色接力，过程记录分散。用 LLM agent 串起这条链路能省人力，但一旦缺少授权与留痕约束，工具本身就变成风险源。

## 2. 为什么是现在

本期 4,504 星、当日新增 133 星，Go + Next.js 单体分发。它在 README 开头即给出误用警告，并把多语言输出做成设置项，说明这类攻防 agent 正从研究原型进入「可交付给团队使用」的阶段。

## 3. 关键能力

- 多个 LLM agent 自主拆解目标、调用真实工具执行、边打边积累资产与漏洞图谱
- 单 Go 二进制内嵌 Next.js 前端，数据统一落 PostgreSQL
- 界面与 agent 生成的报告、摘要、对话支持英/韩/中/西/日切换
- CI 中带检测规则流水线与前端构建流水线
- 面向蓝队与检测工程的可复用产出（检测规则而非仅攻击结果）

## 4. 架构与实现

Go 后端承担编排与工具调用，agent 之间通过共享的资产-漏洞图协同；前端以静态资源嵌入二进制，部署时只需一个进程加一个数据库。上游为 Autumn-27/ARTEX，本仓库是 AGPL-3.0 下的国际化分支。

## 5. 上手路径

1. 只在自建靶场或明确授权的资产上运行，先确认授权范围与时间窗
2. 用容器起 PostgreSQL 与二进制，先跑一次只读侦察类任务
3. 检查 agent 的工具白名单，限制可执行的命令与目标网段
4. 把生成的检测规则单独评审后再进生产检测系统

## 6. 风险与边界

- 自主渗透工具误用成本极高，README 的授权限制不构成技术层面的护栏
- agent 自主调用工具可能触碰未授权资产，必须在外层做网络与权限隔离
- 国际化分支相对上游存在同步滞后，安全修复需关注 upstream
- AGPL-3.0 对通过网络提供服务有源码开放要求，商用前需法务确认

## 7. 谁该用 / 谁别碰

有明确授权范围、具备隔离靶场环境的安全团队与蓝队；不适合个人在公网资产上试用。
