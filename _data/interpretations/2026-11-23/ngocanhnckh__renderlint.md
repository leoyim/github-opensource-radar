## 1. 它解决什么问题

agent 生成的代码类型检查通过、ESLint 也通过，但页面上文字溢出卡片、灰底灰字、图表标签重叠、只在 1024px 断开的布局——这些都不是代码问题，是像素问题，静态检查看不见。

## 2. 为什么是现在

本期 687 星，28 天，JavaScript，MIT，明确以「给 AI 编码 agent 用」定位。它把缺陷报告写成纯文本加注释截图，正好是 agent 能直接消费的格式，而不是给人看的审计报告。

## 3. 关键能力

- 在手机、平板、桌面三档宽度与暗色模式下逐页渲染
- 额外扫描中间宽度，捕捉只在特定断点出现的布局问题
- 用更长文案、更大数值与更长 API 数据复测，暴露溢出与截断
- 检出文字溢出、对比度不足、元素重叠、emoji 当图标等问题
- 每条缺陷附带元素定位、源文件、注释截图与具体修法

## 4. 架构与实现

以真实浏览器渲染页面，按规则集对渲染树与截图做双重判定；输出结构化结果供 CI 失败判定或 agent 消费。框架无关，通过本地开发服务器地址接入。

## 5. 上手路径

1. 先在一条非阻塞的 CI 分支上跑，收集基线而不是立刻卡门禁
2. 从溢出与对比度两条规则开始，逐步增加而不是一次全开
3. 把输出直接喂给编码 agent，让它按截图与定位改，形成闭环
4. 对第三方组件导致的告警做白名单，避免噪声淹没真实问题

## 6. 风险与边界

- 视觉规则天然存在误报，全量门禁会让团队很快关掉它
- 依赖真实浏览器，CI 环境需要额外安装与稳定的启动时间
- 截图与页面数据会进入报告，敏感环境需注意信息外泄
- 项目仅 28 天，规则覆盖面与稳定性仍在快速变化

## 7. 谁该用 / 谁别碰

用 agent 批量产出前端页面、且已经把视觉缺陷当成主要返工来源的团队；纯后端或无 UI 的项目无关。
