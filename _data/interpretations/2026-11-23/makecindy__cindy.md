## 1. 它解决什么问题

agent 通常绑在一台机器上：在台式机开的工作，换到笔记本或手机就接不上；想带着走，只能同步文件或重开会话，上下文与正在跑的任务全部丢失。

## 2. 为什么是现在

本期 10,413 星、123 天，TypeScript，Apache-2.0，当日新增 49 星。它把自己定义为「开箱即用的 agent」，同时接通电脑与手机，属于「agent 客户端化」这条线在本期的代表。

## 3. 关键能力

- 多设备接入同一会话，换设备可继续对话并访问文件
- 自带模型与订阅接入，不强制绑定单一供应商
- Electron 桌面端与 iOS/Android 移动端同源
- 面向个人工作流的常驻 agent，而非一次性问答

## 4. 架构与实现

以 Electron 承载桌面端，移动端复用同一套会话与文件抽象；模型调用走用户自带的 key 或订阅，会话状态在设备间同步。仓库提供 CI 与中英文文档。

## 5. 上手路径

1. 先在一台机器上跑通模型接入，确认 key 与配额可用
2. 开启多设备同步前，明确哪些目录允许 agent 访问
3. 对 agent 的文件写入做版本控制或快照，便于回退
4. 移动端接入时检查网络与鉴权方式，避免长期凭证落到手机上

## 6. 风险与边界

- 跨设备同步意味着一处凭证泄露会影响全部设备
- agent 拥有本地文件访问能力，权限边界需显式收敛
- 多端同源但平台差异仍在，移动端功能可能不完整
- 项目迭代快，会话存储格式变更可能影响旧数据

## 7. 谁该用 / 谁别碰

已经在多台设备间切换工作、希望 agent 跟随而非重开的个人用户与小团队；不适合对终端权限有严格隔离要求的场景。
