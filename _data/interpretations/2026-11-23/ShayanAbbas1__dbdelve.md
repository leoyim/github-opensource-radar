## 1. 它解决什么问题

主流数据库客户端要么基于 Electron、要么跑在 JVM 上，启动慢、内存高；面对百万行结果集时容易卡死或直接加行数上限。日常做数据排查的人，多数时间就耗在这些等待上。

## 2. 为什么是现在

本期 2,036 星、97 天，Rust，GPL-3.0，当日新增 95 星。GPUI 这类原生 UI 框架开始被用来做开发者工具，使「无 Electron、无 JVM」的桌面客户端第一次具备可用的交互完成度。

## 3. 关键能力

- 原生跨平台，启动即用，不需要额外运行时
- 百万行结果集可平滑滚动，不做行数截断
- 多引擎支持，覆盖主流关系型数据库
- 查询编辑器与结果网格并排，支持明暗主题
- 下次启动保留上次结果，免去重复查询

## 4. 架构与实现

以 Rust 直连数据库驱动，UI 用 GPUI 渲染，结果集采用虚拟化视图按需绘制，因此滚动性能不随总行数线性下降。当前安装渠道以 macOS 为主，其他平台按发布页为准。

## 5. 上手路径

1. 先用只读账号连一个测试库，验证驱动与认证方式
2. 拿一张百万行表做滚动与排序测试，确认没有隐性全量加载
3. 把连接配置存在本地加密存储，避免明文写入配置文件
4. 生产库只给只读权限，防止误操作的 UPDATE 落库

## 6. 风险与边界

- 应用未做公证签名，macOS 安装需绕过隔离标记，需自行确认来源可信
- GPL-3.0 对再分发有传染性要求，企业内部二次分发需评估
- 跨平台覆盖仍在推进，Windows 与 Linux 体验可能落后于 macOS
- 早期版本功能对齐商业客户端尚有差距，复杂建模场景需验证

## 7. 谁该用 / 谁别碰

经常在本地做数据排查、对大结果集滚动体验敏感的后端与数据工程师；不适合把客户端直接暴露给生产写权限的场景。
