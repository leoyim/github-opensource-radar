## 1. 它解决什么问题

用云托管数据库省事，但成本随规模上涨、数据落在别人机房；自建 PostgreSQL、MySQL 集群又要自己解决主备、故障切换、备份恢复与 TLS，运维门槛高且容易做错。

## 2. 为什么是现在

本期 130 星、17 天，PHP/Laravel 13 + React 19，Apache-2.0，当日新增 8 星。它把「开源自托管 DBaaS」这条路线从文档级方案变成有控制台的实现，填补了云托管与裸机运维之间的空档。

## 3. 关键能力

- 支持 MySQL 8.4/9.7、MariaDB 多版本、PostgreSQL 15–18、MongoDB 7–9、Valkey 与 Redis 7/8
- 单主、带备节点集群、只读节点与自动故障切换
- 基于时间点的备份恢复与全链路 TLS
- 自有域名下的主机名管理与连接池
- Web 控制台统一管理实例与集群

## 4. 架构与实现

Laravel 承担控制面与编排，React 提供控制台，数据面直接管理各引擎进程与复制关系；备份与故障切换由控制面调度，存储与网络依赖宿主环境。

## 5. 上手路径

1. 先在测试环境用单节点跑通创建、连接、备份与恢复全流程
2. 把故障切换演练列为上线门槛，确认切换后连接串如何更新
3. 为备份单独规划存储与保留期，验证恢复耗时是否可接受
4. 多节点部署前先确定网络与时钟同步，否则复制容易出问题

## 6. 风险与边界

- 控制面自身的高可用未在 README 中充分展开，单点故障需自行设计
- 17 天的新项目，故障切换与备份恢复的边界情况验证有限
- 多引擎支持意味着每个引擎的版本矩阵都要单独测试
- 自托管把合规责任完全转移到自己，备份加密与访问审计需补足

## 7. 谁该用 / 谁别碰

有一定运维能力、希望把数据库托管能力收回自有基础设施的团队；不适合没有 DBA 能力、也不打算演练故障切换的小团队。
