## 1. 它解决什么问题

Claude Code、Codex 这类 agent 跑在开发机上，人却常常不在机器前。任务卡在「需要确认」这一步时，只能回到电脑旁；远程 SSH 能用，但手机上读长输出、敲命令的体验很差。

## 2. 为什么是现在

本期 2,183 星、66 天，TypeScript，MIT，前身是 herdr 的 Web UI。它与 herdr 共用同一套终端视图，说明 agent 的「远程操作面」正在从终端工具里独立出来，成为一层客户端。

## 3. 关键能力

- 手机、平板与浏览器多端接入，与电脑上的 agent 会话同源
- 聊天式交互：直接回复 agent 的提问与确认
- 实时终端视图，可查看 agent 正在执行的命令输出
- 经 SSH 连接远程主机，不必暴露公网端口
- 支持 Web Push 告警，任务需要人时推送到手机

## 4. 架构与实现

服务端跑在 agent 所在机器上，前端为 PWA；终端能力复用 herdr 的会话模型，与 herdr 桌面端可并存。鉴权与网络暴露方式依部署而定，官方提供自托管路径。

## 5. 上手路径

1. 先在开发机上自托管，用局域网验证会话同步与终端回显
2. 外网访问优先走 SSH 隧道或内网穿透，不要直接把端口开到公网
3. 开启推送前确认通知内容不含敏感路径与命令
4. 多人共用一台机器时，核对会话隔离与权限边界

## 6. 风险与边界

- 远程终端等于把机器控制权延伸到手机，设备丢失风险需评估
- 自托管暴露在公网时，鉴权强度直接决定主机安全
- 依赖 herdr 的会话协议，上游变更可能影响兼容性
- 推送通道会将任务状态送到第三方推送服务

## 7. 谁该用 / 谁别碰

长期在自有机器上跑编码 agent、需要离开工位仍能推进任务的人；不适合对终端访问有严格管控的合规环境。
