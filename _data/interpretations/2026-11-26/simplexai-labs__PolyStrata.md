## 1. 它解决什么问题

本地跑大模型的两难是显存与模型规模的错配：动辄数十 GB 的权重装不进消费级显卡，量化到能装下又常牺牲可用性；不同模型对后端的要求差异大，很难用一套栈统一。

## 2. 为什么是现在

1,539 星、上线 50 天、C++、MIT，207 fork、62 issue、日增 44。它的做法是按模型分引擎：Qwen3.8-Flash-Next 沿用原 Strata 引擎（12 GB 以上显存、支持读图），其余十三个跑为 PolyStrata 新写的引擎，单卡或双卡，Windows 除两个最大模型外均支持。官方给出笔记本 8 GB 显卡 106 tok/s、RTX 5090 536 tok/s 的实测，并在本机暴露 OpenAI 与 Anthropic 兼容接口。

## 3. 关键能力

- 十四个模型分两套引擎：按显存与平台能力分配，不强行统一后端
- 小显存可用：9 个较小模型在 8 GB 显卡笔记本上运行，含 3D 生成类用例
- 本机 API：OpenAI 与 Anthropic 兼容接口监听 localhost，Claude Code 等客户端可直连
- 一键安装：Windows 与 Linux 提供安装包，无需自行编译
- 双卡支持：较大模型可跨两张 NVIDIA 卡切分

## 4. 架构与实现

推理核心为自研引擎，权重以 GGUF 量化形式加载，大模型的多数层驻留系统内存、按需换入显存；服务层在本机暴露兼容接口，另有 API Monitor 观察请求。原 Strata 引擎用于承载成熟度最高的那个模型。

## 5. 上手路径

1. 先确认显卡显存与系统内存，按文档的模型—显存对照表挑第一个模型，不要直接从最大模型试
2. 用自带 API Monitor 观察首次加载的换页行为，判断内存是否成为瓶颈
3. 把 Claude Code 指向本机接口跑一个真实小任务，验证工具调用与长上下文表现
4. 需要读图能力时单独验证 Qwen3.8-Flash-Next，两个引擎的行为差异要分开评估

## 6. 风险与边界

- 十三个模型自述为实验状态，长上下文与工具调用的稳定性需逐模型验证
- 大模型文件 79–114 GB 时主要驻留内存，实际体验由内存带宽与容量决定
- 两套引擎意味着两套问题定位路径，排障成本高于单一后端
- 50 天的新仓，量化版本的兼容性与回归测试覆盖仍在建立

## 7. 谁该用 / 谁别碰

只有消费级显卡、希望本地跑编码 agent 的开发者；需要在离线环境使用多模型的内容与工程团队。
