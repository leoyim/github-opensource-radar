## 1. 它解决什么问题

在浏览器里用 agent 的通病是结果散落在对话流中：做完一次调研，结论、对比表与图表都在滚动窗口里，既难复核也难以继续。把 agent 放进侧边栏只是换了位置，没有解决沉淀问题。

## 2. 为什么是现在

1,328 星、上线 163 天、Rust、MPL-2.0，133 fork、129 issue。它的做法是给 agent 一块画布：Helpers 并行工作，结果以对比表、图表、图示与计划的形式留在画布上；一份计划可一键拆成当日任务。浏览器本体对标 Safari 的能效、Brave 的拦截与 Arc 的交互。

## 3. 关键能力

- Work 画布：agent 并行工作，产出以可视化产物沉淀，可回看与继续编辑
- 计划转任务：把画布上的一份计划一键转为当日任务列表
- 浏览器本体：广告拦截、新标签页的信息化呈现、暗色与亮色主题
- 多语言文档：README 提供 11 种语言版本
- 桌面端：macOS 与 Windows

## 4. 架构与实现

基于 Rust + Tauri + Svelte 构建，浏览器内核与界面层分离；agent 侧以 Helpers 并行执行并把结果写回画布数据结构，画布本身是可持久化的文档而非临时视图。

## 5. 上手路径

1. 先当作日常浏览器用一周，确认能效与兼容性是否满足主力使用
2. 再试 Work：给一个需要对比的任务，看产物是否真的比聊天记录更可复核
3. 把重要画布导出或备份，避免早期版本的存储格式变动
4. 需要团队协作时先确认分享与权限能力是否已具备
