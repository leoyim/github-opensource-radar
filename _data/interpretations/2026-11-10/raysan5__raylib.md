# raysan5/raylib · 项目解读

> **一句话**：零外部依赖的纯 C99 游戏编程库，用最朴素的方式把图形、输入、音频与窗口都包进一个库。

## 1. 它解决什么问题

现代游戏引擎把渲染、构建、编辑器与资源管线层层包起来，做原型、写小工具、教图形学或在嵌入式板子上跑一段绘制代码时，这层厚度反而成了负担。需要一个能直接 #include、编译快、依赖可预期的底层库。

## 2. 为什么是现在

创建 4,764 天（约 13 年）的老项目，本期仍 +26，累计 35,618 星、3,381 fork、仅 14 个 open issue。它在本期榜单里与一批 2–15 天的新仓同台，说明「轻量、可读、无依赖」这条路线仍有稳定需求；README 那句「no fancy interface, no visual helpers, no debug button」把定位说得极清楚。

## 3. 关键能力

- 无外部依赖，所需库全部内置在仓库内
- 跨平台：Windows、Linux、macOS、RPI、Android、HTML5 等
- 纯 C99 编写，采用 PascalCase / camelCase 命名约定
- 基于 OpenGL 的硬件加速，覆盖 1.1 / 2.1 / 3.3 / 4.3 与 ES 2.0 / ES 3.0
- 独立的 OpenGL 抽象层 rlgl，可作为单独模块使用
- 无需 OpenGL 的软件渲染后端 rlsw
- 支持 DXT / ETC / ASTC 等压缩纹理格式与 TTF / OTF / FNT / BDF / sprite 字体

## 4. 架构与实现

C99 + Zlib 许可，整体是一个自包含的静态库：图形层由 rlgl 抽象不同 OpenGL 版本，rlsw 提供无 GPU 路径，外部依赖（GLFW、字体、图片解码等）随仓库分发，因此不需要包管理器也能编译。README 的 features 清单几乎全是底层能力条目，没有框架级概念，这与它「编程库而非引擎」的定位一致；灵感来自 Borland BGI 与 XNA，明确面向原型、工具、图形应用、嵌入式与教育。3,381 fork、14 个 open issue，属于接口高度稳定的成熟项目。

## 5. 上手路径

1. 从仓库或官方站获取对应平台的预编译包，或直接用 CMake 构建
2. 跑一遍官方 code examples，确认窗口、输入与绘制循环的基本写法
3. 需要 Web / 嵌入式目标时先确认对应后端（HTML5、RPI）的构建链
4. 若目标环境没有 GPU，改走 rlsw 软件渲染后端验证可行性
5. 把 rlgl 单独作为模块引入既有项目，避免整套图形栈被替换

## 6. 风险与边界

- 刻意不提供编辑器、可视化辅助与调试按钮，团队若依赖这些工具需自行搭建
- 纯 C 接口意味着内存与生命周期管理由使用方负责，上层封装成本不低
- OpenGL 版本跨度大，不同后端的行为差异需要在目标平台上逐一验证
- 13 年老项目的接口非常稳定，但相对现代图形 API（Vulkan / Metal / WebGPU）覆盖面有限
- 内置依赖随仓库分发，安全更新与系统库的版本节奏不同步

## 7. 谁该用 / 谁别碰

图形学教学、原型验证、小型工具与嵌入式图形应用的开发者，以及希望读得懂每一行底层代码、不愿引入引擎的人。要做中大型商业游戏、需要场景编辑器与资源管线的团队，它只是地基不是整套方案。
