## 1. 它解决什么问题

做行业资讯站最费人的不是搭页面，是定「什么值得收、什么算同一件事、凭什么排前面」。多数聚合器只给抓取和去重，精选标准与提示词藏在运营手里，换一个行业就得从零调一遍。

## 2. 为什么是现在

42 天 10,081 星、2,352 fork、仅 1 个 open issue，本期 +291。它是线上 AI 热点站同一份引擎的导出，作者把网站、后台、精选流程、聚簇与热度算法、所有提示词原文和入选门槛全部公开；README 还直说「我不是专业开发者，设计师出身，代码是和 AI 一起重写的」，并把「请不要用 AIHOT 的名字和 Logo」写进约定。这种把编辑判断力也交出来的开源方式比较少见。

## 3. 关键能力

- 多信源采集后，用大模型先筛一遍、再独立打两次分，挑出值得看的条目
- 自动生成中文标题与摘要，把不同来源讲同一件事的条目聚成一个事件
- 按有多少来源在说同一件事排出热点，每天早上产出一份日报
- 公开网站、后台、精选流程、聚簇算法、热度算法与全部提示词原文及入选门槛
- 附 18 个公开海外 AI 资讯源作示范，可直接跑起来看效果
- 提供文档与改成其他行业的指引，把信源与精选标准替换为自己的 KnowHow

## 4. 架构与实现

TypeScript / Node.js 24 + PostgreSQL 17 + Docker Compose，MIT 许可。README 章节按「这是什么 → 为什么开源 → 它是怎么工作的 → 聚簇与热点 → 速度 → 你会得到什么 → 跑起来 → 把它改成你的行业」组织，重点在流程与阈值而非框架抽象。作者明确说明仓库不含线上信源名单与运营数据，也不保证每次线上更新都同步；模型榜、Codex 重置监控等只对 AI 行业有意义的功能做了裁剪说明。2,352 fork 与 1 个 open issue 的组合，说明大量使用发生在 fork 后自行改造。

## 5. 上手路径

1. 按 Docker Compose 把示范站点跑起来，确认 18 个公开信源能出一份日报
2. 先读公开的提示词原文与入选门槛，理解两次独立打分各自在判什么
3. 把信源换成自己行业的 RSS / 站点，同时替换精选标准与 KnowHow
4. 检查聚簇结果，确认「同一件事」的合并粒度符合本行业的语义
5. 按约定改名换 Logo 后再对外使用，不要沿用 AIHOT 的名称与视觉

## 6. 风险与边界

- README 自述并非精心打磨的通用框架，线上更新也不保证逐次同步，二次开发要有心理准备
- 两次大模型打分叠加多信源抓取，调用成本随信源数量线性上升，需要自己设预算
- 示范信源是公开海外 AI 资讯源，换成其他行业后精选阈值几乎必须重调
- 作者说明线上信源名单与运营数据不在仓库内，等于交付的是引擎而不是可直接复用的内容资产
- 作者坦承代码质量参差、Issue 回复可能不及时，长期维护依赖社区 fork

## 7. 谁该用 / 谁别碰

想给某个垂直行业做自己的热点日报 / 简报站、又不想从零设计精选与聚簇逻辑的开发者或小团队；也适合想研究「打分 + 聚簇 + 热度」这套流水线如何落到提示词层面的人。只想接入现成新闻 API、无意定制编辑标准的项目，用不上它的核心部分。
