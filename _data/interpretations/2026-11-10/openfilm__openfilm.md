# openfilm/openfilm · 项目解读

> **一句话**：把影片写成一个 HTML 文件，让编码代理直接产出视频，再用本地编辑器逐帧改回去。

## 1. 它解决什么问题

让代理生成视频通常要引入一套专用框架或 DSL，代理得先学，人想改一个字、一个颜色又得回到提示词里反复重生成。生成结果和人工精修之间缺少一个共同的、双方都懂的中间表示。

## 2. 为什么是现在

37 天 5,528 星、526 fork、35 个 open issue，本期 +170。它的判断是「代理已经最懂网页」，于是把每个镜头定义成用 frame(t) 画任意时刻的网页，视频本体就是一个 film.html，不引入 Remotion / HyperFrames 之类框架；再配一个跑在浏览器里的 Studio 编辑器，让生成与精修落在同一份文件上。

## 3. 关键能力

- 单个 film.html 把动态网页、实拍素材、图片与声音按轨道剪在一起，样式用 CSS 写
- 每个镜头是一个网页，用 frame(t) 绘制任意时刻，可调用 three.js、WebGL、canvas、SVG、CSS、GSAP、video
- Studio 本地编辑器可移动、缩放、旋转页面内元素，改文字、颜色与样式
- 支持放置、裁剪、重设每个片段样式，并在时间轴上修剪与剪切
- 生成结果既能手动改，也能继续让代理接着改，二者作用于同一份文件
- 提供安装、命令、Skills、从源码构建等完整说明

## 4. 架构与实现

TypeScript 实现、MIT 许可。核心是「一个 HTML 文件 + 一个函数 + 一个真编辑器」三层：film.html 作为可交换的影片表示，frame(t) 作为时间轴抽象，Studio 作为浏览器内本地编辑器。因为整个中间层是网页，代理无需学习新的视频 DSL，浏览器生态的绘图能力可直接复用；这也意味着渲染精度与性能受浏览器实现约束。仓库 526 fork、35 个 open issue，37 天内已有稳定的使用反馈。

## 5. 上手路径

1. 按 Install 安装后，在 Codex、Claude Code 或任意编码代理里让它做一支短片
2. 打开 Studio 观察 film.html 逐镜头成形，先改一处文字或颜色验证双向可编辑
3. 读 Skills 与 How it works，理解 frame(t) 的时间轴约定再写自定义镜头
4. 用时间轴做一次裁剪与片段重排，确认手动修改不会被下次生成覆盖
5. 需要定制构建时按 From source 章节自行编译

## 6. 风险与边界

- 以浏览器为渲染后端，复杂三维或高帧率场景的性能与一致性不如专业渲染管线
- 影片即网页的表达很灵活，但缺少传统视频工程的行业标准约束，团队协作需要自己定规范
- 项目 37 天、Skills 与命令仍在演进，提示词写法变化可能影响既有镜头
- 依赖代理对 HTML/CSS/JS 的掌握程度，生成质量波动会直接反映在成片上
- 35 个 open issue 表明编辑器与渲染边界仍在处理中，长期项目需关注版本兼容

## 7. 谁该用 / 谁别碰

已经在用编码代理做内容、想把动效与短视频也纳入同一条工作流的人；以及做产品演示、技术可视化、需要反复微调文案与配色的团队。需要影视级调色、多机位剪辑或专业音频工程的场景，它不是替代品。
