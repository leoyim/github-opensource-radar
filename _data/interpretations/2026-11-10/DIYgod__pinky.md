## 1. 它解决什么问题

手机里有大量没有开放 API 的操作：装应用、扫码、在原生界面里走完一段流程。让代理代劳通常意味着把屏幕和账号全交出去，而「请在付款前问我」这类提示词约束并不能真正阻止越界。另一个现实问题是这类桥接工具常见 Electron 壳、体积大、常驻占资源。

## 2. 为什么是现在

3 天新仓，1,445 星、157 fork、11 个 issue，本期 +603 为全榜日增第一。它把「人留在回路里」做成可验证的机制而非口号：README 明写审批由 Pinky 网关强制执行，不依赖给代理的指令；支付、交易、转账默认等待点击确认，PIN 存本地且代理看不到。这一点正好回应了手机代理最大的信任缺口。

## 3. 关键能力

- 通过 MCP 让 Claude Code、Claude Desktop、Codex、Cursor 或任意脚本操作真实 iPhone / Android
- 网关层强制审批：支付、交易、转账等待用户点击；发送、下单、删除、通话、安装、跳出应用的链接与设置变更也可设为需确认
- 锁屏也能用：PIN 只存一次，之后每次解锁用 Touch ID、Windows Hello 或系统密钥环密码确认，代理读不到 PIN
- 桌面端覆盖 macOS（Apple silicon / Intel）、Windows、Linux；驱动 Android 10–17 与 iOS 17.4 以上设备
- 原生轻量实现：MyGo 在 GPU 上绘窗口，无 Electron 无 webview，安装包 16–22 MB，空闲约 70 MB 内存、Mac 上 0% CPU
- 设置里可查看使用统计、崩溃报告与反馈选项，支持本机与远程 iPhone、自建源码构建

## 4. 架构与实现

Go 实现、Apache-2.0 许可，桌面应用用 MyGo 直接绘制界面，手机侧通过 MCP 暴露操作能力；iOS 27 以上无需安装 helper，iOS 17.4–26 需从 Xcode 装一次辅助组件（README 注明在 27 与模拟器上验证过，未在更低版本真机验证）。审批逻辑放在网关而不是提示词层，是这个项目最关键的架构取舍：代理发出的敏感动作在网关被挂起等待用户确认。仓库 157 fork、11 个 open issue，3 天内已有真实反馈。

## 5. 上手路径

1. 按 Get started 下载对应平台安装包并授予权限（Windows 安装无需管理员）
2. 用 USB 连接手机，按引导完成 iOS helper 或 Android 授权
3. 在 Settings › Agents 里一键接入 Claude Code、Codex、Cursor，或填任意 MCP 兼容地址
4. 在 Settings › Safety 把支付、删除、安装等动作设为需确认，先跑一个只读任务
5. 从会话里观察代理执行过程，确认 Take over（接管）与操作回看符合预期后再放开权限

## 6. 风险与边界

- 项目仅 3 天、iOS 低版本真机路径尚未验证，不同系统版本的兼容性需要自行确认
- 把真实手机（含账号、支付能力）交给代理，风险面远大于普通桌面工具，审批项应逐条配置
- 需要 USB 或同网连接，异地设备的可用性依赖 README 里的 Phones away from home 方案
- 涉及设备解锁 PIN 与账号凭据，虽不上传也需评估本地存储与系统密钥环的安全边界
- 自动化操作第三方 App 可能触及对方服务条款，使用前需自行判断适用性

## 7. 谁该用 / 谁别碰

需要让代理完成真机端到端验证、原生流程回归或移动端自动化的开发者，以及重视「审批由系统强制执行」这一安全模型的人。只想远程看屏幕、或完全不涉及敏感操作的场景，用它偏重。
