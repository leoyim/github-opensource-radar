## 1. 它解决什么问题

单轮对话式 agent 无法承载持续协作：多个角色之间的消息传递、群聊、长期记忆与任务分工都要靠外部编排补齐，宿主本身不提供；如果每次任务都从零开会话，所谓的「团队」只是一次性的角色扮演。

## 2. 为什么是现在

8,792 星、上线 47 天、JavaScript、Apache-2.0，fork 891、issue 353。它把「主 bot + bot 间消息 + 群聊」做进 DSH 宿主，而非在应用层拼装；同时提供独立桌面应用与 DSH 插件两种形态，桌面版自带运行时，降低了首次使用门槛。

## 3. 关键能力

- 多个长期存活的 bot，各自保留会话状态，可被反复唤起
- 主 bot 与子 bot 的分工结构，任务可下派并回收结果
- bot 之间可直接发消息，支持群聊式多方协作
- 桌面应用内嵌 DSH 运行时，无需先安装宿主
- 可从既有的 DSH 团队导入配置，便于迁移

## 4. 架构与实现

基于 DeepSeek Harness 的插件/宿主双形态；桌面版内嵌 DSH 运行时，bot 之间以消息总线通信，会话状态持久化在本地；模型配置集中在 Settings，可替换为自有端点。

## 5. 上手路径

1. 先用桌面安装包起最小团队（一个主 bot 加一个执行 bot），确认消息路由能跑通
2. 改 Settings 里的模型配置，验证整套系统不依赖默认服务商
3. 做一次会话恢复测试，确认「长期存活」是真实持久化而非内存缓存
4. 最后才接入真实项目目录，并给 bot 划定可写的路径边界

## 6. 风险与边界

- README 中段是第三方 API 聚合平台的推广段落，与功能本身无关，评估时应跳过
- 353 个 issue 说明多 bot 编排的边界情况仍多，消息循环与职责重叠是常见故障
- bot 间消息会产生额外 token 消耗，成本随 bot 数量非线性上升
- 本地持久化的会话与凭据需自行管理权限，多人共用一台机器时尤其要注意

## 7. 谁该用 / 谁别碰

已经在用 DeepSeek Harness、想让多个 agent 长期并行协作的进阶用户；不适合只需要单轮问答或轻量脚本的场景。
