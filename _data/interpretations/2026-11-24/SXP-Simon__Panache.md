## 1. 它解决什么问题

需要「手写感」的场景——教案、作业模板、笔记美化——通常靠字体硬套，结果行距与墨迹浓淡对不上真实书写，纸张纹理更是缺失；公式与电路图属于排版盲区，几乎无法用同一套流程处理。而这类需求往往还要能批量导出整份文档。

## 2. 为什么是现在

376 星、上线 54 天、Dart/Flutter + Rust、AGPL-3.0，日增 262 居本期首位。它的关键设计是把「纸张模板」或「自己拍的一张文具照片」作为排版坐标系，从而绕开纸张规格库，把真实拍摄条件（透视、光照）纳入流程；桌面端还内置本地 MCP，让 AI 客户端直接驱动版面生成。

## 3. 关键能力

- 导入 TXT、DOCX、PDF、RTF 或直接粘贴文本
- 手写字体选择、墨迹浓淡调整、笔迹可拖动并对齐纸张横线
- 以纸张模板或自拍照片为底，支持透视校正后的对齐
- 公式、表格与电路图渲染
- 单页 PNG、整篇 PDF 或图片 ZIP 三种导出
- 桌面端内置 stdio MCP 服务器，可被支持该协议的 AI 客户端调用

## 4. 架构与实现

Flutter 桌面/移动端 + Rust 核心处理排版与渲染；桌面包内含 MCP 服务（crates/panache-mcp），另有可自托管的 Web 版；离线安装包覆盖 Windows x64、Apple Silicon、Linux x64 与 Android，iOS 需自行编译。

## 5. 上手路径

1. 用桌面版导入一页含公式的 DOCX，先确认公式渲染与分页正确
2. 拍一张自己的信纸做模板，检查透视校正与横线对齐是否到位
3. 把 MCP 配置粘进支持 stdio 的客户端，让模型读一次版面测量值再改
4. 最后批量导出 PDF，核对字体嵌入与页面尺寸

## 6. 风险与边界

- 手写效果依赖字体与模板质量，手机拍摄的畸变会直接影响对齐精度
- AGPL-3.0 对分发与服务化有约束，闭源分发前需评估
- iOS 端需源码编译，跨端体验不一致，团队协作时要注意版本差异
- 所谓手写本质仍是字体渲染，笔迹的随机性与真实书写仍有差距

## 7. 谁该用 / 谁别碰

教师、学生与需要纸质感文档的内容创作者；也适合想把「版面生成」接进 agent 流程的团队。
