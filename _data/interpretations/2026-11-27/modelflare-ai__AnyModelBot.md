## 1. 它解决什么问题

多 agent 落地的实际阻力有两类：一是每个机器人要单独配模型与密钥，切换成本高；二是「能操作电脑」这件事一旦放开权限就难以约束，用户不敢真让它动文件。

## 2. 为什么是现在

31 天、5,002 星、121 fork、20 watcher、2 issue，Python、MIT，仓库约 152 MB。它的做法是把机器人当成有独立人设、模型、工作区与记忆的实体，并把权限做成只读 / 工作区 / 完全三档，越界写入前先询问；模型既可走 Modelflare 按用量计费，也可用官方 Key 直连。

## 3. 关键能力

- 多机器人并行：每个机器人独立人设、默认模型、工作区与头像，可同时运行多个
- 三档权限：只读 / 工作区（默认，越界写入需确认）/ 完全权限（不进沙箱，删除目录仍会询问）
- 跨渠道触达：应用内聊天，同时接入微信、飞书、Telegram、Slack、Discord
- 本地优先：对话、记忆、文件与 API Key 留在设备，模型调用按需转发
- 模型选择器：70 多个模型统一列出，附上下文长度、能力标记与参考价

## 4. 架构与实现

Python 桌面应用，仓库含 .claude 配置、Docker 相关文件、AGENTS.md 与七语种 CHANGELOG（单文件 45–66 KB），说明迭代密度高且面向多语言用户；执行层在沙箱内运行命令，工作区外写入由确认环节拦截；模型侧通过 Modelflare 网关或用户自带凭据分流。

## 5. 上手路径

1. 首次启动按向导登录并让应用绑定本机，确认授权回跳后不残留可复制的长期 Key
2. 先用一个机器人跑只读任务，验证它对工作区边界的判断是否符合预期
3. 需要执行命令时切到「工作区」档，用一个可回滚的目录做破坏性操作测试
4. 如果在意日志留存，先在设置里核对转发与保留策略，再决定是否改用官方 Key 直连

## 6. 风险与边界

- 模型请求经 Modelflare 转发并保留日志，本地优先并不覆盖调用内容
- 121 fork（2.4%）低于同量级，桌面端多平台打包与系统权限适配依赖单一团队
- 「完全权限」档不进沙箱，误操作的破坏半径大，需自行控制使用场景
- 跨渠道接入意味着凭据分散在多个平台，撤销与轮换成本上升

## 7. 谁该用 / 谁别碰

需要在个人电脑上同时跑多个 agent、并希望统一凭据与权限边界的开发者；对「数据尽量留在本机」有明确要求的用户。
