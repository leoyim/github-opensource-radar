## 1. 它解决什么问题

异构数据库环境里，团队往往要在多个客户端之间切换：一种库一个工具，元数据、权限与导出格式各不相同，排障时还要另开 SSH 隧道。

## 2. 为什么是现在

已维护 4,055 天、52,544 星、4,473 fork、日增 +9，Java、Apache-2.0。开箱支持 350 多个驱动，任何有 JDBC 或 ODBC 驱动的库基本都能接；AI 对话被放进同一个工作台，而不是另起产品。

## 3. 关键能力

- 350+ 数据库驱动，JDBC / ODBC 兜底几乎覆盖所有库
- schema 编辑、SQL 编辑、数据编辑与执行计划
- ER 图、空间数据查看、导入导出与迁移
- AI 对话直接作用于数据、SQL 与库结构
- SSH 隧道与自定义驱动编辑器
- 每日构建，桌面多平台

## 4. 架构与实现

基于 Eclipse 插件的 Java 桌面应用，驱动以插件形式挂载，因此新增数据库类型不需要改主程序；SSH 隧道与代理作为连接层能力统一提供，AI 能力经插件接入。

## 5. 上手路径

1. 先建一个只读连接，确认驱动版本与目标库兼容
2. 用执行计划定位慢查询，再决定是否改索引
3. 需要跨库迁移时先用小表验证类型映射
4. JDBC 驱动自行管理时，注意把驱动 jar 与客户端升级解耦

## 6. 风险与边界

- JVM 桌面端启动与内存开销明显，低配机器体验一般
- 驱动数量多意味着版本组合复杂，个别库仍需手工调驱动
- AI 功能会把库结构信息发往模型侧，敏感环境需评估
- 插件体系庞杂，企业内分发时需统一版本

## 7. 谁该用 / 谁别碰

需要同时对接多种数据库的开发与运维人员；做数据排查与迁移的 DBA。
