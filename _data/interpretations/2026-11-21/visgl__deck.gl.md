## 1. 它解决什么问题

数据量大到数十万点时，常规图表库会卡在渲染与交互上；地理可视化还要处理投影、底图与拾取，自己从 WebGL 写起成本极高。

## 2. 为什么是现在

14,788 星、2,307 fork、近十一年维护，当日 +11。它不属于「新项目」，而是本期里少见的长期基础设施，说明可视化底座仍在被持续使用。

## 3. 关键能力

- 图层化渲染（图标、多边形、文本等），数据集到图层的声明式映射
- 拾取、高亮与筛选等交互能力
- 制图投影与主流底图集成
- 可组合、可扩展的图层目录
- JavaScript 与 Python 两种用法，支持 WebGL2 / WebGPU

## 4. 架构与实现

数据到图层的声明式映射，视图负责相机与投影；渲染循环与交互在 GPU 侧完成，图层可扩展以承载自定义着色器；Python 绑定复用同一套图层语义。

## 5. 上手路径

1. 用官方示例跑一个散点图层，确认底图与投影配置
2. 把数据量加到十万级，观察帧率与拾取延迟
3. 需要定制时再写自定义图层，而不是一开始就改内核

## 6. 风险与边界

- 学习曲线陡于常规图表库
- 版本升级偶有破坏性变更
- 大数据量下的内存占用需提前评估

## 7. 谁该用 / 谁别碰
