## 1. 它解决什么问题

从「有想法和实验记录」到「可投稿稿件」之间，提纲、文献综述、章节写作、图表与格式排版是五段割裂的手工活。研究者常在格式与综述上消耗大量时间，且各环节的中间产物难以复用，返工时往往要整篇重来。

## 2. 为什么是现在

本期 5,470 星、686 fork、50 个 open issue，当日新增 454 星位列 AI 方向前列。作者来自 Google Cloud AI Research，README 直接给出 CVPR 2025 模板参数，说明目标已从「生成文本」转向「产出符合会议规范的稿件」。

## 3. 关键能力

- 多智能体管线：提纲、文献综述、章节写作、内容打磨、绘图各自独立，可分别调试
- 文献自动检索、排序并整合进稿件，形成综述章节
- 生成图表，并支持插入概念示意图
- 按目标会议模板输出可投稿的 LaTeX
- 提供 Conda 环境与 .env 密钥配置，以参数指定原始材料目录与模板目录

## 4. 架构与实现

以「角色分工 + 共享稿件状态」组织：每个 agent 读取前序产物、写入自己负责的部分，LaTeX 模板作为最终渲染约束。外部依赖是 Conda 环境（Python 3.11）与模型 API 密钥，原始材料与模板目录通过 CLI 参数注入，便于替换不同会议模板。

## 5. 上手路径

1. 按 README 建 Conda 环境，并在 .env 中填入模型 API 密钥
2. 准备一份包含想法与实验日志的原始材料目录
3. 用 --latex template dir 指向目标会议模板，跑通最小样例
4. 对照生成稿与人工稿，重点核查文献引用是否真实存在

## 6. 风险与边界

- 文献幻觉是首要风险，引用必须逐条回溯原文
- 学术署名、数据与图表来源的合规责任仍在作者
- 自动生成的表述可能触发会议的 AI 使用披露要求

## 7. 谁该用 / 谁别碰

需要快速产出初稿、且有能力核验文献与结论的研究者；把论文完全交给它而不做校验的用法并不适合。
