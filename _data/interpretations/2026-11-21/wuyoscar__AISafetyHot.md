## 1. 它解决什么问题

AI 安全的信息散落在 arXiv、博客、社交平台与厂商公告里，越狱、提示注入、对齐与评测各有各的圈子。做安全评估的人每天要在信源之间跳转，且很难追溯一条事件与哪些论文相关。

## 2. 为什么是现在

本期 2,082 星、36 fork，51 天新仓，无 issue。README 强调「网站 + 日报 + RSS + MCP」四种出口，说明定位不是又一个资讯站，而是可被程序消费的情报层。

## 3. 关键能力

- 按日汇总越狱、提示注入、Agent 安全、防御与护栏、对齐、评测等方向
- 网页提供中英文阅读，并以可交互的科研星图串联事件与论文
- 提供日报归档与 RSS 订阅
- 公开 MCP 接口：热点排行、事件脉络、当日新论文，免 API Key

## 4. 架构与实现

采集层按信源抓取论文与新闻，归一为「事件—论文—方向」三层结构；展示层是网站与星图，分发层是 RSS、日报与 MCP server。MCP 把查询能力暴露给 agent，使情报可直接进入工作流。

## 5. 上手路径

1. 先用 RSS 订阅一周，判断信源覆盖是否符合自己的方向
2. 把 MCP 挂进常用 agent，问一次「最近 72 小时的提示注入事件」验证召回
3. 对关键条目回溯原始论文或公告，确认摘要未失真

## 6. 风险与边界

- 作为二手聚合，摘要与归类可能失真，结论应回溯原文
- 无 issue 通道意味着纠错反馈路径有限
- 涉及治理与政策的条目属公共议题，引用时需保持语境完整

## 7. 谁该用 / 谁别碰

做模型安全评估、红队或对齐研究、需要稳定信息基线的工程与研究团队。
