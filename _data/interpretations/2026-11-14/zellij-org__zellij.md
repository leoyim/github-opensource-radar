## 1. 它解决什么问题

传统终端复用器功能强但默认体验简陋，配置要写很长的 dotfiles；新手上手门槛高，老手又不想为简单需求牺牲分屏、布局与键位控制。缺的是「装好就能用、想深挖也有得挖」的中间形态。

## 2. 为什么是现在

2,265 天、36,045 星，本期 +32。它与 rtk、gh 同列工具方向，代表本期工具类的一条主线：单二进制 Rust/Go 命令行组件、不引入运行时依赖、把复杂度留给可选配置而非默认项。

## 3. 关键能力

- 面向开发者与运维的终端工作区/复用器，强调开箱即用的默认体验
- 支持自定义配置与布局（Layouts），可保存并复用开发环境
- 同时保留高级能力供需要深挖的用户使用，README 明确「不为强大牺牲简单」
- 仓库提供安装、配置、路线图、FAQ 与屏播教程等完整入口
- Rust 实现，MIT 许可，可用 cargo xtask run / test 从源码构建与测试

## 4. 架构与实现

Rust 编写的终端复用器，以单一进程管理 pane、标签与布局，配置与布局以声明式文件描述；插件与键位扩展为可选层，默认配置即可完成日常分屏与会话管理，源码构建通过 cargo xtask 统一入口。

## 5. 上手路径

1. 按 How do I install it 安装后直接启动，先不写任何配置体验默认键位与分屏
2. 用自带布局跑一个开发环境，确认会话断开重连后状态可恢复
3. 需要定制时再读 Configuration 与 Layouts，逐项加自己的键位
4. 从源码构建用 cargo xtask run，改动前先跑 cargo xtask test 建立基线

## 6. 风险与边界

- 1,965 个 open issue 体量较大，键位与插件兼容性问题需按自己终端环境验证
- 与 tmux/screen 的键位肌肉记忆冲突，团队切换有适应成本
- 布局与配置文件格式随版本演进，跨版本共享 dotfiles 需回归
- SSH、嵌套会话与不同终端模拟器的渲染行为可能不一致
- 默认体验友好但高级配置面仍宽，按需启用即可，不必一次配完

## 7. 谁该用 / 谁别碰

希望在终端里获得稳定分屏与可复用开发环境、又不愿维护庞大 tmux 配置的开发者与运维。
