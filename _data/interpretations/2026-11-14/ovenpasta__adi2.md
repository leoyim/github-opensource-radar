## 1. 它解决什么问题

Ada 常用于高可靠系统，但桌面 UI 生态长期匮乏：写界面要么下沉到 C 绑定，要么自己拼绘图与事件循环，样式、国际化、动效与资源打包都得从零做，难以做出符合当下预期的界面。

## 2. 为什么是现在

82 天、仅 61 星，是本期星标最低的项目，却贡献了前端方向最完整的一份能力清单。它说明榜单不只看体量：本期数据方向多项也是几十星的小工程，评分更看重素材的技术密度与方向覆盖。

## 3. 关键能力

- CSS 选择器、伪类、部件、过渡、渐变与盒阴影写在普通 .css 里，保存即热重载；同一套规则也可用 Ada 聚合手写
- XML 布局可编译成带类型的 Ada 包，或用句柄式构造器在 Ada 里建同一棵控件树，两者汇到同一个 API
- HTML 视图渲染文档式标记并级联样式，位图走 SDL3 image、SVG 走内置 plutosvg、Lottie 走内置 rlottie
- CSS、字体、图片、翻译与 SVG sprite 全部打进可执行文件，程序可从任意目录运行
- Gettext 兼容的国际化（上下文、复数形式、区域检测、.po 编译为 Ada）、Tab/Shift+Tab 焦点与剪贴板、dp/rem/px 等 HiDPI 单位

## 4. 架构与实现

以 SDL3 为渲染与输入底座，Ada 实现控件树与样式引擎；布局同时提供 XML→Ada 编译路径与纯 Ada 构造路径，二者收敛到统一的句柄 API；资源在构建期嵌入二进制，样式在运行期可热重载，形成「编译期打包 + 运行期调样式」的分工。

## 5. 上手路径

1. 按 Quick start 构建库，先跑测试套件确认 SDL3 依赖与本机工具链可用
2. 编译并运行一个示例程序，改 .css 观察热重载行为
3. 对比 XML 布局与 Ada 手写两条路径，选一条与团队习惯一致的
4. 把字体、图片与翻译资源打包验证单文件分发，再评估目标平台覆盖

## 6. 风险与边界

- 仅 61 星、4 fork、3 issue，社区极小，遇到问题基本要靠自己读源码
- Ada + SDL3 工具链门槛高，构建与跨平台分发成本明显高于主流 GUI 框架
- 能力清单覆盖很广（CSS/i18n/Lottie/HiDPI），各项成熟度未必一致
- Apache-2.0 许可清晰，但内置第三方库（plutosvg、rlottie 等）的许可需单独核对
- 82 天新项目，API 仍可能调整，生产使用需锁定版本
