## 1. 它解决什么问题

网盘分享、在线视频与磁力链接各有一套客户端或网页流程，多线程下载、断点续传、多账号凭据管理与浏览器下载接管很难在一个地方统一；跨设备时凭据与配置还要重新导。

## 2. 为什么是现在

70 天、5,744 星，本期 +457，是移动端日增最高项、也是全榜日增第二。它代表本期跨端方向的一条路径：不依赖浏览器内核，用 Kotlin 桌面端 + Manifest V3 扩展把下载能力延伸到浏览场景。

## 3. 关键能力

- 覆盖夸克/UC/迅雷/百度/139/123/115/蓝奏云等网盘，以及 B 站、抖音、微博、小红书、快手、AcFun、Pixiv 等视频平台
- 支持磁力 / BT 种子 / ed2k 等 P2P 链接，Range 分片并发 + 断点续传，B 站高清自动合轨
- 浏览器扩展（Manifest V3）可嗅探页面资源、接管浏览器下载并支持「归还下载」与 5 分钟冷却
- 多账号管理，登录凭证加密存本机并可导出加密备份换机恢复
- 提供免安装便携版与安装版两种分发形式，Kotlin 桌面端与安卓版功能有明确差异说明

## 4. 架构与实现

Kotlin 实现的 Windows 桌面客户端承担解析、任务调度与分片下载，凭据以加密形式保存在本机；browser-extension/ 目录内的 Chrome/Edge Manifest V3 扩展负责页面资源嗅探与下载接管，通过本地协议把任务交回桌面端；文档、FAQ 与构建说明随仓库提供。

## 5. 上手路径

1. 按 README 选择便携版或安装版，先在无需登录的公开链接上验证下载与断点续传
2. 安装浏览器扩展后测试嗅探与接管，确认「归还下载」和冷却逻辑符合预期
3. 多账号凭据只在需要时添加，并导出一份加密备份核对可恢复性
4. 从源码构建前先看技术栈与常见问题章节

## 6. 风险与边界

- 解析第三方网盘与视频平台依赖其接口或页面结构，对方调整后功能可能随时失效
- 使用前须确认对相应内容拥有访问与下载权限，并遵守平台服务条款与版权要求
- 接管浏览器下载会取消浏览器原生下载并抹掉记录，误配置可能影响正常下载流程
- 最高 512 线程需二次确认，过高并发可能触发平台限流或影响本机网络
- AGPL-3.0 对衍生分发有较强要求，二次开发前需评估

## 7. 谁该用 / 谁别碰

有合规下载需求、希望统一管理多网盘与浏览器下载任务的 Windows 用户。
