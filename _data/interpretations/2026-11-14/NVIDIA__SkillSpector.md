## 1. 它解决什么问题

Claude Code、Codex CLI、Gemini CLI 等使用的 agent 技能以近乎默认信任的方式执行，安装前通常没有静态检查。技能包里的一段提示、一个脚本或一个依赖，就足以形成提示注入、数据外泄或供应链风险，而这类内容用普通代码扫描器很难判定。

## 2. 为什么是现在

本期 +190、25,943 星，README 引述研究数据：31,132 个技能的抽样中 26.1% 含漏洞、5.2% 显示疑似恶意意图。当技能市场与官方插件目录同时扩张时，「安装前审查」从可选项变成了流水线里的一环，这也是它与本期 plugin 目录、技能配置类项目共同构成的治理侧。

## 3. 关键能力

- 覆盖 17 个类别、71 种漏洞模式，包括提示注入、数据外泄、权限提升、供应链、过度代理等
- 支持 Git 仓库、URL、zip、目录与单个文件多种输入格式，便于接入下载与分发流程
- 提供分析报告与「何时扫描、怎么读报告、如何卡住安装」的托管指南，可直接做安装门禁
- 分析资源设有失败即关闭的上限（bundle、解析器、嵌套产物、账本与 finding 上限），避免被构造样本拖死
- 提供 Pi 与 OpenCode 扩展，可在 agent 会话内直接扫描技能；Docker 方式无需本机 Python 环境

## 4. 架构与实现

以 Python 编写的静态分析器管线为主，输入侧统一收纳仓库 / 压缩包 / 单文件，中间按类别化的模式库与启发式规则产出 finding，输出侧是可被人审阅的报告并留有失败即关闭的资源边界；扩展层把同一套分析能力挂进 Pi、OpenCode 等 agent 会话，安全披露走 NVIDIA PSIRT 私有通道。

## 5. 上手路径

1. 按 Quick Start 用 uv tool 或 venv 安装，也可直接 docker build，先对一个已知安全的本地技能跑一次建立基线
2. 把待装的第三方技能目录或 zip 作为输入扫描，逐条读 finding 的类别与证据位置，不要只看总分
3. 把扫描接进技能安装前的门禁，配合 README 的托管指南定义「哪些类别必须阻断」
4. 高频使用者再装 Pi / OpenCode 扩展，让 agent 在会话里自行触发扫描

## 6. 风险与边界

- 静态模式匹配会有误报与漏报，扫描通过不等于技能可信，报告只应作为准入的一票而非全票
- 26.1% / 5.2% 是研究数据集的抽样结论，不能直接外推到任意技能生态
- 规则库随攻击手法演进，需跟踪更新；旧版本对新型提示注入可能无感
- 扫描器自身要处理不可信压缩包与嵌套产物，建议在隔离环境运行
- 它给出的是风险信号而非修复方案，处置仍需人工判断
