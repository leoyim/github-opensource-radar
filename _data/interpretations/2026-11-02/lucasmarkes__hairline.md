## 1. 它解决什么问题

给页面加一点「活的」装饰，通常要在三件事上妥协：用 GIF/视频则体积大、不可换色、不响应主题；用 Lottie 要引入运行时与 JSON 资产；自己写 canvas 又得处理高分屏、离屏暂停与 SSR 水合。hairline 的选择是纯 SVG 线稿 + 极薄运行时：33 个等距视角的线条人物，跟随指针做出反应，零依赖、只发 ESM，React 只是可选 peer（仅 /react 子入口需要）。

## 2. 为什么是现在

31 天、3,245 星，本轮 +64。它代表一类正在成型的需求：AI 生成页面越来越快，但生成结果普遍缺少「人味」，于是小而精的视觉装饰件变成刚需。它的工程细节也正好回应了这类组件的常见抱怨——无障碍（图形带可替换的描述，Riffle 做成可聚焦组）、prefers-reduced-motion（自动播放的图在降级时静止）、每页共用一个 requestAnimationFrame 循环且离屏或静止时不做工、SSR 时先渲染 5:4 空盒避免布局跳动、支持 Shadow DOM 内自样式。

## 3. 关键能力

- 33 个等距线稿人物，响应指针位置与强度
- 零依赖、仅 ESM；React 18+ 为可选 peer，只被 /react 子入口使用
- 无障碍：图形视为带描述文本的图片，描述可用 label 替换；Riffle 是可聚焦分组
- 尊重 prefers-reduced-motion：自动播放的图静止，手动播放的图在降级时停住
- 性能：全页共用一个 RAF 循环，离屏或静止的图不做工且循环自动停止
- SSR 安全：服务端渲染为 5:4 比例空盒，绘制时无布局位移
- Shadow DOM 内挂载时自行注入样式
- 官网提供全部图形的实时预览、参数检查器（可直接生成代码片段）与 CDN 用法

## 4. 架构与实现

每个图形是一个由线段组成的 SVG 场景，运行时只维护一组与指针相关的参数（角度、强度、呼吸相位），按帧写入 transform，避免重排。全局调度器把同页所有图形注册进同一个 RAF 循环，并用可见性与静止状态做短路，因此页面挂十个图形也不会线性增加开销。样式通过 CSS 变量注入，主题切换时无需重建 DOM；Shadow DOM 场景下把变量与规则一并注入 root，解决样式穿透问题。

## 5. 上手路径

1. 先看官网的实时预览挑图形，别在代码里逐个试
2. 用检查器调好强度与参数，直接复制它生成的代码片段
3. React 项目只装 /react 子入口，其余场景用核心包，避免多带一层封装
4. 一个页面别超过三四个图形：虽然共享 RAF，但视觉上会打架
5. 主题色用 CSS 变量覆盖，不要改源码里的颜色值

## 6. 风险与边界

- 纯装饰性组件对可访问性是净负担，若图形不承载信息应考虑 aria-hidden 而非加描述
- 33 个图形的视觉风格强绑定等距线稿，与已有设计系统未必协调
- 31 天的新库，图形数量与 API 都可能变动，锁版本使用
- ESM only 意味着老构建链（CJS 环境）需要额外配置
