## 1. 它解决什么问题

把 AI 编码从「复制粘贴到聊天窗口」搬到「直接在仓库里动手」，中间隔着一整套工程问题：怎么读代码库、怎么安全执行命令、怎么处理 git 工作流、怎么在 IDE 与终端之间共享上下文。Claude Code 的答案是把 agent 做成终端里的一个进程：它能读整个仓库、执行常规任务、解释复杂代码、处理 git 操作，全部通过自然语言驱动，同时可以嵌进 IDE 或通过 @claude 在 GitHub 上被调用。

## 3. 关键能力

- 终端内运行，理解整个代码库上下文
- 执行常规开发任务：改代码、跑命令、解释复杂逻辑
- 处理 git 工作流（状态、差异、提交）
- 可嵌入 IDE 使用，也支持在 GitHub 上 @claude 触发
- 通过自然语言命令驱动，无需记忆子命令语法

## 4. 架构与实现

客户端是一个本地 CLI 进程，负责采集上下文（文件树、相关文件内容、git 状态）、维护会话、执行工具调用（读写文件、跑 shell 命令），模型推理在服务端完成。工具调用是它的核心：能力边界由「允许 agent 调用哪些工具」定义，因此权限模型（哪些命令可自动执行、哪些需确认）成为实际使用中最关键的配置项。会话与上下文管理决定了长任务能否持续，也是这类工具与「一次性问答」的根本区别。

## 5. 上手路径

1. 先在只读场景用（解释代码、查调用链），建立对它的行为预期后再放开写权限
2. 把危险命令（rm、force push、生产库操作）列进拒绝清单，不要依赖模型自觉
3. 项目根写 CLAUDE.md 说明构建、测试与代码规范，减少每轮重复解释
4. 长任务分小步提交，让每次改动可回滚——agent 的错误往往是一连串小偏差累积
5. git 操作前先确认当前分支与工作区状态，agent 不总是理解你的未提交改动

## 6. 风险与边界

- 拥有执行 shell 命令的能力，权限配置不当可能造成不可逆破坏
- 代码内容会上传到服务端推理，私有仓库需确认数据使用条款
- 生成代码的正确性无人担保，测试覆盖是唯一的防线
- 长会话容易上下文漂移，早期约定会被逐渐忽略
- 订阅制与用量限制会打断长任务，成本需提前估算
