## 1. 它解决什么问题

传统做法每换一个系统镜像就要重新格式化 U 盘、重新写入，多个镜像无法共存；不同固件（Legacy BIOS、各类 UEFI、MBR/GPT）与不同发行版的引导方式又各有差异，现场装机经常要准备一堆盘。

## 2. 为什么是现在

本期 80,947 星、5,077 fork、当日 +139，年龄 2,444 天；README 依旧以「1300+ ISO 已测试、distrowatch 上 90%+ 发行版支持」的兼容性清单为主体，说明它的长期价值来自覆盖面而非功能迭代，是典型的成熟基础设施。

## 3. 关键能力

- 把 ISO / WIM / IMG / VHD(x) / EFI 文件直接拷进 U 盘即可启动，无需反复格式化，可一次放多个镜像并给出启动菜单
- 支持浏览本地磁盘上的镜像文件并直接启动
- 同一方式支持 x86 Legacy BIOS、IA32 UEFI、x86_64 UEFI、ARM64 UEFI 与 MIPS64EL UEFI，MBR 与 GPT 分区表皆可
- 覆盖 Windows / WinPE / 各类 Linux 与 Unix / ChromeOS / VMware / Xen 等，官方称已测 1300+ ISO、支持 distrowatch 90%+ 发行版
- C 实现、GPL-3.0，配套官网与已验证镜像清单

## 4. 架构与实现

安装时把引导程序与分区布局一次性写入 U 盘，之后 U 盘保持一个可直接读写的数据分区；启动时引导层枚举分区内的镜像文件生成菜单，并按镜像类型选择对应的引导路径。因为镜像只是普通文件，增删系统与更新版本都退化为文件操作，不必重新制作启动盘。

## 5. 上手路径

1. 从官网或 Releases 获取 Ventoy，按目标平台把引导写入一块可清空的 U 盘
2. 拷入两三个不同系统的 ISO，重启后在菜单里逐个验证能否进入安装环境
3. 在 Legacy BIOS 与 UEFI、MBR 与 GPT 组合上各测一次，确认目标机器的固件被覆盖
4. 查阅已验证 ISO 清单，遇到不兼容的发行版先按官方建议的方式处理

## 6. 风险与边界
