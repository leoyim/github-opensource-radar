## 1. 它解决什么问题

现有手机 agent 多依赖 API 集成或云端账号，一旦目标应用没有开放接口就无从下手；把屏幕内容与操作交给云端，又带来隐私与延迟问题。

## 2. 为什么是现在

本期 6,148 星、291 fork，61 天新仓；README 把「无需 root、无需自定义 ROM，一个 APK 加一个 Mac 应用」作为核心差异，并用商业站点提供预配置模型与语音 key 的一键构建，降低了上手门槛。

## 3. 关键能力

- 通过无障碍服务与悬浮层操作任意应用，不依赖目标应用提供 API
- 记忆与密码保存在本机，不上传云端
- 同一账号下的多台设备实例可互相通信
- 提供按用途划分的权限说明，逐项解释拒绝后的后果
- 支持从源码构建并接入自有模型与语音服务

## 4. 架构与实现

Android 端以 APK 承载运行时，借助无障碍与悬浮窗获取界面信息并执行操作；macOS 端为独立应用；模型与语音可走云端后端，也可切到端上自有 key。默认构建通道由第三方商业服务提供。

## 5. 上手路径

1. 先在备用设备上安装，逐项授予无障碍与悬浮权限，观察一次简单任务
2. 在设置里切换端上模式并填入自有模型 key，确认不依赖默认商业后端
3. 用一次可回滚的任务（如打开某应用并返回）验证操作链路

## 6. 风险与边界

- 默认路径依赖第三方商业构建服务，其条款、计费与数据处理独立于本项目
- 无障碍权限等于可读取屏幕并模拟操作，权限面极大，务必在自有设备上使用
- 许可证为 Apache-2.0 附加条件，商用前需逐条确认
- 61 天新项目，跨版本行为与兼容性仍在快速变化

## 7. 谁该用 / 谁别碰

愿意在自有设备上做自动化实验、且在意数据不出端的用户；企业环境或涉及他人设备的场景不适合。
