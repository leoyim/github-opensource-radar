## 1. 它解决什么问题

终端 agent 的能力越来越强，但可观测性没跟上：跑到哪一步、上下文剩多少、刚才那次思考用了多久，用户只能靠滚屏猜。想加界面又怕改核心、留补丁。

## 2. 为什么是现在

本期 7,808 星、372 fork、159 个 open issue，96 天；README 强调「零核心改动，只消费公开导出」，并正在从挂载插件转为带独立入口的应用，说明外围扩展正在成为 agent 生态的一层。

## 3. 关键能力

- 像素鲸鱼开屏、实时工作状态与流式思考展示
- 双击 Esc 回溯时间，上下文进度条与 TPS 表
- 待办侧栏与分栏 diff 卡片，窄终端下自动折叠
- 安装即启用、卸载不留补丁，只依赖宿主公开导出
- 支持图片引用与粘贴的统一准入策略

## 4. 架构与实现

以 npm 包分发，通过宿主公开的扩展点挂载界面层；渲染基于终端 UI 库，状态从宿主事件流读取，不修改宿主源码。

## 5. 上手路径

1. 用 npm 全局安装后启动，先确认原有工作流未被改变
2. 触发一次长任务，观察状态面板与上下文进度是否与实际一致
3. 再验证卸载后宿主是否完全恢复原样

## 6. 风险与边界

- 依赖宿主公开导出的稳定性，宿主升级可能破坏兼容
- 159 个 open issue 说明演进快，边界情况仍需打磨
- 终端渲染在窄窗口与低色深环境下体验下降
- 仍在从插件转向独立应用，安装方式可能变化

## 7. 谁该用 / 谁别碰

高频使用终端编码 agent、希望看清运行状态的开发者；偶尔使用或偏好极简界面的用户收益有限。
