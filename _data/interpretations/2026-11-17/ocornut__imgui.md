## 1. 它解决什么问题

传统保留模式 UI 需要维护一棵控件树，界面状态与业务状态两处同步，改一处容易漏一处；工具类与调试类界面本不需要那么重的状态管理。

## 2. 为什么是现在

本期 77,138 星、12,114 fork，4,501 天；十二年量级后仍在更新并被大量引擎与图形工具采用，说明即时模式在工具与编辑器场景里没有被替代。

## 3. 关键能力

- 每帧重建界面的即时模式，UI 状态由数据直接推导
- 最小化状态同步与 UI 侧状态存储
- 无冗余依赖，可直接嵌入现有渲染管线
- 适合调试面板、编辑器与游戏内工具等高频变动界面
- 跨平台后端适配成熟，接入成本低

## 4. 架构与实现

库只负责生成绘制命令列表，渲染由宿主后端完成；每帧调用即构建界面，交互状态由库内部按 ID 维护，业务状态仍归调用方。

## 5. 上手路径

1. 接入官方示例后端，先跑通一个带滑块的窗口
2. 把界面拆成若干函数，验证每帧重建时状态仍能保持
3. 再接入自有渲染后端，确认绘制命令能被正确消费

## 6. 风险与边界

- 即时模式不适合复杂表单与大量持久 UI 状态，需自行设计缓存
- 每帧重建带来 CPU 开销，界面复杂时要关注性能
- ID 冲突会导致控件状态错乱，需理解 ID 生成规则
- 默认视觉风格朴素，产品化通常需要额外主题工作

## 7. 谁该用 / 谁别碰

做工具、编辑器、调试面板与游戏内界面的 C++ 开发者；面向终端用户的复杂业务界面仍适合保留模式框架。
