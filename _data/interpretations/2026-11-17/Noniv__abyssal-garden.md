## 1. 它解决什么问题

浏览器里的 3D 体验通常要背一个引擎、一堆模型与贴图，首屏动辄数 MB；想做一个「打开就能逛」的场景，成本高得不成比例。

## 2. 为什么是现在

本期 1,728 星、261 fork，创建仅 4 天；README 明确写出「没有图片、没有 3D 模型、没有音频文件，整个世界装在一个约 96 KB 的 HTML 里」，并用 WebGPU 直接绘制，代表了「零素材、纯程序化」这条路线在浏览器端的成熟。

## 3. 关键能力

- 海带森林、光柱、沉船、石鲸尾、蝠鲼、气泡等场景元素全部由代码与数学生成
- 直接使用 WebGPU 绘制，不依赖游戏引擎或 3D 库
- 音景由 Web Audio 实时合成，无音频文件
- 三档画质与自动降级，加载失败时自动退一档重试
- 支持键鼠与触摸操作，移动端自动切横屏与低画质

## 4. 架构与实现

单个 HTML 文件内联全部逻辑与着色器；海床在 GPU 上实时塑形，植被与岩石按程序化规则布置；源码在 source 目录，用 Node 与构建脚本产出压缩后的单文件。

## 5. 上手路径

1. 下载 index.html，用桌面版 Chrome 或 Edge 打开，等待场景构建完成
2. 按 H 查看性能统计，再在菜单里切换画质档位观察帧率变化
3. 进入 source 目录执行 npm install 与 npm run build，验证可改可重建

## 6. 风险与边界

- 强依赖 WebGPU，旧浏览器与部分移动端会直接提示不支持
- 程序化场景的观感依赖调参，二次修改需要一定的图形学基础
- 单文件形态便于分发，但不利于多人协作与增量加载
- 高性能表现基于较强显卡，低端设备帧率下降明显

## 7. 谁该用 / 谁别碰

想学习 WebGPU 实战、或需要一个零依赖演示场景的前端与图形开发者；需要可编辑资产与美术工作流的商业项目不适合。
