## 1. 它解决什么问题

用 Claude Code、Cursor、Codex 这类工具生成落地页，产物往往一眼就能看出是机器做的：每个标题上方挂一个小眉标、字距拉开的全大写标签、标题里只把一个词染色、首屏一堆空框或整屏照片、页尾必有邮件订阅、表单点完只弹一句谢谢但什么都没发出去。这些不是审美偏好问题，而是一组可枚举的坏习惯。hallmark 把这组坏习惯变成检查项：先给一条硬底线，再从 50 套主题里发三套，围绕「访客来这个页面要做什么」来搭结构，最后在真实浏览器里对成品逐条 lint。

## 2. 为什么是现在

今日 +2,830 星，为本期 AI 类第一、全榜第二高日增。时间点值得注意：过去半年讨论集中在「Agent 能不能写出能跑的页面」，现在开始有人把标准前移到「写出来的东西像不像人做的」。这与 i-have-adhd（约束输出格式）、archify（约束可视化产出）同日上榜构成同一信号——Agent 生态的竞争点正从能力转向产出质量的可验证约束。

## 3. 关键能力

- 硬底线 + 三主题发散：从 50 套材料主题库里发三套，避免单一样板导致的全站同质化
- 以访客意图组织页面：先确定这个页面要让人完成什么，再排布信息层级
- 真实浏览器 lint：在浏览器里检测前述「机器味」特征，而不是靠模型自评
- Fresh-context reviewer 终审：交给一个不带生成上下文的审查者做最后判定，规避自证
- 覆盖 Claude Code、Codex、Cursor、OpenCode 四类宿主（README 首段明示）

## 4. 架构与实现

README 显示它是一个 skill 而非应用：没有服务端、没有构建产物，运行方式是宿主 Agent 读取这份规范后按其流程产出页面，再由内置的浏览器检查环节回读 DOM 做规则校验。具体规则清单与判定阈值 README 未逐条列出，需要读仓库内的 skill 定义文件。

## 5. 上手路径

1. 先把仓库作为 skill 装进你常用的宿主（Claude Code / Cursor / Codex 之一），确认 Agent 能引用到这份规范
2. 拿一个你已有的、被评价为「一眼 AI」的页面做对照实验：让 Agent 按规范重做，再看 lint 是否真的拦住了问题
3. 团队内使用时把 lint 规则抄进自己的 code review 清单——规则本身比这个 skill 更耐用

## 6. 风险与边界

- 50 套主题是有限集合，长期只用它会形成新的同质化，只是从「AI 味」换成「hallmark 味」
- lint 针对的是可枚举的表层特征，对信息架构层面的空洞无能为力
- 绑定了具体宿主的 skill 机制，宿主改接口就要跟着改

## 7. 谁该用 / 谁别碰

已经在用编码 Agent 批量产出落地页、且有人能判断「像不像人做的」的团队；纯后端、纯 CLI、纯库类项目完全不适用。
