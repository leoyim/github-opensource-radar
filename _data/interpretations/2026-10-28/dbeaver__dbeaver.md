## 1. 它解决什么问题

现实中的团队往往同时存在 PostgreSQL、MySQL、ClickHouse、达梦、Oracle 等若干数据库，每家都有官方客户端，装齐之后是十几个互不兼容的工具。DBeaver 用「JDBC/ODBC 驱动 + 统一 UI」把这个矩阵收敛成一个应用，任何有驱动的库基本都能连。

## 2. 为什么是现在

今日 +15 星（4,025 天老项目）。它近期值得注意的变化是 README 里明确写入 AI 能力：AI chat 与「用 AI 处理数据、SQL 与库结构」。这是老牌工具面对「自然语言查库」这一波的跟进方式——不重做产品，而是在既有工作流里加一个入口。热度本身不构成信号。

## 3. 关键能力

- 开箱支持 100 多个数据库驱动，任意 JDBC/ODBC 库可扩展
- Schema 编辑器、SQL 编辑器、数据编辑器三件套
- ER 图、数据导入导出与迁移、SQL 执行计划分析
- 数据库管理工具与仪表盘、空间数据查看器
- 代理与 SSH 隧道，适合跳板机环境
- 内置 AI chat，辅助处理数据、SQL 与库结构

## 4. 架构与实现

基于 Eclipse RCP 的 Java 桌面应用，驱动以插件形式加载，因此「支持一个新库」等于加一个驱动配置而非改代码。这种架构带来极强的覆盖面，代价是 JVM 桌面应用的启动时间与内存占用。社区版与商业版（Lite/Enterprise）并存，部分能力需付费。

## 5. 上手路径

1. 先用社区版接通你最常用的两个库，确认驱动与 SSH 隧道能满足内网访问
2. 把常用查询存成 script 并配置连接级参数，避免每次重设
3. 涉及生产库时默认开启只读连接或事务回滚模式，防止误提交

## 6. 风险与边界

- JVM 桌面端启动慢、内存占用高，低配机器体验一般
- 部分高级能力（如某些数据库的深度支持）在商业版
- 多库连接意味着凭证集中在一个客户端，需注意本机安全

## 7. 谁该用 / 谁别碰

需要同时面对多种数据库的开发者、DBA 与数据分析师；只用一个库且只用 CLI 的人无需它。
