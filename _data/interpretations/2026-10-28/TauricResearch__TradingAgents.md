## 1. 它解决什么问题

把 LLM 用于交易的最大障碍不是模型不够聪明，而是回测能轻易作弊：模型可能读到运行日之后才披露的财报，回测可能用当天的收盘价去结算当天开盘前做的决策，跨长假期时又算不清该用哪根 K 线。这类前视偏差会让回测曲线漂亮得毫无意义。TradingAgents 用多智能体分工（分析师、经理等角色）搭投研流程，同时把上述口径问题当成一等公民来修。

## 2. 为什么是现在

今日 +1,735 星，AI 类第二。v0.7.1 的更新日志几乎全是口径修正：决策只按最终收盘价结算、跨长假期也能清算、修掉「模型日期读取了运行日之后的文件」、回测从决策后的第一个收盘价起算。在满天「LLM 炒股」项目的环境里，愿意把 release note 写成审计整改清单的项目并不多，这是它区别于同类的地方。

## 3. 关键能力

- 多智能体分工：分析师、管理者等角色分权，而非单模型一把梭
- 按模型档位分派 provider：不同角色可跑在不同模型上，控制成本与能力配比
- point-in-time 纪律：回测只看到分析日之前已披露的数据（v0.5.x 起持续加固）
- 结算口径明确：决策按最终收盘价结算，节假日跨期可清算
- 自有 ChatGPT Plus / Pro 额度即可运行（v0.7.0）
- 报告输出为单页 HTML，每次运行的设置都记录在报告内

## 4. 架构与实现

README 与 release note 勾勒出的结构是：分析师层并行取数与研判 → 管理者层汇总成决策 → 组合与价格模块落账 → 回测层按 point-in-time 规则结算。v0.6.0 引入「每个模型档位一个 provider」，说明调度层已把模型选择抽象成配置而非硬编码；v0.5.2 起 CLI 支持 --ticker / --date 无提示运行，便于编排。

## 5. 上手路径

1. 先用 --ticker / --date 跑一次单票单日的无提示流程，确认数据源与模型都能通
2. 把回测区间设成跨越一次长假，专门验证结算口径是否按 release note 说的那样工作
3. 在接实盘之前，先用它跑一段历史的「决策 vs 事后实际」对照，看清它在什么行情下会系统性犯错

## 6. 风险与边界

- 框架再严谨，模型输出的投资判断本身不具备可验证的可靠性，历史表现不代表未来
- 数据源依赖第三方（如 Yahoo），源端不稳时结论会静默偏移
- 多智能体 + 多 provider 的组合空间大，配置错误很难在结果里看出来

## 7. 谁该用 / 谁别碰

研究多智能体协作、或需要一套「口径正确」的 LLM 投研回测脚手架的研究者；不适合把它当信号源直接下单的人。
