## 1. 它解决什么问题

传统视频生产把创意锁在 GUI 时间线里：改一个数据就要重剪一遍，做一百个变体就要剪一百遍。Remotion 的做法是把视频定义成 React 组件——帧号就是 props，动画就是插值函数，于是「批量」「参数化」「版本管理」这些软件工程能力直接可用。

## 2. 为什么是现在

今日 +387 星。它已不是新项目（2317 天），持续上榜说明需求稳定而非爆发。值得看的是它最近把三条路径并列摆出来：agentically（让编码 Agent 生成）、interactively（拖拽编辑）、programmatically（纯代码），并强调「任何时候都能切换工作流」。这是对「AI 会不会取代代码化视频」这个问题的直接回答：不取代，而是多一个入口。

## 3. 关键能力

- React 即时间轴：组件树决定画面，props 决定内容，天然可参数化
- 三条工作流互通：Agent 生成 / 拖拽编辑 / 纯代码，中途可切换
- 设计系统化：把动画资产沉淀成组织级库，供多个项目复用
- 批量渲染：在自有基础设施上规模化出片，不依赖云服务配额
- 可发布为应用：从一个简单工具到完整视频编辑器都能承载

## 4. 架构与实现

核心是「帧 = 纯函数」的渲染模型：给定帧号与 props 求值出画面，因此可以在无头浏览器里逐帧渲染再由编码器合成，也可以用 <Player> 在网页里实时预览。批量渲染层把任务分发到多进程/多机，这是它能承诺「百万级视频」的基础。

## 5. 上手路径

1. 用官方模板起一个最小 Composition，先跑通「渲染出一个 3 秒 MP4」的闭环
2. 把可变部分（文案、数据、图片）抽成 props，验证一次改参批量出十个变体
3. 需要编辑器时再接 @remotion/player，不要在纯渲染场景引入交互复杂度

## 6. 风险与边界

- 渲染依赖无头浏览器与 ffmpeg，CI 环境的字体与编解码差异会导致成片不一致
- 许可证为 NOASSERTION（公司规模不同适用条款不同），商用前必须确认授权范围
- 复杂时间轴逻辑会迅速膨胀成难维护的组件树

## 7. 谁该用 / 谁别碰

React 技术栈、需要参数化或批量出片的团队；做一次性短片用常规剪辑工具更快。
