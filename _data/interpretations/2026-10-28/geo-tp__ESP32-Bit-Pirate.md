## 1. 它解决什么问题

硬件调试的常态是「要验证一个传感器，先找对应的转接板与上位机」。I2C 要一套、SPI 要一套、UART 又要一套，临时排查一次就得配一堆工具。ESP32 Bit Pirate 把这件事收敛到一块板子：开源固件 + 浏览器里的 CLI，数字协议与射频协议都能碰。它的灵感直接来自经典的 Bus Pirate。

## 2. 为什么是现在

今日 +16 星（479 天）。热度不高，但它是「硬件黑客工具开源化」这条线的典型样本：Flipper Zero 之后，ESP32 因为便宜、无线能力全、生态成熟，成为自制多协议工具的首选平台。项目把官方站点做成能力总览，说明它已过「实验阶段」进入可交付状态。

## 3. 关键能力

- 数字协议：I2C、UART、1-Wire、SPI 等的嗅探、发送、脚本化交互
- 射频协议：蓝牙、Wi-Fi、Sub-GHz、LoRa、RFID
- 两种交互界面：串口终端，或浏览器里的 Web-based CLI
- 开源固件，可自行修改协议实现
- 面向开发与分析双用途（不只是嗅探，也能主动发送）

## 4. 架构与实现

ESP32 固件层实现各协议的时序与收发（利用其双核与无线外设），上层提供统一的命令接口；Web CLI 通过浏览器与设备通信，把命令解释放在前端，因此换界面不需要改固件。定位是「多协议适配层 + 统一命令面」，而非某个协议的专用分析仪。

## 5. 上手路径

1. 先按官方站点刷固件，用串口终端确认基础命令可用，再接 Web CLI
2. 从一个你熟悉的低速协议（如 I2C 读传感器 ID）开始验证，建立对时序精度的预期
3. 涉及射频时先确认当地法规允许的频段与功率，Sub-GHz 尤其敏感

## 6. 风险与边界

- ESP32 的时序精度不足以替代专业逻辑分析仪，高速信号会漏采
- 射频功能受各地无线电法规约束，违规发射有法律风险
- 多协议意味着每个协议都只做到「够用」，深度分析仍需专用工具

## 7. 谁该用 / 谁别碰

做硬件原型、协议逆向或教学实验的开发者与爱好者；需要高精度时序分析的生产测试场景不适用。
