## 1. 它解决什么问题

架构图与流程图的实际困境不是画不出来，而是画完就过期：代码一改，图就假；用手工工具维护，成本高到没人愿意做。archify 换了个入口——不让你画，让你描述，由 Agent 生成一份可交互的 HTML：节点可点、层级可展开、可以改也可以分享。对「要给别人讲明白一个系统」这个高频场景，它把产出从静态截图变成可操作页面。

## 2. 为什么是现在

今日 +659 星，AI 类第五。它与 hallmark、i-have-adhd 同日上榜，共同指向一个趋势：Agent skill 正在细化到「单个具体工种」。archify 切的是「表达」这一环，而这个环节此前一直由人肉 PPT 承担。需要提醒的是，它的 README 首屏赞助位密度很高（多家 API 中转服务），这是商业化较早的信号，也可能是注意力被分散的信号。

## 3. 关键能力

- 多输入形态：一句想法、一份方案、一整个代码库都可作为起点
- 输出可交互 HTML：不只是静态图，支持探索、定制与分享链接
- 配场景指南与在线画廊：按「讲什么」选模板，而不是按「画什么」选图形
- 多语言 README（简中 / 日 / 韩），面向非英语用户的意图明显
- 可作为 skill 装入主流编码 Agent（Claude Code、Codex 等）

## 4. 架构与实现

README 未公开内部实现，从产品形态看是「Agent 读输入 → 生成带交互逻辑的自包含 HTML → 在画廊/站点分发」的链路，渲染不依赖服务端。真正决定质量的是它内置的场景模板与提示词约束，而不是某个渲染库。

## 5. 上手路径

1. 先拿一个自己的项目，让 Agent 生成一张架构图，重点看它有没有编造不存在的模块
2. 把产出的 HTML 放进仓库跟随代码更新，验证「图可维护」这个核心承诺是否成立
3. 团队使用时固定一套图例与配色，否则每人生成的图风格不一，反而增加理解成本

## 6. 风险与边界

- Agent 生成的结构图可能包含不存在的模块或错误调用关系，必须人工核对
- 自动生成的交互层会增加页面复杂度，分享给非技术读者时可能反而更难懂
- 依赖宿主 Agent 能力，模型换代可能显著改变产出质量

## 7. 谁该用 / 谁别碰

经常要讲架构、讲流程、讲数据流向，又不愿意花时间手工维护图的人；对图形精度有硬要求的正式交付件仍需专业工具。
