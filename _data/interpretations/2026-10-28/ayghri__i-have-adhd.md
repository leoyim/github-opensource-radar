## 1. 它解决什么问题

编码 Agent 的输出有一个共同的坏习惯：先复述你的问题，再解释思路，再列注意事项，最后才给出那句你真正想要的东西。对人来说这是礼貌，对效率来说是灾难——你需要的是「改哪个文件、改哪一行」，而不是一篇前言。这个 skill 的做法很直接：动作先行、步骤编号、禁止客套。

## 2. 为什么是现在

今日 +195 星。它本身只是一段提示词规范，技术上毫无复杂度，但 59k 星说明痛点极真。与 hallmark（约束设计产出）、archify（约束可视化产出）同日上榜，共同构成一个判断：Agent 生态正在细分出「输出形态治理」这一层——不再是让模型更会做事，而是让它的产出更符合人的消费方式。

## 3. 关键能力

- 动作先行：先给结论或要做的事，再给解释
- 步骤编号：多步操作必须编号，便于逐条执行与核对
- 禁止填充语：明确排除「希望这有帮助」这类客套
- 多语言 README：中、英、西、葡、日、越、韩、波斯、泰、阿、法
- 可按 skill 或插件两种形态安装，兼容主流宿主

## 4. 架构与实现

没有任何运行时：它是一份行为规范（skill 定义 + AGENTS.md 指引），由宿主 Agent 在生成时读取并遵守。因此它的效果完全取决于宿主对 skill 的遵从度，也意味着换宿主或换模型后表现会变。这类项目的「架构」就是提示词的措辞本身。

## 5. 上手路径

1. 按仓库 AGENTS.md 的说明安装为 skill 或插件，确认宿主能读到它
2. 装完后立刻用同一个问题做前后对比，看输出长度与首段内容是否真的变了
3. 团队使用时把「动作先行、步骤编号」抄进自己的 AGENTS.md，比依赖外部 skill 更可控

## 6. 风险与边界

- 纯提示词约束，模型换代或上下文变长后遵从度会下降
- 过度压缩输出在需要推理过程的场景（如疑难 bug 排查）反而有害
- 59k 星与它的技术含量严重不匹配，说明热度反映的是情绪而非工程价值

## 7. 谁该用 / 谁别碰

每天被 Agent 长篇前言消耗耐心的开发者；需要完整推理链的场景（教学、审计）不适合。
