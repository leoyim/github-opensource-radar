## 1. 它解决什么问题

插件生态一旦上了规模，问题就从「怎么装插件」变成「插件之间、插件与运行时之间怎么不互相干扰」：环境身份、默认路径、依赖工件、皮肤资源、多实例共存都需要明确契约，否则每次升级都像重装机。

## 2. 为什么是现在

89 天 3,328 星、88 fork、20 issue，日增 +75，是本期跨端方向里架构文档最完整的一项。它所在的 DSH 生态此前已有多期项目上榜，本期首次把重点从「Agent 能力」移到「发行包与环境的装配治理」。

## 3. 关键能力

- 随包准备 Node.js、npm 与 dsh 运行资源并启动本地 Web UI，普通使用无需另装 Node；另有自带 Node 24 的 EAC-Launcher 管理多实例 / 多内核
- 在工作目录发起任务、查看会话的文件变更并通过文件视图检查与还原修改
- 长任务通过请求路径上的上下文压缩与有界溢出恢复管理上下文空间
- 插件目录、安装与启停入口聚合，配保护中心的快照、体检与回滚；皮肤通过市场包接入
- DPX 管理环境身份、默认数据路径与运行时变量并按发布通道隔离；UI 资源由锁文件固定工件并在装配时校验 SHA-256

## 4. 架构与实现

四层分工：Tauri 桌面壳（L1 原生能力）定位资源并启动 sidecar → DPX 建立或复用环境并应用运行时变量 → L2 服务层准备 profile 与配套插件、启动 dsh → 主窗口进入 Web UI，由 Harness 承担会话与工具执行。扩展分发以插件目录、同步清单与依赖工件共同组成的发行包为准，资源缺失在装配阶段暴露。MIT 许可。

## 5. 上手路径

1. 下载 Windows 稳定版或 EAC-Launcher，直接启动，先确认随包运行时无需额外安装
2. 选一个工作目录发起小任务，用文件视图查看变更并试一次还原
3. 按需安装插件与皮肤，安装前后各做一次保护中心快照
4. 需要多实例 / 多内核时再启用 Launcher，并核对各通道的数据目录是否隔离

## 6. 风险与边界

- Windows 是当前主平台，README 给出的其余平台支持有限，跨端预期需收敛
- 插件与皮肤来自生态，启用状态、兼容范围与附加依赖由具体发行包决定，需逐个审阅
- 随包运行时与多实例管理器会推高磁盘与进程占用，低配机器需评估
- 模型调用由用户配置的提供商完成，API 密钥与数据流向自行负责
- 89 天、20 个 issue，架构文档比实现验证更完整，升级与回滚流程建议先在小任务上演练

## 7. 谁该用 / 谁别碰

深度使用 DeepSeek Harness / DSH 插件生态、需要多实例隔离与可回滚桌面环境的人。只是想找一个通用 AI 聊天客户端的用户，用不上这套装配复杂度。
