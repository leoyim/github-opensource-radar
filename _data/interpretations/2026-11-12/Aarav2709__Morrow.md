## 1. 它解决什么问题

云端笔记把数据、协同与编辑器绑成一件事：想长期保存、想用自己顺手的编辑器、想断网工作，都要看服务方的脸色。而纯文本笔记又缺少数据库、画布与关系图这些组织能力。缺的是「文件归文件、界面归界面」的分层。

## 2. 为什么是现在

29 天 288 星、14 fork，热度不高但定位与本期其他本地优先项目形成一条清晰脉络。它把「不上传」写进架构而不是设置项：没有服务端，也就没有遥测与账号体系可关。

## 3. 关键能力

- 每页都是本地文件夹中的普通 Markdown，可用任意编辑器打开，也可交给 Syncthing、iCloud、Dropbox 或 git 同步，外部改动即时反映
- 数据库、画布、关系图、加密、Wiki 链接、callouts、标签、属性与公式全部内置，且沿用常见语法以便迁移
- 程序只重写在 Morrow 中改动过的文件，减少同步冲突与无谓的 diff
- 侧栏页面树支持图标、拖拽与收藏，写作界面强调排版与功能克制
- 无账号、无订阅、无遥测、无广告，断网可用；AI 不是内建功能，需要时由使用者自行接入

## 4. 架构与实现

TypeScript / React 桌面应用直接读写用户指定的本地 Markdown 目录，没有服务端与云端数据库，同步交给外部工具完成；README 专门说明「数据存在哪里」以及从 Obsidian / Notion 迁来的差异。Apache-2.0 许可。

## 5. 上手路径

1. 安装后选择一个本地文件夹作为工作区，建议先放在能被 git 或同步工具覆盖的位置
2. 用页面树建几页并试一次 Wiki 链接与数据库视图，确认生成的文件格式符合预期
3. 配置自己喜欢同步方式（Syncthing / git 等），并约定多设备冲突的处理规则
4. 按需启用加密与画布，之后定期把整个目录做一次独立备份

## 6. 风险与边界

- 29 天新仓、仅 1 个 issue，README 的功能清单远长于可验证的成熟度，关键能力建议实测
- 同步交给外部工具意味着冲突合并、版本历史与多端一致性由使用者自己负责
- 没有服务端就没有原生多人实时协作，团队场景需另找方案
- Wiki 链接、callouts、属性等「兼容」属自述，跨工具迁移时格式细节可能不一致
- 本地加密一旦丢失密钥，文件仍在你手里但内容无法恢复

## 7. 谁该用 / 谁别碰

希望笔记完全落回本地文件、已经习惯 Markdown + git / Syncthing 的个人用户；也适合对云服务的长期可用性有顾虑的人。需要多人实时协作或官方移动端覆盖的团队不适用。
