## 1. 它解决什么问题

技术文章里的示意图常年两难：抽象画漂亮但说不清机制，架构图准确却又劝退读者。让模型直接画一张「解释缓存」的图，往往得到几个带箭头的方框；缺的是一种把抽象机制映射成可观察物理过程、并且图上数字与机制同源的生成方法。

## 2. 为什么是现在

35 天做到 26,763 星与 2,251 fork，是本期体量最大的项目之一。它以 agent skill 的形式分发——一套指令加少量脚本，安装成本几乎为零，容易被不同编码 agent 直接复用；本期 AI 类里唯有它不碰模型能力，而是定义输出的表达方式。

## 3. 关键能力

- 概念到物理隐喻的自动映射：缓存键变成只有全部弹子对齐才转动的锁，单 GPU 上下文服务多画布变成打印头依次访问 16 个井位的龙门绘图仪
- 用数十个小而实心、带一致阴影的部件拼装装置，输出等距视角 SVG，并放进带标题、提示与实时读数的框卡
- 指针与键盘驱动的平缓动效，可选 WebGL shader 与 3D 效果；所有显示数字来自驱动部件运动的同一份小模型
- 生成后放大到每个关节逐处自查，配 capture 脚本做无头浏览器截图复核
- 既可按「要解释什么 + 真实数字」下指令，也可直接指定物体形态

## 4. 架构与实现

以 agent skill 形式提供，主体是给 Claude / Codex 的指令与生成约定，产物为自包含 SVG / HTML 页面，不依赖运行时服务。校验环节调用 node scripts/capture.mjs 生成截图；在 Codex 中需使用 on-request 审批策略或为该命令放行一次，也可自行在普通终端运行校验脚本。MIT 许可。

## 5. 上手路径

1. 把 skill 安装到所用的编码 agent，按 README 配好截图校验所需的无头浏览器
2. 描述要解释的机制并给出真实数值（尺寸、个数、速率、阈值），不要直接描述画面长相
3. 让 agent 生成 figure 并执行逐关节自查，用 capture 脚本出图确认连接处没有错位
4. 把 SVG 或页面导出，用于文章、讲义或文档

## 6. 风险与边界

- 输出质量高度依赖模型的空间推理与自检循环，部件多的机械仍可能出现关节错位或遮挡
- 校验需要本地无头浏览器与相应审批授权，CI 或受限沙箱里可能跑不通
- WebGL shader 与 3D 是可选增强，不同浏览器的呈现会有差异；纯 SVG 更稳
- 隐喻是解释工具而非工程示意，读数同源保证了自洽，但不保证与真实系统参数一致
- 仓库 75 个 issue 说明复杂场景仍在打磨，重要图示建议人工过一遍

## 7. 谁该用 / 谁别碰

写技术文章、教程与讲义、需要一张能交互又能说明机制的概念图的人；以及想研究「让 agent 自检图形输出」这条路径的工具作者。要求工程精确图纸或合规示意图的场景不适用。
