## 1. 它解决什么问题

家庭实验室与小型自建服务要在边缘同时解决动态域名、HTTPS 证书、端口转发、内网穿透、反向代理和访问控制，通常得装六七个小工具，各自有配置格式与升级节奏，出了问题很难一眼看清全貌。

## 2. 为什么是现在

27 天 499 星、54 fork，是本期后端方向里扩散较快的新项目。它强调 Apache-2.0、配置与数据留在本机、不收集上报，正好切中本期多篇文章共同关注的「数据留在自己设备上」这一取向。

## 3. 关键能力

- DDNS 覆盖主流提供商，ACME 自动证书，带 SNI 路由的端口转发与「单 443 端口承载所有服务」
- 反向代理与 Web 服务可替代常见 nginx 配置；内置 WAF 与入侵防御、SSO 与文件分享
- 集成 frp、Tailscale 与 Cloudflare Tunnel，按网络条件选择穿透路径
- fnOS 统一网关集成：点桌面图标即可进入管理界面，并可用 fnOS 会话登录；LAN 侧另有 :16680 管理端口
- Docker 管理与 Web 终端；十种语言 README，设置集中在浏览器控制台

## 4. 架构与实现

Go 单服务以 root 运行，以便监听 80/443 并通过 docker.sock 管理容器；Web 控制台提供全部配置入口，默认账号与口令需在首次登录后立即更换。Apache-2.0，README 明确配置与数据保存在本机、不上报。

## 5. 上手路径

1. 在 NAS、软路由或云主机按 Docker 或安装包部署，先只放在内网可达范围
2. 浏览器打开控制台登录，第一件事是修改默认口令并收紧访问来源
3. 配 DDNS 与 ACME，加一条反代 / SNI 规则，用一台测试服务验证 443 复用
4. 再按需接 Tailscale / frp / Cloudflare Tunnel，并核对 WAF 与 SSO 的实际规则

## 6. 风险与边界

- 进程以 root 运行且持有 docker.sock，一旦被攻破等同于交出整台主机，必须置于内网与强认证之后
- 默认账号口令是公开信息，首次登录不修改就等于把边缘网关对外开放
- 把证书、WAF、隧道、SSO、文件分享与容器管理收进一个进程，故障域与升级风险高度集中
- 27 天新仓、3 个 issue，暴露到公网前需自行做一轮配置审计与权限复核
- fnOS 集成与默认端口属于特定发行环境，迁移到通用 Linux 时行为可能不同

## 7. 谁该用 / 谁别碰

自己管 NAS / 软路由、希望把分散的边缘能力集中管理的家庭实验室用户与小规模自建服务维护者。不建议不经审计直接放到公网生产入口。
