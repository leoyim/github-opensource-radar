## 1. 它解决什么问题

在桌面直接跑 Claude Code 时，代理配置、浏览器登录态、时区语言与主机凭据混在同一环境里：既难确认流量是否真的走了预期出口，也难控制项目文件与 SSH 密钥被谁读到。把这套环境拆到 VPS 或指纹浏览器上又要手工拼一堆工具，配置漂移后很难复核。缺的是一个边界明确、能自检的隔离工作台。

## 2. 为什么是现在

11 天新仓即录得 +2,063 的日增，是本期唯一四位数增量、约占全榜有基线项目日增的七成五；381 fork 与 57 issue 说明不少人真的把它跑起来了。需求侧的背景是 agent 编码工具进入日常后，「在哪个环境里跑」从偏好问题变成了配置问题。

## 3. 关键能力

- Cage 接管并代理客机内部全部网络流量，代理不可用时不做直连回退；关键检查失败或证据不完整即暂停外网
- 隔离时区、语言等环境指纹，支持与代理出口 IP 自动同步，并内置网络与隔离检查面板
- 针对 Claude 登录、授权与 Claude Code 进程做全链路适配，终端、浏览器、编辑器与官方 Claude Desktop 同窗口工作
- 共享范围可控：只共享默认工作区与显式打开的项目文件夹，主机的 Claude 登录态、浏览器配置与 SSH 密钥不自动导入
- 可选 macOS、Windows 或 Linux 客机，能自动匹配本机系统版本下载官方镜像；支持连接自有服务器与手机接续电脑上的任务

## 4. 架构与实现

Go 桌面程序负责编排虚拟机与代理，客机内跑 Claude Code 与浏览器，宿主机只暴露指定工作区。网络侧管理订阅导入、节点选择与出口检查，检查未通过则环境保持离线；指纹侧统一设置时区与语言。MIT 许可，README 提供十余种语言版本与「使用前了解这些边界」章节。

## 5. 上手路径

1. 下载并安装桌面端，先准备一个自己可控的网络代理（订阅或节点），不要跳过出口检查
2. 选择客机系统并创建独立环境，必要时让程序匹配本机系统版本下载官方镜像
3. 只把当前项目文件夹加入共享范围，确认主机登录态与 SSH 密钥未被导入
4. 打开终端运行 Claude Code，观察内置网络与隔离检查通过后再开始工作

## 6. 风险与边界

- 项目自述的使用场景涉及平台账号环境风控，实际使用前需自行确认服务条款与合规边界，本解读不对其用途作建议
