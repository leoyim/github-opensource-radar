## 1. 它解决什么问题

一次运维会话里，SSH 终端、SFTP、端口转发、远程桌面往往是四个不同程序，凭据散落、隧道规则与会话生命周期不同步；而新一代带 AI 助手的终端又多是 WebView 套壳，体积与内存都不轻。缺的是一个把这些能力当作同一个「会话对象」来管理的应用。

## 2. 为什么是现在

21 天 954 星、100 fork，却有 132 个 issue——真实使用反馈密度是本期最高的之一，说明用户已经把它接进日常会话。Go + Viva 的无 WebView 路线在桌面 SSH 客户端里也属少数派，与本期其他几个原生绘制项目形成呼应。

## 3. 关键能力

- 主机按分组、标签、颜色、图标管理，可从 OpenSSH config、PuTTY、MobaXterm 等格式导入；密码入 AES-256-GCM 保险库，密钥交给系统密钥库
- 分屏后可在 shell 旁查看 CPU、内存、磁盘与网络；终端登录、SFTP 文件面板、转发规则与 AI 助手共享同一会话上下文
- 本地 / 远程 / SOCKS5 / HTTP CONNECT 转发规则仅绑定回环、可保存、随所属 SSH 标签停止；跳转链与备份同步也在同一模型内
- VNC 与 RDP 可借 SSH 主机连接仅监听回环的服务；标签、分屏、SFTP、转发与助手都是命令面板里的命令，鼠标可选
- AI 助手与 MCP 接入后能读当前终端输出，用于解释部署日志或协助操作

## 4. 架构与实现

Go 1.26+ 配合需同级检出的 Viva 框架做原生绘制，支持 macOS（Metal 与 Xcode 命令行工具）、Windows 10/11、Linux，不内嵌 WebView。认证支持运行中的 agent、私钥文件与密码；Apache-2.0 许可。README 专设「Honest about limits」说明远程桌面等能力的边界。

## 5. 上手路径

1. 准备 Go 1.26+ 与同级目录的 Viva 检出，按 Build from source 构建
2. 在 Hosts 新建主机，选认证方式（agent / 私钥 / 密码），连接时核对 host-key 指纹再决定是否信任
3. 打开终端与文件面板，按需添加仅绑回环的转发规则并验证随标签停止
4. 需要助手时先确认 MCP 端点与终端输出的数据边界，再让它读日志

## 6. 风险与边界

- 需要从源码构建且依赖同级 Viva 仓库，开箱即用程度低；132 个 issue 也说明接口仍在快速迭代
- AI 助手读取终端内容意味着日志中的密钥、令牌与客户数据可能进入模型上下文，务必先设数据边界
- 远程桌面、跳转链等能力 README 自述有明确限制，不能按成熟商业客户端的预期使用
- 把四类能力收进一个进程，崩溃或凭据泄露的影响面比分散工具更大
- 转发规则默认只绑回环是安全默认，但也意味着跨机访问需要额外显式配置

## 7. 谁该用 / 谁别碰

运维与后端工程师，尤其是希望在一个原生窗口内同时管会话、文件、隧道与屏幕、且愿意自己构建的人。只需要偶尔连一下服务器的轻量场景，用现成客户端更省事。
