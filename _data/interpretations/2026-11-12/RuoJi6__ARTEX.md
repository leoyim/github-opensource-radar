## 1. 它解决什么问题

让 agent 自主做安全测试，最难的不是让它找到问题，而是限定它能碰哪些资产、以及在高风险动作前把人放回环路。多数同类项目把范围写在配置里、把审批藏在日志里，出事之后很难回答「它当时为什么被允许做这一步」。

## 2. 为什么是现在

原仓库 Autumn-27/ARTEX 之后由本仓库独立维护，保留原始提交历史与 AGPL-3.0，发布包与 Docker 镜像改由本仓库 Actions 构建；34 天累计 1,707 星、995 fork。本期更新的重点是审批详情展示与资产同步，恰好对应上述两个卡点，而不是新增攻击能力。

## 3. 关键能力

- 全局「审批记录」、任务内「拦截审批」与对话中的审批卡片均可展开查看详情，审批结构参考 AegisHook 组件并沿用原有主题
- 从 ScopeSentry 接入数据源，按项目或任务维度选择域名 / 子域 / IP / 端口 / 站点 / 端点等资产类型，一键导入并按公司范围归并进资产图
- 仪表盘展示总览、Token 消耗与活动流；任务页给出会话、工具调用、探索链路、发现与资产覆盖图（力导向布局、已测高亮、节点折叠）
- 流量录制、人在环路对话、Agent 管理与 LLM 配置，可在同一界面观察与介入执行过程
- 提供一键安装脚本、Docker Compose（默认 localhost:8787）与可自行部署的 Vercel Mock 在线 Demo

## 4. 架构与实现

Go 后端承担任务调度与工具执行，Next.js 前端提供工作台；Docker 镜像 ruoji6/artex 由本仓库流水线发布。Mock Demo 通过 NEXT_PUBLIC_MOCK=1 呈现界面而不连接真实数据库，README 明确要求不设置 NEXT_EXPORT=1、不填数据库连接。AGPL-3.0 许可，保留上游提交历史。

## 5. 上手路径

1. 从 Releases 取发布包，或用 Docker Compose 起本地实例并确认 8787 端口可用
2. 配置 LLM 提供商与 Agent，先只接入明确授权的测试资产
3. 在「资产同步」页填 ScopeSentry 地址与 API Key，按项目导入域名、IP 与端口，核对归并结果
4. 建一个带拦截审批的任务，从会话与审批详情里确认每一步的授权依据

## 6. 风险与边界

- 渗透测试工具只应面向自有或取得书面授权的目标，README 亦附免责声明；「自主」不等于可以无人值守对外发起测试
- AGPL-3.0 对服务化与分发有较强要求，二次开发前需评估许可影响
- 独立维护分支与上游存在分叉，后续升级路径、安全修复的同步节奏需自行跟踪
- Vercel Mock Demo 不连真实数据库，只能看交互，不能据此判断实际测试能力
- 审批组件沿用第三方实现，展示层完善不等于策略层已经过独立审计

## 7. 谁该用 / 谁别碰

拥有明确授权范围的安全团队、红队平台工程与想研究「agent 可观测性」的开发者。没有授权资产、或希望完全无人值守自动对外测试的用法都不合适。
