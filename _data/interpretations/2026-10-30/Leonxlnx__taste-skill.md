## 1. 它解决什么问题

编码 agent 生成的界面有极强的同质化倾向：居中大标题、三张卡片、紫色渐变按钮、千篇一律的 hero 区。根因不是模型不会写 CSS，而是它没有美术方向、没有真实素材、也没有任何验收标准——生成完就交付。Taste Skill 补的正是这三件事：先给出方向，再配真实图片，最后用真实浏览器自检并返工。

## 2. 为什么是现在

今日 +1,131 星，AI 类第二。项目的 topics 里明确写着 anti-slop、claude-code、codex、cursor，说明它瞄准的是「AI 生成物太像 AI 生成」这个具体痛点。同期 superpowers 的代码评审、spec-kit 的 SDD、shannon 的 PoC 门禁，都在把「验收」前置到流程里——这是本期跨类别最一致的趋势。

## 3. 关键能力

- 读 brief 后先列出「只有这个客户才有的东西」，作为设计素材起点
- 从 20 个调研过的视觉方向中由脚本发三张牌，agent 选一张并说明理由
- 用一句话把客户自有素材与该方向缝合，形成设计概念
- 配真实摄影素材，来自开放档案并逐张标注来源与许可
- 在真实浏览器的三个宽度下检查页面，按 slop 特征判失败
- 看自己的截屏，修前三个问题，最多返工三轮

## 4. 架构与实现

它是一份 Agent Skill 而非独立程序：技能定义文件 + 方向库 + 取图脚本 + 浏览器检查脚本，运行在宿主 agent（Claude Code / Cursor / Codex 等）内部，无后端、无构建产物。设计决策由 agent 按技能里的流程走，判定由浏览器脚本产出，人只在方向偏离时介入。

## 5. 上手路径

1. 挑一个你已有人工设计稿的页面，让 agent 用这套技能重做，逐项对比偏差在哪一层（配色 / 排版 / 图片 / 信息层级）
2. 观察三张牌里它选的方向是否与你的品牌一致；不一致时改方向库，而不是反复改提示词
3. 把「三宽度截屏检查」单独摘出来接进你的 CI，这一步的收益与整套技能无关，可以独立用
4. 真实摄影素材的许可与署名要逐张核对，商用项目尤其注意

## 6. 风险与边界

- 方向库是作者个人的审美，品牌调性强的项目容易被带偏，且偏了不容易察觉
- 截屏判分能拦住「丑」，拦不住「错」——信息架构、可达性、文案准确性都不在它的判定范围内
- 外链图片存在许可、失效与加载速度三类风险
- 最多三轮返工意味着 token 成本不可控，页面复杂时会明显变慢

## 7. 谁该用 / 谁别碰

独立开发者、小团队做落地页与营销页，尤其是自己设计能力一般但能判断好坏的人。已有成熟设计系统的团队收益有限。
