## 1. 它解决什么问题

编码 agent 跑长任务时会反复停下来等权限确认，人一旦离开工位（开会、吃饭、通勤），任务就卡在原地。聊天式通知又会打断当前工作。coucou 把会话状态与批准动作搬到 Mac 刘海与手机锁屏/灵动岛，让「等确认」不再阻塞流程。

## 2. 为什么是现在

今日 +70 星，项目 32 天。0.4 版把它从「刘海挂件」升级为「真正的 Mac 应用」：系统级按住说话听写（本地 Parakeet）与无机器人入会的通话记录。同期 OpenMausBot 给 bot 虚拟机、nyaterm 给命令加风险卡片，三者分别占据「执行环境」「操作闸门」「人机接口」三个位置。

## 3. 关键能力

- 刘海/屏幕顶部挂件：显示 agent 会话状态与文件改动（文件名 +N −M）
- 权限批准：直接确认或拒绝 agent 的操作请求
- 拖文件给 agent，与 Claude 直接对话
- 手机端：iPhone 锁屏、灵动岛、小组件、Siri；Android 亦支持
- Flow 听写：按住任意键说话，松开后文字粘贴到光标处
- 本地语音识别：NVIDIA Parakeet 经 FluidAudio 跑在神经引擎，25 种语言，离线
- 无机器人入会的通话记录 + 转录 + 摘要 + 待办
- 听写统计（字数、节省时间、连续天数）
- 支持 Claude Code、Cursor、Codex、Gemini CLI、Antigravity 等十余种 agent

## 4. 架构与实现

Mac 原生应用（Swift）监听各 agent 的会话状态文件或接口，把状态渲染到刘海挂件；语音识别在本地经 ANE 推理，不联网；移动端通过与 Mac 的同步通道接收状态与批准请求。v0.4 的听写与录音功能依赖较高系统权限（麦克风、辅助功能、通知）。

## 5. 上手路径

1. 先只开刘海状态显示，观察它对工作流的干扰程度——常驻挂件很容易变成视觉噪音
2. 权限批准先在非关键仓库试用，确认它的批准范围与你理解一致
3. 听写要配好词典与替换规则才准，专有名词不配会持续出错
4. 通话记录涉及他人隐私，先确认录音的本地存储位置与告知义务

## 6. 风险与边界

- 需要较高系统权限（麦克风、辅助功能、通知、可能涉及录屏），权限面大
- 功能堆叠很快（挂件、听写、录音、同步），体积与稳定性存在波动
- 跨设备同步意味着会话内容离开本机，需确认传输与存储方式
- 32 天的项目，权限模型与数据处理逻辑建议自行审计

## 7. 谁该用 / 谁别碰

长时间跑编码 agent、经常离开工位的开发者。只用短会话、不离开工位的人收益有限。
