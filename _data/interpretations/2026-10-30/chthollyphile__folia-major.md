## 1. 它解决什么问题

音乐播放器的差异化在歌词表现力与多源聚合，但这类项目长期卡在两件事上：各平台接口易变导致源随时失效；社区扩展没有安全边界，装上就信任。Folia 用智能歌词匹配与 AI 配色解决体验问题，用带签名的模组市场解决扩展治理问题——后者在同体量项目里相当少见。

## 2. 为什么是现在

今日 +203 星，项目 336 天。它同时提供 React Web、PWA 与 Electron 桌面三种形态。同期 Concat 暴露 MCP 供脚本驱动、coucou 让人远程批准权限，说明工具类项目正把「可被第三方扩展」当成一等需求，而一旦开放扩展，就必须回答「扩展怎么被信任」——Folia 的三档签名标识正是对这个问题的回答。

## 3. 关键能力

- 多源聚合：网易云、酷狗、QQ 音乐、Navidrome、本地库
- 桌面端扩展源：波点音乐、YouTube Music、Spotify、汽水音乐
- 全屏沉浸式歌词动画与智能歌词匹配
- AI 生成配色主题
- Electron 桌面端 + Node Web 端 + Vercel 一键部署
- 自建模组市场，Folium 签名区分「官方认证 / 先行测试 / 未验证」
- 模组开发指南与由契约文件生成的 API 参考

## 4. 架构与实现

React 前端，Node 服务端提供多源聚合与歌词匹配；桌面端用 Electron 打包。模组以 zip 形式分发，运行时加载；市场内模组带 Folium 签名，安装后按签名状态显示信任等级，未签名模组仍可加载但标记为未验证。API 文档由契约文件生成，保证模组作者看到的接口与实现一致。

## 5. 上手路径

1. 先跑 Web 版（Vercel 或本地 node）验证你常用的几个源是否可用，多源项目的可用性波动很大
2. 模组开发按官方指南写第一个再考虑上架，签名流程有审核环节
3. 注意签名只覆盖市场内模组，第三方仍可加载——安全边界实际由用户判断，不是你
4. 桌面端歌词动画吃 GPU，低配机器先关动画验证音频链路

## 6. 风险与边界

- 依赖非官方平台接口，随时可能因对方改动而失效，属结构性风险
- AGPL-3.0，二次分发与 SaaS 化有明确约束
- AI 配色需要外部模型，涉及密钥管理与隐私
- 未签名模组可运行意味着扩展生态的信任默认开放，恶意模组风险由用户承担

## 7. 谁该用 / 谁别碰

追求歌词可视化与多源聚合的重度听歌用户，以及想学习插件体系与签名分级设计的前端工程师。
