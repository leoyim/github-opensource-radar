## 1. 它解决什么问题

在线设计工具的能力早就够用，问题在别处：免费档带水印、导出格式受限、素材与作品存在别人的服务器上、团队协作按人头计费。对内部团队，这四点里任何一点都可能让工具无法采用。doory 的选择是把编辑器做成可自托管的应用：无付费档、无需注册即可开始、Docker 或 nginx+systemd 都能跑，数据在自己的盘上。

## 3. 关键能力

- 从模板或空白页开始，覆盖海报、社媒图、故事、幻灯片、邀请函、简历、缩略图、名片
- 左侧工具栏加随选中对象变化的上下文面板
- 图层重命名、锁定、隐藏、分组、排序，以及复制与对齐
- 进入退出强调动画、页面转场、音乐与音效，可演示或导出视频
- 导出 PNG、JPG、SVG、PDF、MP4、GIF，印刷 PDF 支持出血与裁切标记
- 自托管：Docker 或无 Docker 的 nginx 加 systemd
- 可选项：邮件、Google 登录、OIDC 单点、S3 兼容存储、服务端导出

## 4. 架构与实现

前后端分离的单体：一个 API 服务加一个 Web 客户端，开发分三段（make setup、make dev-api、make dev-web）。渲染与导出在浏览器侧完成，服务端只负责存储、账号与分享链接，因此自托管时的计算压力落在客户端而不是服务器——这也是它敢承诺「零配置起跑」的原因。可选集成全部通过环境变量开关，默认关闭，避免部署时被 OAuth 与对象存储卡住。

## 5. 上手路径

1. 先用 Docker 起一份，确认导出 PDF 的字体嵌入是否完整，这是自托管设计工具最常见的坑
2. 把 S3 兼容存储接上，否则附件会落在容器本地卷，容器重建即丢
3. 印刷用的话拿真实印厂文件验一次出血与裁切标记，别只看屏幕效果
4. 十套模板不够用时，先评估模板格式是否好写，这决定它能否长期可用

## 6. 风险与边界

- 模板库极小，实际使用基本是从空白页开始，替代不了 Canva 的素材生态
- 项目年轻，导出复杂排版（多页、混排文字、特殊字体）的稳定性未知
- 自托管意味着备份、升级与安全补丁都归你，长期维护成本要算进 TCO
- 许可为 NOASSERTION，商用分发或二次开发前必须确认条款

## 7. 谁该用 / 谁别碰

需要内部设计工具、又不能把素材放第三方云的小团队；对模板量有要求的市场团队不适合。
