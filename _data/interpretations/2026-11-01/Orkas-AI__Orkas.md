## 1. 它解决什么问题

单 agent 的瓶颈不是能力而是持续性与分工：一个 prompt 出一个结果，下一轮又要重新交代背景；复杂任务需要多个角色（研究、写作、设计、编码）接力，现状是人来当调度。Orkas 的做法是把「项目」做成第一类对象——目标、规则、记忆与文件都挂在项目下，待办在人与 agent 之间分配，团队自己往下推。

## 2. 为什么是现在

186 天、6,769 星、今日 +1,044，为本期全榜最高日增。它与同期的 orca（多 agent 终端编排）、paperclip（agent 组织管理）构成一组对照：三者都在做 agent 的「组织层」，Orkas 的差异是自带 16 个专家与生产工具链，更偏交付结果。

## 3. 关键能力

- Commander 把目标拆成待办并调度
- 16 个内置专家：视频、语音、图像、深度研究、SEO 审计、股票分析、内容写作、PPT、UI 设计、产品开发、Office 文档、电商等
- 可联合 Claude Code、Codex、OpenCode、OpenClaw、Hermes 一起工作
- 项目维度保存目标、规则、记忆与文件，新对话接着上次继续
- 待办在人与 agent 之间分配，Auto-advance 让团队自动推进下一项
- 定时自动化：小时、日、周、月级
- 本地优先，数据留在本机，成品回到人工复核
- macOS 与 Windows 免费应用，可用内置模型或自带 key

## 4. 架构与实现

三层：项目层是持久化容器（目标、规则、记忆、文件），解决跨会话连续性；调度层是 Commander，把目标分解为待办并决定由哪个专家执行、何时需要人确认；执行层是可插拔的专家与外部 harness，每个专家绑定一组工具与提示词，外部编码 agent 通过适配器接入。Auto-advance 与定时器在调度层触发，形成闭环。数据落本地，模型可走内置或用户 key，因此没有云端账号体系。

## 5. 上手路径

1. 第一个项目选「一周内要交付的小成品」，不要用开放式目标验证，否则看不出它是否会收敛
2. 把项目规则写清楚（风格、禁用做法、验收标准），这是它区别于普通对话的关键输入
3. 先用一个专家跑通，再让它联合编码 agent；一次上五个专家会看不清是谁出的问题
4. Auto-advance 先关着，手动批准几步，确认它的判断与你的标准一致再放开

## 6. 风险与边界

- 16 个专家意味着 16 套提示词与工具，质量必然不均，营销类专家的产出需要重点核对
- 全自动推进会在错误方向上持续投入，人工复核点必须显式设计
- 本地优先代表没有云端备份，项目数据丢失只能靠自己的备份
- 内置模型的成本与限额策略需在试用期内摸清，避免长任务中途停摆

## 7. 谁该用 / 谁别碰

独立开发者与小型团队，需要把研究、内容、设计、编码串成一条交付链的人；只需要写代码的人用 orca 更直接。
