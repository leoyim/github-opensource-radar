## 1. 它解决什么问题

系统自带听写在跨应用场景里体验割裂：有的应用不响应，切换语言要进设置，转写结果还要手动确认。云端听写工具（Wispr Flow 一类）解决了体验，但把语音送出本机。hex 的选择是把这两头都占住：原生应用，端上识别，快捷键按住即说，松开自动粘贴到当前焦点应用。

## 2. 为什么是现在

106 天、2,225 星、今日 +172，属本周期的稳定增长。它与 anarlog（会议转写）、Mika（手机端 agent）同属本地优先这条线：语音是最敏感的数据之一，把它留在设备上正从卖点变成默认预期。

## 3. 关键能力

- 按住快捷键说话，松开后转写并粘贴到当前应用
- 端上语音模型，安装时下载，音频不出本机
- 可选语言与模型，Modes 支持按场景切换行为
- macOS 15 加 Apple 芯片为主路径，Windows 与 Linux 为 beta
- 提供 TypeScript SDK，可把听写能力接进自己的应用
- 签名 DMG 分发，走标准安装与权限流程

## 4. 架构与实现

Rust 原生应用，分三层：全局快捷键层监听按键并判定录音起止，音频层采集麦克风，识别层调端上模型（首次启动下载）。粘贴环节依赖辅助功能权限，通过模拟按键把结果送进前台应用，因此它不需要为每个目标应用写集成——这也是它比「逐应用适配」的方案更容易维护的原因。SDK 把同一套识别与粘贴能力暴露给第三方。

## 5. 上手路径

1. 先确认机型与系统版本：macOS 15 加 Apple 芯片是主路径，其余是 beta，别在旧机器上先下结论
2. 把麦克风与辅助功能两个权限一次配好，辅助功能没给会导致「识别成功但不粘贴」
3. 试三档场景：短句、长段落、中英混说，后者最能暴露模型边界
4. 如果要做集成，优先用 SDK 而不是模拟快捷键，稳定性差一个量级

## 6. 风险与边界

- 端上模型对专业术语与中英混说的准确率仍低于云端大模型
- 辅助功能权限是强权限，企业设备可能被 MDM 策略禁止
- Windows 与 Linux 为 beta，行为差异与缺陷密度都更高
- 按住说话在长段落场景下体验不佳，缺少「持续聆听」模式

## 7. 谁该用 / 谁别碰

长时间写代码与文档、希望减少键盘输入的开发者；对语音数据出网敏感的用户。
