## 1. 它解决什么问题

游戏特效的常规做法是美术画序列帧或做粒子贴图，成本高、授权复杂、改色就得重画。程序化特效可以解决这些问题，但门槛在「写得出好看的那一段数学」。pixelfx 把 244 个特效做成独立的小段代码，每个都能单独播放、改色、镜像、导出——把「特效资产」变成「特效函数」。

## 2. 为什么是现在

2 天新建、1,647 星，热度按速度估算。它的传播动力来自两处：一是像素风在小游戏与独立开发圈的需求稳定，二是附带的 Claude Code 技能给出了「如何用 agent 批量生成同类资产」的范式，正好对上本期技能生态扩张的节奏。

## 3. 关键能力

- 244 个特效，覆盖火焰、爆炸、法术、天气、UI、拾取、生物等类别
- 两种类型：纯效果导出 draw(p, t, o)（给定时间与参数返回当前帧），以及带表演的动作
- 角色相关特效按「蓄力—出手—命中定格—收招」表演，目标有受击反应
- 12 套完整动作把多个特效串成一次攻击
- 浏览器内实时播放、改色、镜像
- 导出 sprite sheet，供 Godot 等任意引擎使用
- 附带 Claude Code 技能，按起草、渲染、查看、细化的流程生成新特效
- 自然语言驱动：「给法师大招加个霜新星」「出五个金币拾取方案给我看最好的两个」

## 4. 架构与实现

每个特效是一个纯函数：输入参数对象与时间 t，输出该帧要绘制的图元，因此没有状态、可任意跳帧、可离线批量渲染成序列帧。颜色与镜像作为参数注入，同一份代码能出多种变体。动作层在此之上定义一个时间轴，把多个特效按阶段编排并对目标施加反应。导出器把函数在固定帧率上采样成 sprite sheet，这是它能对接任意引擎的关键——引擎只需要图片，不需要理解特效代码。

## 5. 上手路径

1. 先在浏览器里挑 3 个接近你需求的，读它们的代码看参数怎么组织，再决定是否生成新的
2. 纯效果与「带表演的动作」要分清：前者可任意时长，后者有固定节奏，混用会很别扭
3. 导出 sprite sheet 前先定帧率与画布尺寸，改一次要重导全部帧
4. 让 agent 生成新特效时，把「渲染后自己看效果再改」这一步明确写进流程，否则它会交出不动的代码

## 6. 风险与边界

- 像素风是明确的美术取向，写实或高分辨率项目用不上
- 244 个特效的质量参差，需要逐个看而不是按数量评估
- sprite sheet 导出会放大包体，大特效序列帧占用可观
- 技能生成的代码需人工验收，「能跑」与「好看」之间差距很大

## 7. 谁该用 / 谁别碰

独立游戏开发者、像素风项目、需要批量特效资产又不想处理授权的团队。
