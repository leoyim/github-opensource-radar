## 1. 它解决什么问题

手机上的 AI 助手长期停在「问答」层：能告诉你步骤，不能替你做。要做自动化就得走 ADB 或无障碍脚本，配置门槛高、维护成本高。Mika 的取向是端侧 agent：说出需求，它在隐藏的后台屏上操作 app 与网页完成，前台不受影响。

## 2. 为什么是现在

3 天新建、2,948 星，热度按速度估算。它与 dsh-Go（手机跑 DSH）、Orkas（桌面多 agent）一起，说明 agent 的落点正在从「聊天窗口」移向「真实操作界面」；而端侧执行让隐私叙事成立，这是它能快速传播的原因。

## 3. 关键能力

- 自然语言下达任务，agent 操作手机 app 与网页直到完成
- 在隐藏的后台屏执行，前台可继续使用手机
- 模型可选：内置供应商加 API key，或直接账号登录
- 手机操控通过一次性无线调试配对开启
- 无自建服务器，对话与屏幕内容只发给你选择的模型供应商
- Kotlin 实现，Apache-2.0

## 4. 架构与实现

端侧 agent 循环：截图或读屏获取当前界面状态，模型决定下一步动作，通过无障碍服务执行点击与输入，再回到观察。隐藏后台屏是关键设计——任务在独立显示空间里运行，前台应用不受打扰，也不会因为用户切走而中断。无线调试配对用于获得更高权限的操作通道（如跨应用启动），配对一次即可长期使用。所有推理请求直连模型供应商，没有中间服务端，因此隐私边界等于你选的供应商。

## 5. 上手路径

1. 先做一个只涉及单一 app 的短任务（发一条消息、查一个订单），确认读屏与点击可用
2. 无线调试配对只做一次，但要注意重启后可能需要重新配对
3. 给任务写明终点条件，否则 agent 会在同一个界面反复尝试
4. 涉及支付、删除、发送的动作先关掉自动执行，改成逐步确认

## 6. 风险与边界

- 各家 app 的防自动化（混淆控件、检测无障碍）会让成功率波动很大
- 读屏加点击的权限极高，等于把手机控制权交给模型，需按任务分级授权
- 3 天的项目，兼容性与稳定性都未经过时间验证
- 无中间服务器意味着没有审计日志，出问题只能看本地记录

## 7. 谁该用 / 谁别碰

想把手上的重复手机操作交给 agent 的 Android 用户、验证端侧 agent 可行性的开发者；iOS 用户暂不适用。
