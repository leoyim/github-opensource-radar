## 1. 它解决什么问题

编码 agent 的运行时通常绑在桌面上：要有 Node、要有终端、要能长时间在线。离开电脑就只能等。dsh-Go 想解决两件事：在手机上直接跑 DSH（不依赖 Termux、不要 root），以及在外面连回电脑上已经在跑的 DSH 继续对话。

## 2. 为什么是现在

7 天新建、3,793 星，热度按速度估算。它与本期 Orkas、orca（手机端监控）指向同一个变化：agent 的使用位置正在从桌面移到手机，而移动端缺的不是模型，是运行时与审批交互。

## 3. 关键能力

- 本机运行：App 内安装 Ubuntu、Node.js 与 DSH 运行环境，免 root、不依赖 Termux
- 远程连接：通过 SSH 或 DSH Remote 使用电脑和服务器上的 DSH
- 聊天与工具：切换模型、发图片、语音输入、处理工具审批与提问
- 两种界面：聊天界面与网页模式
- 插件界面：适配 DSH Go 的原生工具卡、表单与面板，附 SDK、教程与示例
- 手机操控：授权后让本机引擎读屏、点按与输入，可随时停止
- 分享、导出、回放对话，调整主题、图标与桌宠

## 4. 架构与实现

双模式运行时：本机模式在 App 私有目录里解出 Ubuntu 根文件系统与 Node 运行时，DSH 以子进程方式跑在里面，通过本地回环与 UI 通信；远程模式把同一套协议指向 SSH 主机或 DSH Remote 端点，UI 层不区分两者。工具审批与提问被做成原生卡片，替代终端里的交互式提示——这是移动端可用的关键，因为手机上没法在终端里敲 y/n。手机操控走 Android 无障碍服务，读屏与点按都在设备本地完成。

## 5. 上手路径

1. 先用远程模式连你电脑上的 DSH，验证协议与审批流，这比本机装环境快得多
2. 本机模式装完先跑一个最小任务（读文件、改一行），确认 Node 与权限都正常
3. 把工具审批策略调到你舒服的粒度，手机上弹卡片太频繁会毁掉体验
4. 读屏点按只在你信任的任务上开，并记住随时可以停

## 6. 风险与边界

- 卸载会清空对话、Linux 环境与设置，升级前务必导出
- 本机跑完整 Linux 环境对存储与电量的消耗都不小
- 读屏点按是强权限，等于把手机操作权交给 agent
- 7 天的新项目，签名变更与包结构可能频繁调整，覆盖安装容易失败
