## 1. 它解决什么问题

在电脑上操作手机的需求一直存在：演示、录屏、批量调试、多设备测试。商业方案要么装客户端（留下残留、要账号）、要么依赖厂商私有协议。scrcpy 的解法极简——用 adb 拿到的调试通道传输视频流与输入事件，设备端不需要安装任何东西，拔线即净。

## 2. 为什么是现在

3,268 天、15.3 万星、单日 +102。这是老牌工具的常态曝光，但本期的对照意义很强：mobile 类另外四席分别是 PS5 重链接工具、2 天 1,087 星的手机隐私审计、29 天 1,022 星的手机-PC 互联、6 天的手机端 agent，全都围绕「让手机与电脑更紧密地工作」。scrcpy 是这条线上的原点——它证明了「零安装、低延迟、无账号」这套约束是可以同时满足的，后来的互联类工具大多在这个基础上叠加功能。

## 3. 关键能力

- USB 或 TCP/IP 连接，镜像视频与音频并支持键鼠控制
- 无需 root、无需在设备安装应用，断开后设备无残留
- 原生渲染，仅显示设备画面；30–120fps，分辨率 1920×1080 及以上
- 低延迟 35–70ms，启动到首帧约 1 秒
- 支持录屏、剪贴板同步、文件拖拽、多设备并行
- Linux / Windows / macOS 三平台，Apache-2.0

## 4. 架构与实现

极简的客户端-服务端模型：客户端把一个小型 server 二进制推送到设备并通过 adb 启动（仅存在于临时目录，退出即清理），设备侧用 MediaCodec 硬件编码屏幕与音频，通过 adb 通道回传，客户端用 FFmpeg 解码并渲染，输入事件反向注入。选择 adb 作为传输层是一切的根源——它免去了装 App、配网络、做鉴权，也把性能瓶颈限定在 adb 隧道带宽上。

## 5. 上手路径

1. 务必从官方仓库或发行版包管理器获取，README 明确警告不要从随机网站下 release
2. 先用 USB 跑通再切无线，无线模式要额外配 adb tcpip 且延迟更高
3. 调 --max-size 与 --video-bit-rate 控制带宽，默认档位在弱网络下会卡
4. 多设备时用 -s 指定序列号，否则命令会因目标不唯一而失败

## 6. 风险与边界

- 依赖 adb 调试通道，需开启开发者选项与 USB 调试，设备安全性下降
- adb 通道本身未加密（USB 除外），无线模式在不可信网络下应避免
- 第三方站点常以 scrcpy 名义分发捆绑恶意程序，来源必须严格核实
- 高帧率高分辨率下对主机与线材要求较高，劣质线缆会导致花屏

## 7. 谁该用 / 谁别碰

需要录屏与演示的开发者、做多设备自动化测试的团队、以及想在大屏上操作手机的重度用户。
