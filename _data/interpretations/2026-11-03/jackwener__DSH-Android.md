## 1. 它解决什么问题

在手机上让 agent 真正干活，过去有两条都不好走的路：一是在 Termux 里搭环境跑命令行 agent，配置繁琐、权限受限、电池消耗大；二是靠无障碍服务做自动化，但缺乏模型侧的规划能力，只能执行固定脚本。DSH-Android 把两者结合：引擎内嵌进 App 进程（不需要 Termux），操作层用读屏 + 点按 + 输入，需要系统级能力时走 Shizuku 或自连 ADB。

## 2. 为什么是现在

6 天、755 星，无日增基线。它代表的是本期最值得关注的一个走向：agent 的执行面正从桌面浏览器扩张到手机 App。README 列的场景很具体——在微信发消息、总结群聊、抓小红书内容、在 BOSS 直聘上投递打招呼、在淘宝下单——这些全是「只有手机端才有」的操作。另一个关键设计是 Android 14+ 的「不打扰模式」：配好 Shizuku 或自连 ADB 后，agent 在虚拟屏幕上操作，不占用用户当前屏幕。这条设计直接决定了它能否日常使用。

## 3. 关键能力

- 免 root、免 Termux，单个 APK 在手机上运行 DeepSeek Harness
- 引擎内嵌 App 进程，无需额外运行环境
- 读屏 + 点按 + 输入操作任意 App，过程中可随时暂停、停止或插话
- Android 14+ 不打扰模式：经 Shizuku 或自连 ADB 在虚拟屏幕上操作，不占用当前屏幕
- 悬浮球随时呼起对话或派活，也可把当前屏幕发给 agent 询问
- 内置 Linux 环境，可跑 Python、处理文件、执行自写脚本
- 通过 SSH 或 DSH Remote 连接电脑/服务器上的 DSH，纯远程模式无需本地运行环境
- 可登录 DeepSeek 账号或填 API key，也支持在设置里添加其他模型服务商

## 4. 架构与实现

单 APK 三段式：内嵌的 agent 引擎进程负责推理与规划，操作层通过无障碍读屏获取界面结构并向系统注入点按/输入事件，特权层在需要修改系统设置或使用虚拟屏幕时经 Shizuku（或自连 ADB）借用 shell 权限。把 Linux 环境打进 App 内意味着 Python 与文件处理可以本地完成，不必外挂 Termux。这种「一个安装包解决全部依赖」的取舍极大降低了上手门槛，代价是包体与功耗，以及权限模型的复杂度集中在首次授权环节。

## 5. 上手路径

1. 从官方 Releases 装 arm64 包，要求 Android 10 及以上
2. 先用远程模式（连电脑上的 DSH）验证模型与流程可用，再开本地运行环境
3. 要用不打扰模式必须先配 Shizuku 或自连 ADB，并开启「开机启动（无线调试）」
4. 首次使用时逐项授予权限，别一次性全开——读屏与输入注入权限范围极大
5. 先让它在低风险 App 上练手（如整理文件、总结页面），涉及支付与投递的动作需人工确认

## 6. 风险与边界

- 读屏与输入注入权限可读取屏幕全部内容并代替用户操作，滥用风险与安全边界必须自行评估
- 在招聘、电商类平台上自动投递与下单可能违反平台条款，账号风险由使用者承担
- agent 读屏会接触聊天记录、账号信息等最敏感数据，模型调用路径需确认
- 6 天新项目，稳定性与权限处理未经时间检验
- Shizuku 与自连 ADB 都要求开启调试能力，设备整体攻击面扩大

## 7. 谁该用 / 谁别碰

想把 agent 用到手机上的重度用户、做移动端自动化与 RPA 的开发者、以及在无电脑环境下需要 agent 协助的用户。
