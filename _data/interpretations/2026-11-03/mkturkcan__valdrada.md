## 1. 它解决什么问题

做自动驾驶或城市研究，需要「城市」作为测试环境。真实路测贵且不可复现；游戏引擎里的城市好看但没有真实拓扑，也没有可追溯的数据来源；CARLA 这类仿真器够专业，但场景构建成本高。Valdrada 的思路是：城市的建筑轮廓、税务地块、外立面备案、街道中心线本来就是公开记录，把它们编译成可流式加载的二进制瓦片，就能得到一个每个元素都能追溯到某份公开档案的纽约。

## 2. 为什么是现在

39 天、254 星、单日 +5——规模很小，但方向值得记。它出现在今天榜单上的意义，是提供了一条与 agent 热潮完全不同的技术路线：不追求让模型更聪明，而是把现实世界结构化，做成可仿真、可生成合成数据的底座。README 里提到「像素级精确的感知真值（perception ground truth）」和「参照 CARLA 的客户端-服务端 API」，说明目标明确是给感知模型训练供数据。在合成数据需求上升的背景下，这类「从公开记录编译世界」的项目会越来越多。

## 3. 关键能力

- 实时 WebGL2 渲染器，客户端围绕相机流式加载城市瓦片
- 车道级交通与行人仿真，含车道图与人行道图
- 像素级精确的感知真值输出，用于合成数据生成
- 参照 CARLA 设计的客户端-服务端 API，便于接入既有仿真工具链
- 所有建模元素可追溯到公开市政记录（建筑轮廓、税务地块、外立面备案、街道中心线）
- 附带编译好的城市数据与模型贴图，提供 Windows x64 仿真服务端与 Unreal Engine 5 Linux 客户端

## 4. 架构与实现

离线编译 + 在线流式两段式。离线侧是一个 Node.js 编译器：读取市政记录，把建筑轮廓与税务地块、外立面备案做 join 并归类立面类型，把街道中心线转成车行道、路缘、人行横道、车道涂装，输出二进制瓦片。在线侧客户端按视野范围拉取瓦片、贴立面、跑交通与行人仿真，并在同一帧内输出渲染图与对应标签。这个「数据可溯源」的设计是它区别于游戏引擎方案的核心——每一栋楼都能回答「这条数据从哪来」。

## 5. 上手路径

1. 先跑浏览器 demo 确认渲染与仿真链路可用，再下 Windows 仿真服务端做闭环
2. 理解瓦片格式与坐标系统是二次开发的前提，城市数据不是通用格式
3. 合成数据用途要先做域差异评估：公开记录里没有的（临时施工、季节植被、光照习惯）需要自己补
4. 明确许可证与市政数据条款，纽约公开数据的再分发条件与 MIT 代码许可不是一回事

## 6. 风险与边界

- 数据覆盖受限于公开记录完整性，非纽约城市无法直接套用同一套编译器
- 仿真真实度与感知训练需求之间存在域差异，直接拿合成数据训练容易过拟合仿真特征
- 项目仅 254 星、单人维护，长期可持续性存疑
- 代码 MIT 但底层市政数据的使用与再分发受各自条款约束
- UE5 客户端仅 Linux、服务端仅 Windows x64，跨平台使用受限

## 7. 谁该用 / 谁别碰
