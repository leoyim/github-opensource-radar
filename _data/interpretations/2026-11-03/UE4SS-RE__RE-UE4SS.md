## 1. 它解决什么问题

给 UE 游戏写 Mod，通常要自己处理注入、反射结构解析、蓝图加载和属性读写；每换一个引擎版本，之前逆向出来的偏移全部作废。

## 2. 为什么是现在

项目已维护四年、3,111 星，覆盖 4.7 到 5.8 的引擎跨度，是当前单机 Mod 社区里少见的长期维护型基础设施。

## 3. 关键能力

- Lua 脚本 API，基于 UE 对象系统写 Mod，不必编译 C++
- 蓝图 Mod 自动加载，不修改也不替换游戏原文件
- C++ Modding API，需要性能或深度控制时可直接对接对象系统
- 运行时属性查看与编辑，搜索、监视、修改任意已加载对象，调试 Mod 时非常实用
- UHT 与 C++ 头文件 Dumper，生成可编译的镜像工程与带偏移的头文件

## 4. 架构与实现

以 DLL 注入进入游戏进程，在引擎反射系统之上建立一层对象访问接口；Lua 绑定与 C++ API 共用同一套对象模型，Dumper 则把运行时的反射信息导出成可编译的头文件，供离线开发使用。

## 5. 上手路径

1. 先确认目标游戏的引擎版本，对照 README 的版本支持表选择对应构建
2. 按 Basic Installation 把文件放进游戏目录，先用自带的通用 Mod 验证注入成功
3. 读 Command Line Options 与 Environment Variables，调整日志级别便于排查
4. 要写自己的 Mod，从 Lua API 入手，比 C++ 门槛低得多

## 6. 风险与边界

- 注入类工具会被反作弊系统判定为异常，仅适用于单机或明确允许 Mod 的场景
- 需要与引擎版本严格匹配，游戏更新后往往要等新构建
- 涉及游戏文件的读写，使用前应确认不违反游戏的用户协议
- 277 个未关闭 issue，提问前最好先搜一遍

## 7. 谁该用 / 谁别碰

做单机游戏 Mod 的开发者；需要研究 UE 反射结构与运行时对象模型的逆向工程学习者。
