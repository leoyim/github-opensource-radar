## 1. 它解决什么问题

用罗技鼠标键盘的人几乎都被 Logi Options+ 劝退过：安装包大、常驻后台、必须登录账号，遥测开关藏在深处，而且在 Linux 上基本不可用。可真正的功能——改侧键、调 DPI、配 SmartShift 滚轮阻尼、看电量——又确实需要官方软件。OpenLogi 的切入点很直接：这些都是 HID++ 协议上的标准命令，没必要为它装一个带账号体系的臃肿客户端。

## 2. 为什么是现在

163 天、2.5 万星、单日 +108。这类「替代官方驱动」的项目能起量，通常意味着官方方案在某个人群里的体验已经跌破容忍线——这里的人群很明确：Linux 用户与外设重度用户。它把 Linux 当一等公民写进 README 第一条，而罗技对 Linux 长期只有社区 remap 工具可用。另一个推力是本地优先的叙事：TOML 明文配置可同步、可进版本库、可脚本化，与当下「配置即代码」的习惯正好对上。

## 3. 关键能力

- 按键重映射、DPI 调节、SmartShift 滚轮阻尼设置，走 HID++ 协议直连设备
- Linux 一等支持，同时覆盖 macOS 与 Windows
- 单个 TOML 明文配置文件，可用任意方式在多机之间同步
- GUI 之外提供真正的 CLI，含 JSON 自动化 API（DPI、SmartShift、Fn-lock、回报率）与硬件诊断
- 支持 Logi Bolt 与 Unifying 接收器、蓝牙、有线三种连接，可读电量与充电状态
- 低电量提示（每次放电周期一次，不需系统通知权限）、Caps Lock / Num Lock / Scroll Lock 屏上指示
- Easy-Switch 面板：显示每个通道配对的电脑及其系统与连接方式，并支持重命名

## 4. 架构与实现

Rust 编写，GUI 用 GPUI（Zed 团队的 GPU 渲染 UI 框架），设备通讯走 HID++ over HID 原始报文。分层是「设备层 → 能力模型 → 界面/CLI」：能力模型把不同型号支持的功能抽象成统一描述，界面与 CLI 都消费同一份模型，因此新增设备主要是补协议细节而非改两套逻辑。明文 TOML 作为唯一事实源，意味着 GUI 只是编辑器，真正可移植的是配置文件——这个取舍让它天然适配 dotfiles 管理与自动化。

## 5. 上手路径

1. 先确认你的型号在支持列表内：HID++ 各代协议差异大，老设备部分能力缺失
2. 把 TOML 放进 dotfiles 仓库，多机同步比用手工导出配置可靠
3. Linux 上先解决设备权限（udev 规则 / hidraw 访问），否则 GUI 能开但读不到设备
4. 要用脚本批量控制就先看 JSON API 文档，CLI 才是它最稳的接口面

## 6. 风险与边界

- HID++ 协议未公开，新硬件上市后需要逆向补齐，存在功能空窗
- GPUI 仍在演进，跨平台渲染层的稳定性依赖上游
- 绕过官方驱动意味着固件更新、部分高级特性可能无法支持
- 明文配置在多机同步时若含敏感信息（如自定义宏内容）需注意仓库可见性

## 7. 谁该用 / 谁别碰

Linux 桌面用户、不愿为改两个侧键而登录账号的外设玩家、以及需要脚本化控制外设的自动化用户。
