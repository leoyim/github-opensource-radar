## 1. 它解决什么问题

液态玻璃效果在截图里很好看，落到真实页面就开始塌：边缘折射要么靠 WebGL 重渲染整个背景，要么用一张模糊图假装；文字对比度随壁纸变化失控，换一张背景就要重调一遍参数。缺的是一个能逐项拆开、实时看到代价、并直接导出可用 CSS 的场地。

## 2. 为什么是现在

仓库仅 6 天、60 星、4 个 fork、MIT 许可、无构建步骤，README 却把实现拆成了六层并逐层说明取舍（阴影、模糊与提亮、边缘折射、边缘高光、色板、文字对比）。这种「小仓库、高文档密度」的组合通常意味着作者是先做完再发布，而不是先占坑再补文档。

## 3. 关键能力

- 明暗两套玻璃独立调参：着色与强度、模糊、饱和度、亮度、对比度、边缘光、斜面与阴影
- 边缘折射可调宽度、边缘偏移、衰减与色散，圆角平滑度独立控制，折射跟随圆角形状
- 自适应玻璃：壁纸越复杂着色越浓，同时把文字对比度守在 4.5:1 以上
- 内置五世代 macOS 抽象壁纸（含两套动态）、六张 WebGL 动态壁纸，以及 Unsplash 随机图
- 自定义图片或视频可上传、拖入、粘贴文件或粘贴链接，本地文件仅在浏览器内打开、不上传
- 五个预设（Lumno / Clear glass / Frosted / Thick slab / Vivid），只改材质不动其他设置
- 全部参数写入 URL，分享链接即可复现同一结果；一键复制生成的 CSS

## 4. 架构与实现

纯前端、无构建步骤、MIT 许可。实现上不替换组件结构，只改四条声明：background、backdrop-filter、box-shadow、color；材质由阴影、模糊提亮、SVG 位移折射、边缘高光、色板与对比度六层叠加。折射依赖 Chromium 与 WebGL，其它浏览器降级为普通模糊。

## 5. 上手路径

1. 直接打开在线 playground，先用预设感受五档材质差异
2. 换一张自己的壁纸，观察自适应着色与文字对比度的联动
3. 逐项调边缘折射的宽度、偏移与衰减，找到与设计稿匹配的一组
4. 点 Copy CSS，把四条声明贴进自己的组件，确认结构未被破坏
5. 把参数固化进 URL 存档，作为团队内的材质规范链接

## 6. 风险与边界

- 折射效果依赖 Chromium 与 WebGL，Safari 与 Firefox 上会退化为普通模糊，跨端观感不一致
- backdrop-filter 在低端 Android 设备上开销明显，长列表或滚动场景可能掉帧
- 仅 6 天、4 个 fork，API 与参数命名仍可能变动，不宜直接锁死版本依赖
- 自适应着色基于壁纸复杂度估算，极端高对比壁纸下仍需人工复核可读性
