## 1. 它解决什么问题

mihomo（Clash Meta）内核能力完整，但官方只提供命令行与配置文件的用法；想在桌面与手机上直观地看连接、切节点、管订阅，要么用第三方 GUI 忍受陈旧界面，要么自己写配置。跨平台还要面对「桌面一套、移动一套」的重复实现。

## 2. 为什么是现在

仓库仅 3 天，已 409 星、23 fork、5 个 issue，本期无历史基线，属首次进入视野。它的技术选择值得注意：桌面端用 Go 直接经 GPU 渲染界面、不走 WebView，Android 端用 Flutter 复用同一套卡片与皮肤——两条渲染路径却维持一致的视觉语言，这在同类客户端里少见。

## 3. 关键能力

- 按用途分流（Routes），出口节点可手动指定或按速度自动选择
- 连接面板逐条展示应用、目标、命中规则、出口与速率，支持运行时改道域名
- 订阅源可导入链接、节点 URL、YAML 配置或二维码，并显示各源的用量与到期时间
- 菜单栏/系统托盘切换系统代理接管、代理模式与兜底节点
- 十三套皮肤覆盖整套界面（Broadsheet、Phosphor、Neon、Blueprint、Sakura、Paper、Shanshui、Celadon、Dunhuang、Dusk、Aurora、Obsidian、Riso）
- 自定义规则（域名、关键词、IP 段）并可测试地址实际走向
- TUN 模式接管忽略系统代理的应用；网关模式（macOS/Linux）把本机变为局域网出口
- 开发工具联动：识别 Docker、终端、Git 等不走系统代理的程序，一键写入或撤销其配置
- 内置 MCP server，供 agent 读取状态与排障，改设置前默认先询问

## 4. 架构与实现

桌面端 Go + GPU 直绘（无 WebView），Android 端 Flutter，界面共用设计语言；许可证字段为 NOASSERTION，使用与分发前需到仓库确认条款。工程上有两处细节值得注意：一是「测得的出口位置」用 Cloudflare trace 校验而非只看配置；二是「下载源测速」覆盖 npm、pip、Go、Cargo，把包管理器换源这件琐事纳入同一界面。

## 5. 上手路径

1. 从官方发布页下载对应平台安装包，Android 侧安装 APK
2. 导入现有订阅链接或 YAML 配置，确认节点与规则被正确解析
3. 先用规则模式跑通日常流量，再按需开启 TUN 或网关模式
4. 在开发工具页勾选需要接管的程序，避免命令行工具绕过代理
5. 需要 agent 协助排障时启用 MCP，保持「改设置前询问」的默认策略

## 6. 风险与边界

- 仅 3 天的新项目，5 个 issue 虽少但基数小，稳定性尚未经时间检验
- 许可证字段为 NOASSERTION，二次分发或商业集成前必须确认条款
- TUN 与网关模式会改动系统网络栈，配置错误可能导致断网，需保留回滚方式
- 代理节点的来源与用途由使用者自行负责，需符合所在地法律法规与服务条款
- 桌面与移动两套渲染路径可能产生行为差异，问题排查需区分平台
