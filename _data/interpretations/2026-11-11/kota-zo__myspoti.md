## 1. 它解决什么问题

Spotify 官方 Android 客户端把广告、播客推荐与社交功能层层叠加，免费账号还要忍受音频与视频广告；想要一个「只有音乐、界面干净」的客户端，官方并不提供，第三方方案又大多停在旧版 API 上。

## 2. 为什么是现在

28 天、1,839 星、99 fork、148 个 open issue，本期日增 76。它的实现路径值得注意：不在逆向 API 上重建播放能力，而是把官方 Web Player 藏在应用内、用手机自身的 DRM 播放，再用 Compose 自绘界面去驱动它——播放上报仍按浏览器行为计入艺人与 Wrapped，这让它在「可用性」上比纯逆向方案稳。

## 3. 关键能力

- 使用自己的 Spotify 账号登录（在 Spotify 官方登录页完成，应用不接触密码）
- 自绘界面：首页、搜索、音乐库、播放列表、播客、Spotify Connect 与 Android Auto
- 逐词歌词、官方 MV、Genius 歌曲解读
- 离线下载通过「下载源扩展」实现：扩展决定文件来源与格式（FLAC/M4A/MP3），应用加密存储并校验时长
- 下载的播放列表与 Spotify 保持同步，新增歌曲自动下载
- 沉浸式视觉，设计灵感来自 BitChord（README 已署名）

## 4. 架构与实现

Kotlin + Jetpack Compose，GPL-3.0 许可。架构上是「WebView 承载官方播放器 + 原生界面作为控制层」的混合体：播放能力与 DRM 交给官方实现，交互与视觉完全自绘。下载能力被刻意做成可插拔扩展，应用本身不提供下载源——这个设计既划清了责任边界，也把合规风险转移给了扩展提供方。

## 5. 上手路径

1. 从 Releases 下载 APK 侧载安装（不在应用商店分发）
2. 用现有 Spotify 账号在官方页面登录，免费账号即可
3. 先在 Wi-Fi 下验证播放、切歌与 Connect 是否正常
4. 需要离线时自行安装下载源扩展，注意其来源与合法性
5. 关注 issue 列表，登录或播放失效通常与官方前端变更有关

## 6. 风险与边界

- 绕过广告与离线限制与 Spotify 服务条款存在冲突，账号被限制的风险由使用者承担
- 依赖官方 Web Player 的前端结构，Spotify 改版可能导致播放失效
- 下载源扩展由第三方提供，来源不可控，存在恶意文件与版权风险
- 侧载 APK 无应用商店签名校验，需自行核对发布者
- 148 个 open issue 说明 28 天内问题积压较快，稳定性仍在爬坡

## 7. 谁该用 / 谁别碰

想要干净界面与逐词歌词、能接受侧载与条款风险的 Android 音乐重度用户；以及研究「原生界面 + 官方 Web 播放器」混合架构的客户端开发者。
