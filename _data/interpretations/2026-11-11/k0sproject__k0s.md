## 1. 它解决什么问题

标准 K8s 安装要处理容器运行时、kubelet、CNI、证书、etcd、负载均衡等一长串前置条件，不同发行版的依赖矩阵各不相同；到了边缘与 IoT 设备，往往连包管理器都没有，安装脚本直接失效。

## 2. 为什么是现在

2,345 天、6,585 星、541 fork，OpenSSF Best Practices 徽章与夜间 OS 测试矩阵都在跑，属于长周期维护的发行版。本期日增仅 6，说明它不是靠话题上位，而是被持续引用——这类项目出现在日报里，通常对应某批团队在做边缘或离线环境的选型。

## 3. 关键能力

- 单二进制同时承担控制面与工作节点角色，可在同一节点上启用或分离部署
- 零宿主依赖：除 Linux 内核外不需要额外软件包，支持任意 Linux 发行版
- 内置 CNI、CoreDNS、Metrics Server、konnectivity 等组件，开箱即可拉起可用集群
- 支持单节点、多节点、高可用（嵌入式 etcd）与 air-gapped 离线安装
- 通过 k0sctl 做声明式集群生命周期管理，支持升级与备份恢复
- 适配云、裸机、边缘与 IoT，资源占用可压到较低水平

## 4. 架构与实现

Go 编写，许可证字段为 NOASSERTION（需到仓库确认为 Apache-2.0 或相应条款）。设计核心是「把所有组件编译进一个可执行文件，用进程管理替代包管理」，因此安装不依赖 systemd 之外的宿主能力（也提供无 systemd 模式）。CNCF 认证保证 API 兼容性，OpenSSF 徽章与夜间多发行版 OS 测试则覆盖了「在陌生环境能否起来」这一关键风险。

## 5. 上手路径

1. 先确认目标环境的架构与内核版本，下载对应 k0s 二进制
2. 单节点验证：k0s install controller --enable-worker 后启动服务，取 kubeconfig
3. 多节点用 k0sctl 写 cluster.yaml，一次性下发控制面与工作节点
4. 边缘或离线场景准备 air-gapped 镜像包，验证无外网时的拉起路径
5. 上线前跑一次备份恢复演练，确认 etcd 快照可用

## 6. 风险与边界

- 许可证字段为 NOASSERTION，分发与商用前需确认具体条款
- 单二进制打包全部组件，升级时是整体替换，回滚窗口需要提前规划
- 270 个 open issue 说明边缘场景的组合复杂度仍在被消化
- 默认组件选择偏「能跑起来」，生产环境仍需按需替换 CNI、Ingress 与存储
- 与托管 K8s 的托管能力（自动修复、托管控制面）不可直接类比，运维责任在用户侧

## 7. 谁该用 / 谁别碰

要在裸机、边缘设备或离线环境部署 K8s 的平台工程师；需要给客户交付「一个二进制就能起集群」的 ISV 与集成商。
