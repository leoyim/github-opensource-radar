## 1. 它解决什么问题

模型生成的文本有一批高度稳定的套话：对比式升华、单句收尾、「Here's the thing」式铺垫、假装有反驳对象、空洞的核心论断言。人工逐篇改既慢又难保持一致，而一句「写得自然些」对模型几乎没有约束力。

## 2. 为什么是现在

本期 70,391 星、5,529 fork，304 天项目，较上一快照新增 457 星；README 把维基百科「Signs of AI writing」与 WikiProject AI Cleanup 作为模式来源，并以 agent skill 的形态分发，说明「技能包」正在成为把编辑规范固化给 agent 的常见载体。

## 3. 关键能力

- 按维基百科「AI 写作迹象」清单识别并改写典型套话：Not X but Y、一句话升华、听起来很深刻的格言、分阶段铺垫、无对象反驳等
- 只调整表达方式，不改原文的事实与论点
- 以标准 agent skill 形式加载，可用于 Claude Code、Codex 及其他支持 skills 的 agent
- README 自述盲测中评审 16 次全部更偏好改写后的版本，并明确不面向绕过 AI 检测器

## 4. 架构与实现

本质是一份结构化的写作规范 + 执行指令，而不是服务或模型：skill 被 agent 读入上下文后，按模式清单逐项扫描待改文本并重写命中片段。规则来源公开可查（维基百科条目与 WikiProject AI Cleanup 的维护页面），因此可以由使用者自行增补或裁剪模式。

## 5. 上手路径

1. 把 skill 放进你的 agent 的 skills 目录，用一段自己写的 AI 味明显的文字试跑一次
2. 对照维基百科模式清单检查哪些套话被清掉、哪些事实被误改
3. 把团队常用的禁用句式补进规则，再跑一遍确认不损失原意
4. 对重要文稿保留改写前后对照，形成可复核的编辑记录

## 6. 风险与边界

- 规则基于公开清单，对中文语境的「AI 味」覆盖不一定完整，需要自行补充本地化模式
- 任何自动改写都可能改变语气甚至细微语义，正式发布前必须人工通读
- README 明确声明不用于绕过检测器，把它当「过检测」工具使用既无效也不符合项目定位
- 5 个 open issue 但星标量级极大，说明使用广泛而反馈渠道相对安静，规则更新节奏需自行跟踪

## 7. 谁该用 / 谁别碰

需要批量产出面向人类读者文本、又希望保持统一文风的写作者与内容团队；追求绕过检测或需要严格保留法律/技术措辞的场景不适用。
