## 1. 它解决什么问题

把大模型接上安全工具并不难，难的是「agent 说发现了漏洞」之后怎么核实：多数编排只留一段对话记录，看不到当时探测了哪些资产、发了什么请求、为什么判定成问题；同时完全自主的探测又容易越出授权范围、打爆目标或烧穿预算。

## 2. 为什么是现在

本期 6,943 星、3,048 fork、14 个 open issue，40 天新仓且较上一快照新增 2,069 星，是本期增量最高的一项；README 把「两张图 + 证据绑定 + 审批门」写成核心设计而非附加功能，说明关注点已从「让 agent 会用工具」转向「让自主执行可被审计和约束」。

## 3. 关键能力

- planner 把目标拆成 intent 并分派 worker，worker 用真实工具执行后把结果写回，形成闭环推进直到目标被证明或耗尽预算
- 共享资产图记录目标的根域、子域、IP 等事实，单任务探索图记录 goal / intent / fact / finding 的推理与进度，两者由 anchors 关联
- 录制型 MITM 代理与浏览器扩展抓取真实 HTTP 流量，发现、证据引文与复测都绑定到确切的请求响应对
- 自主行为经范围与 deny 规则、human-in-the-loop 审批、argv 前缀白名单、token 与轮次预算、目标噪声治理与工具输出的提示注入隔离
- 单 Go 二进制内嵌 Next.js 界面，配 PostgreSQL；模型侧可接自有 Anthropic/OpenAI 兼容端点或本地 Ollama，并支持多供应商 worker 轮换

## 4. 架构与实现

自托管的单体服务加数据库：Go 进程承载编排、图存储与 Web UI，PostgreSQL 存资产与任务状态，MITM 代理和浏览器扩展负责把外部流量录进证据链。LLM 只承担规划与意图分派，实际动作由受约束的 worker 执行；任务级 LLM 配置链决定用哪个 profile，轮换模式按 intent 顺序在多个供应商间分配，失败时回退到任务当前 profile。安装走 docker compose 从本机构建，首次访问用启动日志里的一次性 setup token 完成初始化。

## 5. 上手路径

1. clone 仓库后复制 .env.example 为 .env，至少设置 POSTGRES_PASSWORD，再执行 docker compose up -d --build
2. 从 docker compose logs 里取一次性 setup token，在 http://localhost:8787/setup 完成初始化并配置 LLM profile
3. 在 System → Settings 把并发 worker 数调到 2 以上，创建任务时先用一个明确授权的小目标验证范围规则与审批门是否生效
4. 核对一个发现的证据链：确认能追到对应的请求响应，再决定是否扩大探测范围

## 6. 风险与边界

- 这是具备真实攻击能力的工具，必须在自己拥有或获得书面授权的目标上使用，范围规则配错即可能越界
- README 明确没有预构建镜像、必须从 checkout 构建，构建链与依赖需自行审阅
- 录制代理会留存完整流量，其中可能含凭据与敏感数据，存储与访问权限要单独设计
- 40 天新仓、14 个 open issue，多供应商轮换与故障回退等较新路径的稳定性尚未经长期验证
