## 1. 它解决什么问题

Windows 自带任务管理器能看当下，但遇到「刚才卡了一下」「昨晚某个进程偷偷跑满」这类问题时没有历史可查；文件被占用时还得另外找工具，进程树与结束操作也不够顺手。

## 2. 为什么是现在

本期 1,921 星、84 fork、37 个 open issue，37 天新仓、无历史基线；README 把 7 天历史曲线、文件占用拖拽查询和规则化优先级管理列为核心特性，并提供官网在线交互演示与 8 语言文档，说明系统工具类项目正把「可回溯」当作基础能力而非附加项。

## 3. 关键能力

- 进程页支持按应用、进程树或列表查看，可搜索、排序并结束整棵进程树
- 性能页展示每核心 CPU 利用率、频率、温度与功耗，以及内存、磁盘、网络与 GPU 曲线
- 历史回溯：在 7 天曲线上单击任意时刻，列出该时刻最忙的进程
- 文件占用：把文件或文件夹拖进窗口，列出占用它的进程并可直接结束
- 规则：右键为进程设置优先级、能效策略等；硬件传感器与快捷键扩展在路线图中
- 提供官网在线交互演示（无需安装即可体验完整界面）与从源码构建说明

## 4. 架构与实现

Rust 直接调用 Windows 原生系统接口采集进程与硬件指标，UI 由 GPUI Kit 的原生组件构建，曲线随屏幕刷新率连续绘制，避免 Electron 方案的额外开销。历史数据落本地供 7 天回溯；文件占用查询走系统句柄枚举。源码构建需要 Rust stable-x86_64-pc-windows-msvc、Node.js 26.x/24.x LTS、pnpm 12.18 与 Visual Studio Build Tools。

## 5. 上手路径

1. 先去官网在线体验界面，确认功能与预期一致，再决定是否下载安装
2. 按 README 的发布页下载对应版本，或备齐 Rust/Node/pnpm/VS Build Tools 从源码构建
3. 打开进程页切到进程树视图，试一次搜索与结束进程树
4. 在性能页等一小段时间后点 7 天历史曲线上的某个时刻，核对列出的高占用进程是否符合当时的实际情况

## 6. 风险与边界

- 仅支持 Windows 10 22H2（19045）及以上、x64 架构，且需 DirectX 11 图形设备，适用范围有限
- 37 天新仓、37 个 open issue，硬件传感器覆盖依赖官方 PawnIO 驱动，驱动类能力的稳定性与兼容性需谨慎
- 结束进程树与设置优先级属高权限操作，误操作可能影响系统稳定性
- 持续采集 7 天历史与高刷新率曲线会带来额外 CPU/存储开销，需观察常驻占用
- AGPL-3.0 许可，二次分发或集成前需评估合规义务

## 7. 谁该用 / 谁别碰

需要排查瞬时卡顿、进程占用与文件锁定的 Windows 重度用户与运维/开发人员；只用基础查看能力或为 ARM/x86 设备的用户不适用。
