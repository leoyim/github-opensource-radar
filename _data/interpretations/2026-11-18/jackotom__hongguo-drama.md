## 1. 它解决什么问题

第三方内容平台的桌面客户端常卡在两处：播放接口与签名协议一变就失效，以及发行包来源不明、升级后设置丢失；用户很难判断手里的包对应哪份源码、是否可正常播放。

## 2. 为什么是现在

本期 1,708 星、265 fork、1 个 open issue，42 天新仓、无历史基线；README 以 7.5 正式版的逐平台验收状态开篇，明确列出 HTTP 200 空响应修复、纯 JavaScript Android v5 签名移植与新播放器请求协议，并公开 SHA256 与精确源码包，发行透明度在同类项目中较为少见。

## 3. 关键能力

- 覆盖搜索、播放、下载、追剧与合并导出，支持 Apple 芯片 Mac、Intel Mac 与 Windows x64
- 7.5 修复播放接口 HTTP 200 空响应，移植纯 JavaScript 版 Android v5 签名与新播放器请求协议
- 保留下载临时文件清理的 EPERM 修复；安装版保留应用内更新入口且不强制升级
- Mac 双架构 App 与 DMG 完成 Developer ID 签名、Apple 公证 Accepted 与票据装订；提供 SHA256 与精确源码包
- 便携版把设置与下载记录放在程序目录 data 文件夹，便于迁移；README 附逐版本发布回执

## 4. 架构与实现

Electron 桌面应用，通过自实现的签名与请求协议对接上游内容源，本地负责搜索聚合、播放、下载队列与追剧状态持久化；更新由应用内下载 + 用户确认重启完成。发行侧按平台分别构建并签名公证，便携版与安装版共用主体逻辑但数据目录策略不同（便携版放程序目录 data，安装版沿用用户资料目录）。

## 5. 上手路径

1. 从 7.5 正式发行页按平台下载，先核对 SHA256SUMS 再安装
2. Mac 用户确认签名与公证状态；Windows 用户知悉 EXE 未签名、可能触发系统安全提示
3. 跑一次搜索 → 静音播放 → 下载，验证新播放器协议在当前网络下可用
4. 需要升级时先备份便携版 data 目录，再按 README 的升级路径替换

## 6. 风险与边界

- README 明确上游部分片源可能 404、只提供预览或超时，不保证内容永久可播
- Windows EXE 未签名，可能触发系统安全提示，需自行核对官方下载来源
- 依赖对上游接口的逆向适配，上游协议变更会直接导致功能失效
- 便携版与安装版不能同时运行，且设置/下载记录位置不同，迁移时易丢数据
- 第三方内容平台客户端涉及内容授权与合规，使用与分发前需自行评估；GPL-3.0 亦带来衍生分发义务
